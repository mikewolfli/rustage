# Support

## Before opening an issue

Read the [README](README.md) and [documentation index](docs/README.md).
Check whether your question concerns a design proposal or an existing
implementation. There is no installable designer release yet.
Search existing issues and pull requests before opening a duplicate.

| Request | Channel |
|---|---|
| Documentation, checker, or implementation defect | Bug report form |
| Product capability, UX improvement, or roadmap addition | Feature proposal form |
| Architecture, roadmap, design questions, or non-sensitive governance | Design and repository governance form |
| Verified host or output-target compatibility evidence | Target compatibility form |
| Vulnerability or exposed credential | [Security policy](SECURITY.md); do not publish details |
| Community behavior concern | [Code of Conduct](CODE_OF_CONDUCT.md) |

The project has no dedicated forum or instant-chat channel.
Do not assume GitHub Discussions is enabled.
Maintainers do not promise a response deadline, and public issues are not
a private support channel.

## Useful evidence

Include the repository revision, relevant document or task, minimal reproduction,
actual commands and output, and applicable OS/architecture, toolchain, profile,
target, SDK, or device details.

Distinguish unverified claims, missing environments, and actual failures.
Remove credentials, personal information, private paths, and unauthorized code
from logs before sharing them. Do not upload a complete private project for support.
