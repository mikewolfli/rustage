## 1. 问题

[`blue13`](../plan/blue13.md) 的 MS12 联合验收发现：设计器窗口有菜单、工具栏、停靠面板、
编辑组和状态栏，但没有把已有的模型接到用户入口上。因此以下旅程只有模型级证据：

- J02 多页面应用：窗口内没有页面编辑与导航入口；
- J03 键盘完整工作流：命令注册与 keymap 可用，但窗口内没有命令面板/树/属性编辑的焦点路由；
- J04 复杂布局与主题：布局与令牌模型可用，但没有画布多选与主题审阅；
- J09 调试业务事件：`--debug` 真实跑通，但窗口内没有断点/栈/变量面板。

证据见 [`log-20261020-3.md`](../log/log-20261020-3.md) §5.2–§5.3。

路线图 §5 明确 MS12 是集成门禁、不新增任务；上述能力在现有任务表里已有验收词：

| 缺口 | 现有任务 | 里程碑 | 现有验收词 | 当前证据 |
|---|---|---|---|---|

| 面板注册/焦点 | T04.02、T04.07 | MS03（blue4） | 已接入面板可关闭恢复；错误可发现，键入不中断 | 面板可显示/隐藏；无 canvas/palette/debug 面板 |
| 对象树/画布选择与联动 | T09.02、T09.03、T09.04、T09.08 | MS05（blue6） | 树/画布联动；树/画布选择一致 | 窗口入口已接通：树/画布共用选择，点击/框选/隐藏/锁定均有真实指针证据 |
| 属性编辑 | T11.01、T11.02 | MS05（blue6） | 类型/范围校验，错误不改有效模型；多选按能力交集 | T11.01 真实字段通过；T11.02 多选交集仍未接 GUI |
| 调试面板 | T19.03–T19.06 | MS11（blue12） | 有效绑定状态；执行状态栏；线程/栈/局部变量；双向源映射 | `--debug` 真实通过；窗口无调试面板 |
| 事件/数据绑定 UI | T13.03、T13.04 | MS06（blue7） | 名称存在与实际接线/触发分开验证 | 模型通过；Data/Events 面板只读 |
| 运行检查 | T14.05 | MS06（blue7） | 设计值/计算值/运行值及版本 | 模型通过；窗口无检查器 |

所以问题不是“路线图漏了任务”，而是**这些任务在 GUI 部分未完成时被所在阶段签成了
“完成（待验收）”**。按路线图 §5“交付集合要求列出的任务范围全部验收”和 §35.1 完成定义
第 1 条（界面适用环节全部接通），正确做法是把对应任务恢复为“进行中”，而不是新造一个
“写完即完成”的任务。

## 4. 门禁

MS12 只有在 J02/J03/J04/J09 的上述步骤能从**用户入口**复现后才可签收。以下情况仍判不通过：

- 用模型 CLI 输出替代窗口交互；
- 面板只显示静态示例数据，没有接到同一模型；
- 焦点、禁用原因、空/错误状态或中文/DPI 未检查；
- 为了通过门禁而把未接线的面板写成“已更新”。

## 5. 不在本项范围

- 拖拽停靠、浮动面板、macOS 原生菜单绘制（T04.06 及平台后续）；
- 完整代码编辑器（T06）；
- 目标应用外壳的菜单/对话框/状态栏生成（F26/F27，MS08）；
- 真机调试与远程部署（FUTURE）。

这些边界不影响本项先把“设计器自身的入口”接通。
