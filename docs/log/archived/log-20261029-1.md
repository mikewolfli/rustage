## 1. 上游 3.0.0 重钉与 API 差异

| 项 | 旧值 | 新值 |
|---|---|---|
| `Cargo.toml` rev | `ba1db3c274beab0a760a69eac1f9adf458c727eb`（2.8.12） | `177716410bc714cb0b1131d0c8f7065076f10583`（3.0.0） |
| `DEPENDENCY_VERSION` | `2.8.12` | `3.0.0` |
| `DEPENDENCY_REVISION` | `ba1db3c2…` | `177716410bc7…` |
| P-DEP（capability-reference） | `cee6b223…`（2.8.11） | `177716410bc7…`（3.0.0） |
| 决策 U1 的“当前修订” | `cee6b223…` | `177716410bc7…` |

**为什么固定到 `17771641` 而不是 `40d24294`。** 两者都是 3.0.0 之后的本地 HEAD 链；`40d24294`
（`temp`）与 `17771641`（`3.0.0`）的差异只在 `demo/code_editor` 与 `docs/log`，
`src/`、`Cargo.toml`、`Cargo.lock`、`crates/` 无差异。固定到标记为 `3.0.0` 的提交，
使 P-DEP 与上游版本号一一对应。

**编译差异。** 2.8.12 上宿主的两个 `impl Layout` 可编译；3.0.0 报：

```text
error[E0046]: not all trait items implemented, missing: `arrange`, `arrange_with_context`, `update_with_context`
  --> src/app/run/workbench_layout.rs:284:1
  --> src/app/run/workbench_scene.rs:379:1
```

宿主适配：

- `workbench_layout.rs`：`arrange`/`arrange_with_context` 转发到 `update`；
  `update_with_context` 转发到 `update`。工作台区域由 `Area` 表决定，菜单/状态栏没有可用的
  子 hint；忽略 hint 与 context 是显式决定，不是静默回退。
- `workbench_scene.rs`：三条入口同样转发到 `update`。画布节点位置来自设计空间与
  `CanvasTransform`，使用库的 preferred-size hint 会把显式设计位置变成布局猜测。
