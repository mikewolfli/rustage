## 1. Form/FormSet 接入宿主契约（T09.01 / T11.01 的 suite 面）

### 1.1 问题

3.1.0 的 `Form`/`FormSet` 由可选包 `rust-widgets-suites` 注册。
`WidgetFactory::shared()` 是父 crate 的不可变表，不能安装 suite，因此：

- `Catalog::from_contract(shared(), …)` 看不到 `form`/`form_set`；
- 属性面板 `resolve_contract` 对 `form.*` 报 “schema unavailable”。

### 1.2 修改

| 文件 | 修改 |
|---|---|
| `src/app/contract.rs`（上一轮已落盘） | `factory()`：`OnceLock<WidgetFactory>`，`new_with_defaults()` + `rust_widgets_suites::install`，安装失败以真实 `RegistrationError` panic |
| `src/app/canvas/widget_catalog.rs` | 新增 `Catalog::from_host_contract(profile)`；`run/design.rs` 改用 |
| `src/app/style/property_editor.rs` | `resolve_contract(factory, …)` / `resolve_host_contract(control, property)` |
| `src/app/run/workbench_property.rs` | **本轮**：Inspector 的 `resolve_contract` 改读 `crate::app::contract::factory()` |
| `src/app/data/events.rs` | **本轮**：`Registry::from_control` 改读宿主工厂，suite 控件的事件声明可解析 |
| `src/app/run/quality.rs` | **本轮**：`contract-control:` 事实改读宿主工厂 |

`WidgetFactory` 的不可变语义没有变：宿主只构建一次、只借用；没有 `static mut`，没有 unsafe。

## 4. T25.09：SBOM 由 lockfile 派生

### 4.1 已实现

新文件 `src/app/release/lockfile.rs`：

- `parse(&str) -> Result<Vec<Locked>, String>`：读 `Cargo.lock` 的 `[[package]]`
  （name/version/source/checksum；跳过 `dependencies` 数组、`[metadata]`、`[[patch.unused]]`），
  缺 name 或 version 以**行号**拒绝；
- `sbom(packages, licences) -> (Sbom, Coverage)`：组件名用惯用
  `pkg:cargo/<name>@<version>`，因此同名多版本（如 `bitflags` 1/2）不冲突；
- 缺失许可证如实记 `unrecorded`，不猜；
- `Coverage` 统计包数、有摘要数、有许可证数、无 source 数（工作区成员），
  并明确“vulnerabilities: no advisory source configured”。

CLI（`src/app/run/release.rs`）：

- 新 op `sbom-lock:<Cargo.lock>:<output>`；
- 新 op `package-license:<name>@<version>:<licence>`；
- 若已声明 `artifact:`，把发布产物作为组件写入（`source = release artifact`，摘要即产物摘要），
  并校验该摘要确实出现在 SBOM 中——这就是 artifact↔SBOM 的摘要链接。

### 4.2 真实仓库证据


## 8. T22.06：真实子进程 Handler

### 8.1 已实现

| 项 | 落点 |
|---|---|
| `ChildHandler`：`Handler` 的真实子进程实现，走 `DuplexProcess` 的一行一帧协议 | `src/app/extension/supervisor.rs` |
| 只能用 `ExecutionPermit`（`EffectClass::Command`）启动 | 同上 |
| 请求非 UTF-8 或含换行 → `HandlerFailure::Protocol`（写管道前拒绝）；管道关闭/读超时 → `Crashed` | 同上 |
| 丢弃 handler 时关闭 stdin 并回收进程组（`DuplexProcess` 现有 Drop） | `src/host/subprocess.rs` |
| CLI `supervise-child:<program>`；`supervise-status` 的 `handler starts` 含真实子进程启动次数 | `src/app/run/extension.rs` |

子进程的读超时设为 `Limits::call_timeout + 1s`，让“慢回答”先由 supervisor 报 `Timeout`，
而不是被 handler 误报为崩溃。

### 8.2 证据

```text
$ rustage --extension supervise-child:/bin/cat supervise-call:hello supervise-status supervise-stop
supervising child process /bin/cat
answer (5 byte(s)): hello
supervisor extension: running (restarts 0/3)
design: on, preview: on, extension: on
handler starts: 1
supervisor extension: stopped (restarts 0/3)
```

单元测试（真实子进程，非模型替身）：

- `a_real_child_process_answers_a_line`（`/bin/cat` 回显）；
- `a_child_that_exits_is_a_crash_not_an_empty_answer`（`/bin/sh -c 'exit 0'`）；
- `a_frame_with_a_newline_is_refused_before_it_is_written`（坏帧不污染下一帧）；
- `a_child_is_not_started_without_a_command_permit`（FileWrite permit 不能启动命令）。

`app::extension` 定向 22 passed。
