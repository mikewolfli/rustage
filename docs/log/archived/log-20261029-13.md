## 1. T24.04：生成应用的语言资源

### 1.1 已实现

新文件 `src/app/language/target.rs`，消费库 `rust_widgets::i18n`：

| 能力 | API | 说明 |
|---|---|---|
| 加载文件 | `Resources::load_file(&Path)` | 走 `I18nManager::load_translations`，**注册路径**，因此可热重载；文件名必须是 `<tag>.json`（库按文件名识别语言） |
| 加载文本 | `Resources::load_json(&str)` | 走 `inject_translations`，用于嵌入数据；不可重载 |
| 选择/回退 | `select(&mut self, tag) -> Selection` | `Loaded` / `FallsBackToEnglish{requested,fallback}` / `Unavailable`，不把回退说成已翻译 |
| 复数+上下文 | `translate(key, context, count)` | 库的 `plural.get(&count)` 与 context 规则原样使用 |
| 键审计 | `audit(language) -> Audit` | `missing`（en 有、此语言无）/ `extra`（此语言多出），排序 |
| 热重载 | `reload(language)` | 文件加载的目录真实重读；注入目录如实返回库的 “no translation file is registered” |
| 方向 | `direction(tag) -> TextDirection` | 宿主表：`ar/he/fa/ur/yi/dv/ps/sd`（含地区/脚本后缀）→ RTL；其余 LTR |
| 长文本预览 | `preview(key, ctx, count, max_chars) -> Preview` | 按 Unicode 标量换行；**不是**字体度量 |

CLI `--target-i18n`（与设计器自身的 `--ui-language` 明确分开）：

```text
$ rustage --target-i18n load:/tmp/rustage-ti18n/en.json load:/tmp/rustage-ti18n/de.json \
      language:de translate:greeting audit direction:ar-EG preview:greeting:4 reload
loaded en (3 key(s), new)
loaded de (1 key(s), new)
language de (loaded)
greeting = Hallo
audit de (2 missing, 0 extra)
missing: files
missing: save
direction ar-EG rtl
preview greeting: 5 char(s), 2 line(s), truncated false
text: Hallo
reloaded de
```

复数与 en 回退也在同一命令中验证：

```text
$ rustage --target-i18n load:…/en.json language:en count:2 translate:files context:button translate:save
files = many files
context button
save = Save
```

## 2. T25.03：更新确认、中断恢复与格式迁移

### 2.1 状态机（`src/app/release/manifest.rs`）

```text
Planned --verify--> Verified --confirm--> Confirmed --begin_install--> Installing
Installing --complete_install--> Installed --rollback--> RolledBack
Installing --interrupt--> Interrupted --resume--> Installing
Interrupted --recover--> RolledBack
```

- `install()` 现在要求 `Confirmed`（不再是 `Verified`），是 `begin_install + complete_install` 的一次调用路径；
- `begin_install()` 记录并返回 `rustage-<from>.bak`；
- `Migration::plan(from,to,steps)`：`from == to` 拒绝；**步骤为空时拒绝**（“user projects are never
  migrated silently”）；`acknowledge()` 后才允许 `confirm()`；
- `set_migration` 只在 `Planned`/`Verified` 可设，确认后不可再改。

CLI 新增 `confirm`、`begin-install`、`complete-install`、`interrupt`、`resume`、`recover`、
`migration:<from>:<to>:<step>[|<step>…]`、`ack-migration`。

### 2.2 真实 CLI 证据


## 3. T22.09：扩展来源、摘要、离线安装、固定与回退

### 3.1 已实现（`src/app/extension/package.rs`、`src/app/run/extension.rs`）

| 能力 | 说明 |
|---|---|
| 来源 | `Package.source`：命令行声明为 `local`，目录安装为真实路径；`Registry::source(id)` |
| 离线目录安装 | `Package::from_directory`：`manifest.json` + `files/` 递归读取；`/` 分隔相对名；拒绝符号链接（不能越出包目录） |
| 摘要先验 | `Registry::install` 在任何状态改变前校验 manifest 摘要；失败不改动已装副本 |
| 版本固定 | `pin`/`unpin`：固定后 `install` 与 `update-preflight` 都拒绝更新，直到解固定 |
| 更新回退 | 替换时保留旧包，`rollback(id)` 恢复并可再次回退（交换） |
| 移除清理 | `remove` 同时清 pin 与保留的旧版本 |

CLI：`install-dir:<path>`、`pin:<id>`、`unpin:<id>`、`rollback:<id>`、`lookup:<id>`；`status`
每行显示 `版本 许可 [状态,pinned] 摘要 from 来源`。
