## 1. T14.08：真实进程内存与线程

### 1.1 已实现

`src/app/preview/load.rs` 的运行器原本已经真实 mount/update/stop 100 轮，并把
“resident memory / thread count” 明确列为未测。本轮补上进程读数：

| 项 | 实现 |
|---|---|
| `Sample { rss_bytes, threads }` | 一次进程读数 |
| `sample_process()` | macOS：`ps -o rss= -p <pid>` + `ps -M -p <pid>`（表头后每行一个线程）；Linux：`/proc/self/status` 的 `VmRSS`/`Threads`；其他平台返回明确错误 |
| 采样点 | 第 1 轮结束后（基线，含一次性字体/运行时页）与最后一轮结束后 |
| 判定 | 线程增长必须 ≤ 0；RSS 增长 ≤ `RSS_GROWTH_CEILING_BYTES`（64 MiB，粗读数只抓大泄漏） |
| 报告 | `resources: rss A -> B bytes (growth N); threads X -> Y (growth M)`；未采样时打印 `resources: not measured` 并列入 `unmeasured` |
| 失败原因 | `verdict()` 增加进程增长原因 |
| 工厂 | `drive` 改用宿主工厂（库默认 + suite），与目录/Inspector 一致 |

CLI：`--quality load[:<cycles>]`，默认 100 轮、5 s 延迟预算：

```text
$ rustage --quality load:100
budget: 5000 ms; viewports: 1; cycles: 100 (measured 100, declared 0); invalid input: 0 (kept); residual controls: 0
steady: yes
  desktop: measured; live controls 2..2 peak 2; generation 2..2; instances 1..1; processes 0..0
latency: worst 38 ms (0 cycle(s) over budget)
resources: rss 22429696 -> 22986752 bytes (growth 557056); threads 1 -> 1 (growth 0)
unmeasured: signal subscriptions: this session holds none; the dispatcher's handles identify records, not connected slots
load passed: 100 real cycle(s)
```

### 1.2 为什么增长断言在独立进程里

第一次把 `thread_growth == 0` 放进 100 轮单元测试时，全量套件下它失败了：unit test 二进制与其他
测试共用进程，别的测试在 100 轮期间启动的线程被计入“增长”。这不是泄漏，是测量边界错误。

处理方式：

- 单元测试只断言“取了读数、且 `unmeasured` 不再声称内存未测”；
- 新增 `tests/preview_load.rs`，启动真实二进制跑 `--quality load:100`，在同一进程内解析
  `resources` 行并断言 `threads ... (growth 0)` 与 RSS 增长 ≤ 64 MiB。

证据：

```text
$ cargo test --test preview_load
running 1 test
test a_hundred_cycles_leave_the_process_memory_and_threads_steady ... ok
```

### 1.3 仍未测量（明确）

- 读数属于**整个进程**，不是单个预览子系统；它证明“进程没有持续增长”，不证明某一次分配去向。
- 本机没有挂载窗口/真实预览实例（§3 系统缺口 3 未关闭），因此这不是窗口级或设备级证据。
- 只实现 macOS/Linux 读数；其他平台如实报告未测。

## 2. T22.08：扩展声明的文件/网络权限过 `PermissionService`

### 2.1 已实现

`src/app/run/extension.rs`：

| 项 | 实现 |
|---|---|
| 权限映射 | `fs` → `EffectClass::FileWrite`，`network` → `EffectClass::Network`；其他名字拒绝 |
| 安装前检查 | `install`、`install-dir`、`update-preflight` 在建包/落库前调用 `check_permissions` |
| 判定服务 | 整个 `--extension` 调用共用一个 `PermissionService`，判定有记录 |
| 诊断 | 被拒时按清单 id + 权限名 + 服务自身原因（含下一步）输出，exit 4 |
| 查询 | `authorize:<fs|network>` 打印判定与记录条目号 |

### 2.2 真实 CLI 证据

```text
$ rustage --extension authorize:fs
permission fs: allowed (file-write permitted in session for Human via human-only (record entry #1))

$ rustage --extension authorize:network
WARN host::permission: refused: request-network-service is not allowed in session
     (service-not-configured) and declare this service in the project's network policy, ...
rustage: permission network is not authorized: refused: request-network-service is not allowed in
session (service-not-configured) and declare this service in the project's network policy, ...
（exit 4）

$ rustage --extension install-dir:/tmp/rustage-pkg-fs status
installed acme.chart 1.2.0 (23d6…) from /tmp/rustage-pkg-fs
permission fs: allowed (file-write permitted in session for Human via human-only (record entry #1))

$ rustage --extension install-dir:/tmp/rustage-pkg-1.2.0 status    # 清单声明 network
rustage: acme.chart declares network, which is not authorized: refused: request-network-service is
not allowed in session (service-not-configured) ...                    （exit 4，未安装）
```

单元测试（`app::run::extension` 5 passed）：

- `fs` 允许且返回记录证据；
- `network` 在无策略时被拒，消息含 `declares network` 与 `not authorized`；
- 宿主没有决定的权限名被拒。

### 2.3 仍未完成（不伪造）

- **运行期逐次调用**的文件/网络执行缝尚未存在：当前没有扩展 I/O 执行器，因此权限在
  **安装/升级**时被检查，而不是每次调用时。真正的逐次门属于将来接入执行器时的工作。
- `network` 要成功必须存在项目网络策略（T01.09/T02.01）；当前命令不伪造策略，所以一律可见拒绝。
