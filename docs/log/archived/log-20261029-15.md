## 1. T21.06：视觉证据接真实基线

### 1.1 问题

质量中心此前只有 `VisualCondition { platform, scale, font_digest }` 与 `compare`：它只回答
“两次捕获是否在相同环境”，不比较像素，也没有“未采集”这一状态——没采集与通过看起来一样。

### 1.2 已实现

新文件 `src/app/quality/visual.rs`：

| 项 | 说明 |
|---|---|
| `VisualCondition` | 增加 `resources`（资源版本）；`visual:<platform>:<scale>:<font>[:<resources>]` 可省略（默认 0） |
| `VisualRun` | 保存基线 `Baseline`、候选 `Shot`、容差与最后一次 `Report` |
| `VisualEvidence` | `NotCollected` / `Captured` / `MissingBaseline` / `Compared(Report)`；**只有 `Compared` 能 pass** |
| 比较 | 直接调用 `preview::visual_baseline::compare`：先比条件（平台/DPI/资源/字体），再比尺寸，最后逐像素与容差 |
| 证据 | `Evidence.visual` 改为 `VisualEvidence`；JSON 带 `state`、`verdict`、两边条件，差异时带像素统计 |

CLI（`--quality`）：

- `visual:<platform>:<scale>:<font>[:<resources>]`（设当前捕获条件）
- `visual-baseline:<name>:<w>:<h>:<digits>`（登记基线）
- `visual-candidate:<name>:<w>:<h>:<digits>`（登记候选）
- `visual-tolerance:<percent>`（像素比例容差，通道步长 0）
- `visual-check`（真实比较；**没有比较结果就不是通过**）
- `evidence:<file>` 写入带状态的视觉证据

## 2. T21.11：JUnit 导入

### 2.1 已实现

新文件 `src/app/quality/junit.rs`：`JUnitImport::from_xml` 把质量中心自己写出的 JUnit XML
读回。

| 项 | 说明 |
|---|---|
| 状态映射 | `<failure>`/`<error>` → Failed；`<skipped>` → Skipped；无子元素 → Passed；JUnit 无 “not run”，所以未运行测试**缺席**而不是通过 |
| 校验 | 无 name、属性未加引号、标签未闭合、关闭标签不匹配、`time` 非数字、未知实体、第二个根元素、根不是 testsuite(s) —— 全部带**行号**拒绝 |
| 环境 | `<properties>` 的 `revision`/`target` 与当前值不一致时拒绝导入；未声明时输出 `not declared`，不冒充匹配 |
| 实体 | 五个预定义实体解码（`&amp;` 等），其他实体拒绝 |

CLI：`junit:<file>`（导出，原有）与 `junit-import:<file>`（新增）。

### 2.2 真实 CLI 证据

```text
$ rustage --quality test:renders:passed:0.2 test:breaks:failed junit:/tmp/junit-export.xml
wrote JUnit XML to /tmp/junit-export.xml

$ rustage --quality revision:3 target:desktop junit-import:/tmp/junit-export.xml show
imported 2 test result(s) from /tmp/junit-export.xml
(revision not declared, target not declared)

$ rustage --quality revision:3 target:desktop junit-import:/tmp/junit-env.xml   # 文件声明 revision 7/tablet
rustage: the file is for revision 7, not 3                     （exit 4）

$ rustage --quality revision:7 target:tablet junit-import:/tmp/junit-env.xml show
imported 1 test result(s) from /tmp/junit-env.xml (revision 7, target tablet)

$ rustage --quality junit-import:/tmp/junit-bad.xml
rustage: line 2: <testcase> attribute name is not quoted      （exit 4）
```

`app::quality::junit` 5 passed，含导出→导入往返、`<error>` 与实体、属性环境匹配/不匹配、
无环境如实说明、7 类畸形文档带行号拒绝。

### 2.3 仍未完成

- 只解析导出器写出的形状（元素/属性/实体/嵌套）；不支持 CDATA、DTD、命名空间前缀。
- 同名测试后者覆盖前者（`Tests` 以名字为键）；JUnit 允许同名，导入不保留重复。
- 不读取 `<system-out>`/`<failure>` 文本内容，只记录状态。
