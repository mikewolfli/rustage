## 1. 为什么需要它

第十三轮的更新状态机活在**一个进程的内存里**。它覆盖了“用户点了中断”，却覆盖不了它存在的
理由：机器在“已备份、还没写完”时断电或被杀，重启后的进程对这次半装的更新一无所知，下一次
就会在半装的文件上规划一次全新更新。T25.03 要求“中断恢复”，而进程内状态机只能恢复
“进程内中断”。

`src/app/release/update_journal.rs` 就是这个记忆。

## 2. 记录与文件形态

| 项 | 说明 |
|---|---|
| `Record` | from/to 版本、产物名/摘要/字节数/是否签名、最后状态、备份名（有才写） |
| 文件头 | `rustage-update 1`；之后每行 `<name>\t<value>` |
| 严格读取 | 头不对、行没有制表符、字段缺失、`size` 非数字、`signed` 不是 yes/no、状态名不认识 → 带行号拒绝；**不猜**半装状态 |
| 无文件 | `read()` 返回 `Ok(None)`，不是错误：从未更新过的机器没有这个文件 |
| 每次迁移都写 | 只要声明了 `journal:<file>`，`--release` 每次状态变化后写一次（相同记录不重复写） |
| `recover_interrupted` | 只在最后状态是 `installing` 时改成 `interrupted` 并落盘，返回该记录；否则 `None` 且**不动文件**，已完成安装的记录因此保留 |
| 不清空文件系统 | 本构建的安装就是状态机本身；日志如实说“状态是什么、备份叫什么”，不假装恢复了文件 |
| `clear` | 删除文件；本来就不存在也算成功 |

`UpdateState` 新增 `name()` / `parse()`（`planned`/`verified`/`confirmed`/`installing`/
`interrupted`/`installed`/`rolled-back`）作为唯一的写入/读取映射；`Debug` 输出仍是既有
`Update::render` 的用法，未改动。

## 3. 命令行

| 操作 | 行为 |
|---|---|
| `journal:<file>` | 之后每次状态变化都把记录写入该文件（当前已有更新时立即写第一条） |
| `journal-recover:<file>` | 把一个 `installing` 记录标成 `interrupted` 并打印它；没有中断记录时打印 `no interrupted install` |
| `journal-clear:<file>` | 删除日志 |

## 4. 真实证据（跨进程）

进程一：规划→校验→确认→开始安装后**退出**，日志停在 `installing`：

```text
$ rustage --release artifact:rustage-update:1d2fb442…:22:unsigned \
      update:1.0.0:1.1.0 verify-update:/tmp/rustage-t25-03/artifact.bin \
      confirm journal:/tmp/rustage-t25-03/update.journal begin-install
artifact rustage-update (Unsigned)
1.0.0 -> 1.1.0 (rustage-update, unsigned, Planned)
update 1.1.0 verified
1.0.0 -> 1.1.0 (rustage-update, unsigned, Confirmed)
journal /tmp/rustage-t25-03/update.journal
backup rustage-1.0.0.bak
1.0.0 -> 1.1.0 (rustage-update, unsigned, Installing)

$ cat /tmp/rustage-t25-03/update.journal
rustage-update 1
from	1.0.0
to	1.1.0
artifact	rustage-update
digest	1d2fb4429ec3072ed09844b433cfdd6fd7a2d21c830a164dbf5fbca3216342ba
size	22
signed	no
state	installing
backup	rustage-1.0.0.bak
```

进程二：另一个进程读它，把它标成中断并报出备份：

```text
$ rustage --release journal-recover:/tmp/rustage-t25-03/update.journal
update: 1.0.0 -> 1.1.0
artifact: rustage-update 22 byte(s), unsigned
digest: 1d2fb4429ec3072ed09844b433cfdd6fd7a2d21c830a164dbf5fbca3216342ba
state: interrupted
backup: rustage-1.0.0.bak

$ rustage --release journal-recover:/tmp/rustage-t25-03/update.journal
no interrupted install

$ rustage --release journal-clear:/tmp/rustage-t25-03/update.journal
journal /tmp/rustage-t25-03/update.journal cleared
$ rustage --release journal-recover:/tmp/rustage-t25-03/update.journal
no interrupted install
```

第二次 `journal-recover` 返回“没有中断”，证明第一次的 `interrupted` 已经落盘——这正是
“另一个进程在关机后继续”的最小证据。

测试：`app::release` 38 passed（`update_journal` 5 项为新增：往返、缺文件、中断恢复并持久化、
已完成安装不被改、畸形文件带行号拒绝）。

## 5. 仍未完成（不伪造）

- **更新发现**（T25.03 的“更新发现”）：需要一个带签名的更新源/通道元数据，它依赖 T25.02 的
  打包与签名身份决策，本机没有可验证的来源，因此不做、不假装能查。
- **真实文件替换与迁移执行**：日志记录的是状态与备份名；本构建的“安装”仍是状态机，没有
  在磁盘上替换 `rustage` 可执行文件，也没有执行迁移步骤的写盘实现。
- 日志不加密也不签名：它是本机状态文件，不是可传递的凭据。
