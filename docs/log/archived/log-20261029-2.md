## 0. 结论摘要

本轮先把四个可独立闭环的 P0 模型/证据缺口补齐，并修掉两处会在失败时误导人的行为：

1. **T21.01 完成**：问题中心按
   `(source, target, revision, node, location, message)` 去重；`advance(revision)` 后旧修订
   不再作为当前问题出现。
2. **T18.02 完成**：能力快照从库的 `DesignerManifest` 读取
   `protocol/library/profile` 与 `triple`，不再由调用方另填一套字符串。
3. **T23.02 完成（模型层）**：`Context::payload` 不再公开；唯一发送口
   `sendable_payload()` 在未授权时返回 `SendError::Unauthorized`。
4. **T23.03 完成（模型层）**：`ChangeSet` 拒绝 `src/generated/**` 与 `target/**`；
   `validate_against(current_revision)`/`Candidate::new_at` 拒绝过期基线。
5. **T25.03 部分修复**：`Update::plan` 现在比较数字版本，拒绝降级（`1.10.0 -> 1.9.0`），
   不再只判 `from == to`。确认/中断恢复/格式迁移仍未实现，因此 T25.03 不标完成。
6. **T16.10 部分修复**：`Job` 持有 `Reproducibility`，`cargo check/build` 的 argv 真实带
   `--locked/--offline/--frozen`；`--compile locked:yes offline:yes execute` 已真实调用 cargo。
   由于 `--compile` 默认给宿主编译加 `--features desktop`，它不能用于宿主编译本身；
   宿主用 `cargo check --frozen --bin rustage` 取得通过证据。目标工程的离线构建仍未取得证据。
7. **失败可诊断**：`Outcome::render` 不再只写 `stderr: N bytes`，而是输出限长摘录；
   这次真实离线命令因此显示
   `error: the package 'rustage' does not contain this feature: desktop`。
