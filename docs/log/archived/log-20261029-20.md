## 1. 为什么“警告后照样删”不算完成

T22.05 的验收是两句：**移除先显示工程依赖**、**不留下悬空入口**。第二句决定了第一句不能只是
提示：一个“还会继续删除”的警告，删完就正好留下悬空入口。所以本轮的移除是**拒绝**，不是确认。

依赖的来源也必须诚实。工程文件里目前只有页面/资源/目标，没有记录扩展条目；本构建也没有
T22.02 的控件注册表把“哪个控件由哪个扩展注册”落盘。因此：

- 扩展在清单里**声明自己提供什么**（`provides`：控件/命令名）；
- 打开工程的调用方**报告工程用到什么**（`usage`）；
- 依赖 = 两者交集。模块不读文档、不假设“装了就算在用”。

`provides` 是清单的可选成员：没有它的旧清单照样解析、照样安装，只是没有可检查的工程入口。
这是 T22.02 清单侧最小的声明，不假装已经实现了运行时控件注册。

## 2. 面板与依赖（`src/app/extension/manager.rs`，新）

| 项 | 说明 |
|---|---|
| `Usage` | 工程自己报告的名字集合；重复声明是同一个使用 |
| `Dependency` | 扩展 id、版本、以及**具体**哪几个工程用名由它提供 |
| `Panel::render` | 每装一个扩展一行：`id version licence [enabled,pinned] provides N (K project use(s)) from <source>` |
| `Panel::dependents` | 工程依赖的全部扩展，按 id 排序 |
| `Panel::removal` | 返回 `Removal`；未知 id 是错误，不是“干净” |
| `Removal::allowed` | 只有依赖为空才为真；`dangling()` 数出会被留下的入口 |
| `Removal::render` | 先逐条 `depends:`，最后一行给出结论（`no project dependency` 或 `refused, … dangling entry point(s)`） |

`Registry` 仅新增 `manifest(&id)` 只读取器；`remove` 本身不变，门禁在调用方之前的
`Panel::removal`，因此模型层仍然“移除就是移除”，管理层的规则只有一处。

## 3. 命令行

| 操作 | 行为 |
|---|---|
| `provides:<name>[,<name>...]` | 声明本扩展提供的条目（也可由清单的 `provides` 数组给出） |
| `usage:<name>[,<name>...]` | 打开工程报告自己用到的名字 |
| `panel` | 面板：每扩展一行 + 工程用量 + 逐条依赖 |
| `remove-preflight:<id>` | 只显示，不改状态；有依赖时以拒绝退出 |
| `remove:<id>` | 先算依赖；有依赖则打印依赖并以拒绝退出，否则删除 |

## 4. 真实证据

```text
# 安装一个提供两个条目、工程只用其中一个的扩展
$ rustage --extension id:acme.chart version:1.2.0 host-min:0.1.0 host-max:0.2.0 \
      license:MIT capability:widget provides:acme.chart,acme.spark \
      file:main.rs:'fn main() {}' install usage:acme.chart,button panel
installed acme.chart 1.2.0 (23d67b5f…)
project uses acme.chart, button
acme.chart 1.2.0 MIT [enabled] provides 2 (1 project use(s)) from local
project uses 2 name(s): acme.chart, button
dependency: acme.chart 1.2.0 provides 1 project use(s): acme.chart

# 移除预检：先显示依赖，再拒绝
$ rustage --extension … install usage:acme.chart remove-preflight:acme.chart
depends: acme.chart 1.2.0 provides 1 project use(s): acme.chart
remove acme.chart 1.2.0: refused, the project would leave 1 dangling entry point(s)
rustage: acme.chart would leave 1 dangling entry point(s)
（exit 4）

# 真正移除同样被拒绝——不是“确认后继续”
$ rustage --extension … install usage:acme.chart remove:acme.chart
depends: acme.chart 1.2.0 provides 1 project use(s): acme.chart
remove acme.chart 1.2.0: refused, the project would leave 1 dangling entry point(s)
rustage: refusing to remove acme.chart: the project still uses 1 entry point(s) it provides
（exit 4）

# 工程不再使用它时，移除成功
$ rustage --extension … install usage:button remove:acme.chart
removed acme.chart 1.2.0
（exit 0）
```

测试：`app::extension` 43 passed（`manager` 5 项为新增：依赖只归因到真正提供的名字、
有依赖时拒绝并计入悬空数、无依赖时放行、未知 id 拒绝、面板行包含状态/固定/使用计数）。

## 5. 仍未完成（不伪造）

- **面板不是窗口**：`panel` 是命令行渲染；窗口里的管理页还没有接线（与其它 CLI 面一致）。
- **工程使用清单由调用方提供**：工程文档目前不记录扩展条目，`usage` 是外部报告的输入，
  不是从 `.json` 读出的。等 T22.02 的控件注册落盘后，这个输入才有文档来源。
- **依赖只到“名字”粒度**：不解析页面里每个节点用了哪个扩展控件，也不统计使用次数。
- `provides` 的重复项不去重（声明两次就是两条），也不校验名字格式。
