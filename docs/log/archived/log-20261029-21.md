## 1. 验收线

T21.05 的验收是 **“IPC 与静态调用共用核心测试向量”**。共用不是“两套向量看起来一样”，而是
**只有一套向量，两个调用路径都跑它**。所以本轮不做“再生成一份 IPC 用例”，而是：

- 向导声明状态/事件/迁移/页面导航；
- 向量由声明**推导**（不是手写）；
- 同一组向量交给 `logic::regression::run`，它先直接驱动 `Core`，再把每个事件装帧过类型化通道后
  再驱动一次，报告两次状态序列是否逐项相同。

## 2. 向导（`src/app/quality/wizard.rs`，新）

| 项 | 说明 |
|---|---|
| 声明即校验 | 未声明的源/目标状态、未给载荷的事件、重复的 `状态/事件` 都在**声明那一刻**被拒 |
| 载荷必填 | 事件的 `flag:`/`number:`/`text:` 载荷是向量可复现的前提，缺了就不许声明迁移 |
| 生成 | 从初始状态广度优先走“恒真”迁移，每个可达状态一条**最短路径**向量 |
| 不可达 | 声明了但没有事件走到的状态逐条报告，不静默丢掉 |
| 守卫 | 读运行时字段的迁移不生成向量，按 `状态/事件` 列出：猜一个字段值就不是数据向量了 |
| 导航 | 声明页与边；`run` 用真实 `Window::open → ready → navigate` 回放，并核对窗口停在该页 |
| 产物 | `save` 写声明本身，`load` 严格读回（行号 + 列名），因此向量**可复现**而不是粘贴 |

行格式（制表符分隔，与更新日志同一约定）：

```text
rustage-vectors 1
name	checkout
initial	idle
state	idle
state	ready
event	open	flag:true
transition	idle	open	ready
page	home
page	details
entry	home
edge	home	details
seam	tax	number:7
```

## 3. 命令行（`--quality` 家族）

| 操作 | 行为 |
|---|---|
| `wizard:<name>` | 开一份计划 |
| `w-state:<name>` / `w-initial:<state>` | 声明状态；第一条自动成为初始，可覆盖 |
| `w-event:<name>:<kind>:<value>` | 声明事件及载荷（`flag:yes`、`number:1`、`text:hi`） |
| `w-transition:<from>:<event>:<to>` | 恒真迁移 |
| `w-transition-if:…:<field>:<kind>:<value>` | 带字段守卫的迁移（不进入生成） |
| `w-page` / `w-entry` / `w-edge:<from>:<to>` | 页面、入口、导航边 |
| `w-seam:<function>:<kind>:<value>` | 核心向外要的答案 |
| `wizard-vectors` | 生成并列出向量（不运行） |
| `wizard-run` | 生成 + 两路运行 + 导航回放；任一向量分叉或导航失败则退出非零 |
| `wizard-save:<file>` / `wizard-load:<file>` | 写/读向量产物 |

## 4. 真实证据

```text
$ rustage --quality wizard:checkout w-state:idle w-state:ready w-state:paid \
      w-event:open:flag:yes w-event:pay:number:1 \
      w-transition:idle:open:ready w-transition:ready:pay:paid \
      w-page:home w-page:details w-entry:home w-edge:home:details \
      wizard-vectors wizard-run
...
vector idle->ready: open (true)
vector idle->paid: open (true), pay (1)
navigation home->details: home -> details
wizard checkout: 2 event vector(s), 1 navigation vector(s) from idle
vector idle->ready: 1 step(s), identical
vector idle->paid: 2 step(s), identical
navigation home->details: replayed
wizard checkout: 2 event vector(s), 1 navigation vector(s); identical over both seams
（exit 0）

# 产物写盘 → 另一个进程读回 → 向量完全相同并再次通过
$ rustage --quality wizard:checkout … wizard-save:/tmp/rustage-t21-05.txt

$ rustage --quality wizard-load:/tmp/rustage-t21-05.txt wizard-vectors wizard-run
loaded wizard checkout

navigation home->details: home -> details
vector idle->ready: 1 step(s), identical
navigation home->details: replayed
wizard checkout: 1 event vector(s), 1 navigation vector(s); identical over both seams
（exit 0）

# 声明指向不存在的状态：在声明时就被拒
$ rustage --quality wizard:x w-state:idle w-event:go:flag:yes w-transition:idle:go:nowhere
rustage: no state "nowhere" is declared
（exit 4）
```

测试：`app::quality::wizard` 10 passed（声明校验、最短路径生成、不可达、守卫、两路一致、
导航回放、边/入口校验、产物往返、畸形产物行号、无初始状态）。

## 5. 仍未完成（不伪造）

- **向导不是窗口**：`--quality` 的向导是命令行面；窗口里的分步向导页未接线。
- **生成的是模型向量**：它证明静态调用与 IPC 调用在 `logic::core` 上一致，**不是** UI 控件级
  交互测试，也没有生成到工程里的 `tests/` 源文件（产物是本构建的向量文件）。
- **动作（set/emit/call）不参与生成**：向导只声明迁移的下一个状态；带动作的迁移要等有 UI 侧的
  动作声明来源。
- 守卫迁移只报告不生成；没有“合成一个满足守卫的状态”的能力，也不打算假装有。
