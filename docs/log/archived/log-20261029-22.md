## 1. 验收线的两句话

T22.03 要求 **“能力不支持有禁用解释，失效不崩宿主”**。这两句都不是“加一个 if 返回 None”：

- **禁用解释**：不兼容的适配器**仍留在列表里**，状态是 `disabled` 并带原因（宿主版本区间，或
  宿主不提供的能力名）。它要是悄悄消失，那就成了谁也读不到的解释。
- **失效不崩宿主**：一个适配器失败只在**它自己**上记原因（`failed`），其它适配器状态不变，
  注册表继续回答。

## 2. 模型（`src/app/extension/adapters.rs`，新）

| 项 | 说明 |
|---|---|
| `Kind` | `language`/`debug`/`build`/`deploy`，封闭集合，`parse`/`name` 往返 |
| `Adapter` | id、种类、版本、宿主区间、需要的宿主能力 |
| `incompatibility(&Host)` | 区间反向、宿主版本不在区间、缺能力——各自给出一句含两边的原因 |
| `Status` | `Enabled` / `Disabled{reason}` / `Failed{reason}`；`enabled()` 只认 `Enabled` |
| `Adapters::register` | 重复 id 拒绝；不兼容不拒绝，记 `Disabled` |
| `Adapters::probe(&Host)` | 重新比对全部条目，返回变化行；`Failed` 保持失败（没有证据说它恢复了，清掉原因就是掩盖） |
| `Adapters::fail` / `ok` | 只改这一个 id；`ok` 重新按当前宿主判定 |
| `Adapters::missing_kinds` | 四类里没有可用适配器的种类，供面板说明“这一块没有工具” |

没有任何进程、协议或网络：宿主知道的只有调用方给它的东西。真正的传输仍由
`extension::supervisor` 负责，这一层只是清单与解释。

## 3. 命令行（`--extension` 家族）

| 操作 | 行为 |
|---|---|
| `adapter:<id>:<kind>:<version>:<host-min>:<host-max>` | 声明一个待注册适配器 |
| `adapter-needs:<capability>` | 给待注册适配器加一条宿主能力需求 |
| `adapter-register` | 按当前宿主注册，打印状态（含禁用原因） |
| `adapter-probe` | 按当前宿主重判，打印变化；无变化说 `no adapter changed` |
| `adapter-fail:<id>:<reason>` / `adapter-ok:<id>` | 记失败 / 记恢复 |
| `adapters` | 列表 + “哪些种类没有可用适配器” |

## 4. 真实证据

```text
# 需求得到满足 → 启用
$ rustage --extension adapter:acme.rust:language:1.0.0:0.1.0:0.2.0 \
      adapter-needs:widget adapter-register adapters
adapter acme.rust language 1.0.0 host 0.1.0..=0.2.0
adapter acme.rust needs widget
adapter acme.rust [enabled]
acme.rust language 1.0.0 [enabled] host 0.1.0..=0.2.0 needs widget
adapters: 1 registered, no usable adapter for debug, build, deploy

# 宿主不提供 lsp → 保留并解释
$ rustage --extension adapter:acme.debug:debug:2.0.0:0.1.0:0.2.0 \
      adapter-needs:lsp adapter-register adapters
adapter acme.debug [disabled (the host does not provide "lsp")]
acme.debug debug 2.0.0 [disabled (the host does not provide "lsp")] host 0.1.0..=0.2.0 needs lsp
adapters: 1 registered, no usable adapter for language, debug, build, deploy

# 一个失败不波及另一个
$ rustage --extension adapter:acme.rust:language:1.0.0:0.1.0:0.2.0 adapter-register \
      adapter:acme.debug:debug:2.0.0:0.1.0:0.2.0 adapter-register \
      'adapter-fail:acme.debug:the tool exited' adapters
adapter acme.debug [failed (the tool exited)]
acme.debug debug 2.0.0 [failed (the tool exited)] host 0.1.0..=0.2.0
acme.rust language 1.0.0 [enabled] host 0.1.0..=0.2.0
adapters: 2 registered, no usable adapter for debug, build, deploy
（exit 0：宿主仍然正常回答）

# 恢复由一次回答决定，不是探测
$ rustage --extension adapter:acme.rust:language:1.0.0:0.1.0:0.2.0 adapter-register \
      'adapter-fail:acme.rust:timeout' adapter-ok:acme.rust adapters
adapter acme.rust [failed (timeout)]
adapter acme.rust [enabled]
acme.rust language 1.0.0 [enabled] host 0.1.0..=0.2.0

# 种类是封闭集合
$ rustage --extension adapter:acme.lint:linter:1.0.0:0.1.0:0.2.0 adapters
rustage: "linter" is not language, debug, build or deploy
（exit 4）
```

测试：`app::extension::adapters` 9 passed（种类封闭集、兼容启用、不兼容保留并解释、缺能力点名、
重复 id 拒绝、探测双向翻转、失败只降级自身且不被探测清除、未知 id 拒绝、列表含状态/区间/需求）。

## 5. 仍未完成（不伪造）

- **没有真实协议握手**：`incompatibility` 比较的是宿主契约（版本区间与能力集合），不启动工具、
  不询问工具自己的版本。T22.03 的“兼容探测”在本构建里是契约探测。
- **面板与窗口**：`adapters` 是命令行列表；窗口里的适配器页未接线。
- **能力集合是宿主写死的**（`widget`/`template`），所以 `lsp`/`dap` 这类需求一定显示为不支持——
  这是事实，不是占位。等宿主真的提供这些能力时，同一份声明会自动变成启用。
- 适配器没有持久化：每次调用从空表开始。
