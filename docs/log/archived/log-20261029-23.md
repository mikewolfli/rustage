## 1. 三件事，一条底线

T20.04 是“**`log`/`show`/恢复旧版预览**”。前两件是读，第三件词里就写着“预览”。

底线是：**恢复预览不写任何文件**。一个“预览”顺手把工作副本改掉，就既不是预览，也毁掉了用户
唯一能对照的东西。所以 `restore_preview` 只读该修订的内容、与工作副本比对、报告差在哪，
然后明写 `preview only: nothing was written`。

## 2. 模型（`src/app/vcs/repository.rs`）

| 项 | 说明 |
|---|---|
| `Commit` | hash、作者、邮箱、作者时间（epoch 秒）、主题；`short()` 取前 7 位 |
| `Commit::stamp()` | `YYYY-MM-DD HH:MM:SS UTC`，由 epoch **算**出（前推格里高利历换算），不读本机时钟/区域设置 |
| `Repository::log(Some(n))` | 真实 `git log --format=%H%x1f%an%x1f%ae%x1f%at%x1f%s --max-count=n`；字段数不是 5 就以原始行拒绝 |
| `Repository::commit_show(rev)` | `git show --no-color <rev>`：这次提交的 diff |
| `Repository::commit_show(rev, path)` | `git show <rev>:<path>`：该修订下该文件的**原始字节** |
| `RestorePreview` | 修订、路径、字节数、是否与工作副本不同、工作副本是否根本没有该文件 |
| `Repository::restore_preview(rev, path)` | 该修订没有这个路径 → 直接报 git 的拒绝（`path 'x' does not exist in 'HEAD'`），不返回“空内容预览” |

时间格式化有意保持**与语言无关**：这一行是提交事实，按语言渲染属于界面（T24.03）。不过它现在
是一个**真实日期渲染面**了，下一轮可以在这里做本地化，而不是凭空造一个面。

## 3. 命令行（`--vcs` 家族）

| 操作 | 行为 |
|---|---|
| `log[:<n>]` | 历史，最新在前，默认 20 条；空仓库说 `no commits yet` |
| `commit-show:<revision>[:<path>]` | 无路径＝该提交的 diff；有路径＝该修订下文件内容 |
| `restore-preview:<revision>:<path>` | 只预览，三行：内容大小、与工作副本的关系、未写盘 |

## 5. 仍未完成（不伪造）

- **没有真正执行恢复**：T20.04 只要求预览；写回工作副本是一个需要单独确认的操作，本轮不做。
- **没有分页/图形化历史**：`log` 一次取前 n 条，没有游标、没有父提交图、没有分支图。
- **时间按 UTC**，不按作者时区（`git log` 的 `%at` 就是 UTC 秒）。本地化与本地时区属于 T24.03。
- **`show` 仍是仓库摘要**：提交查看叫 `commit-show`，避免改变既有 `show` 的含义。
