## 1. 验收线拆成三句

T20.03 的验收是 **“脏缓冲提示，不提交未授权变化/机密”**：

1. **脏缓冲提示**：暂存的内容与屏幕上还没保存的编辑可能不同，必须说出来。
2. **不提交未授权变化**：只提交 index 里的内容，其余逐项列出“被留在外面”。
3. **不提交机密**：扫描**将要提交的**（index）内容；有发现就**拒绝**，不是“打印警告照常提交”。

第 3 句的措辞很重要：一个先打印 `warning: secret found` 再继续提交的实现，既满足不了验收，也让
扫描形同虚设。

## 2. 机密扫描（`src/app/vcs/secrets.rs`，新）

| 规则 | 形状 |
|---|---|
| `private-key` | `-----BEGIN … PRIVATE KEY-----` |
| `aws-access-key` | `AKIA` + 16 位大写/数字 |
| `github-token` | `ghp_…` / `github_pat_…`（≥20） |
| `api-key` | `sk-…`（≥20） |
| `slack-token` | `xoxb-/xoxp-/xoxa-/xoxr-/xoxs-` |
| `secret-assignment` | 字段名（`password|passwd|secret|token|api_key|apikey|access_key|auth`）后接 `=`/`:` 与真实值 |

三条克制的规则，都是为了不误报：

- **占位符不算机密**：`$VAR`、`${VAR}`、`<your-token>`、`{{ token }}`、`changeme`、`example…`、
  `REDACTED`、单一重复字符都不报。总在文档上误报的扫描器会被关掉，关掉之后什么也保护不了。
- **调用不是凭证**：`token = read_token()?` 不报（值里有 `(` 或 `[`）。
- **字段名必须是字段**：`mytoken = …`、`subtokens = …` 不算 `token` 字段。
- 每行最多一条发现；凭据形状先于“赋值”规则判定，所以 `password = … AKIA…` 报的是更具体的
  `aws-access-key`。
- **二进制不扫描**：index 内容不是 UTF-8 就进 `unscanned`，呈现为“not scanned (not text)”，
  而不是“干净”。

## 3. 预览模型（`CommitPreview`）

`Repository::commit_preview(&[dirty])` 只读：

| 字段 | 含义 |
|---|---|
| `staged` | index 列有变化的路径（真正会提交的） |
| `not_staged` | 工作区有变化但没暂存的路径（留在外面） |
| `untracked` | 未跟踪路径（也留在外面） |
| `dirty` | 调用方报告“有未保存修改”且正好在暂存列表里的路径 |
| `secrets` | 暂存内容里的发现（`path:line kind`） |
| `unscanned` | index 内容读不出文本的路径 |

`can_commit()` = 有暂存 **且** 无机密。构建预览不暂存、不写盘、不提交。

## 4. 命令行

| 操作 | 行为 |
|---|---|
| `dirty:<path>` | 声明一个有未保存修改的打开文档 |
| `commit-preview` | 只打印预览 |
| `commit:<message>` | **先跑预览**；有机密或没暂存 → 打印预览后拒绝；否则打印预览并真的提交 |

## 6. 仍未完成（不伪造）

- **没有逐块暂存**：T20.03 交付物里的“选择变化”目前是整文件级（`stage:<path>`）；按 hunk 暂存
  需要把 diff 切成可应用的补丁并 `apply --cached`，本轮没做。
- **机密扫描是形态匹配**，不是熵检测或供应商校验；高熵随机串（不在已知前缀下）不会命中。
- **脏缓冲由调用方报告**：CLI 不知道自己打开了哪些文档；窗口侧应把 `Tab::is_dirty` 接上。
- 扫描只看暂存内容（这正是会提交的东西），不扫未暂存/未跟踪文件。
