## 2. 做法与“为什么不是自己拼 diff”

| 项 | 说明 |
|---|---|
| `diff_hunks(path)` | 读 `git diff --no-color -- <path>`，以 `@@` 行切分；每块保留 Git 打印的原文 |
| `stage_hunk(path, n)` | 取 **Git 自己打印的** 文件头 + 第 n 块，经 `git apply --cached -` 应用到 index |
| 编号 | 1 起（给人读的序号）；0 或超出范围都拒绝，并报出**当前**还有几块 |
| 只动 index | `--cached`；工作区不变——这是“逐块暂存”的定义 |
| 二进制 | 没有 `@@`，块数为 0，报 `no unstaged text change`，不假装暂存了 |

不自己拼补丁的原因很直接：上下文行、行号偏移、`\ No newline at end of file` 这些细节 Git 已经在
diff 里写好了；重写一遍只会引入“看起来一样但 apply 失败”的补丁。

## 3. 命令行

| 操作 | 行为 |
|---|---|
| `hunks:<path>` | 列出未暂存改动分成的块，各带 `@@` 头 |
| `stage-hunk:<path>:<n>` | 只把第 n 块放进 index |

## 4. 真实证据（30 行文件，三处改动相隔足够远）

```text
$ rustage --vcs repo:/tmp/rustage-hunks hunks:a.txt
hunk 1 of a.txt: @@ -1,5 +1,5 @@
hunk 2 of a.txt: @@ -12,7 +12,7 @@ line 11
hunk 3 of a.txt: @@ -26,5 +26,5 @@ line 25

$ rustage --vcs repo:/tmp/rustage-hunks stage-hunk:a.txt:2
staged hunk 2 of a.txt (3 hunk(s) were unstaged)

$ git -C /tmp/rustage-hunks diff --cached -U0
@@ -15 +15 @@ line 14
-line 15
+line 15 changed

$ git -C /tmp/rustage-hunks diff -U0 | grep '^[+-]line'
-line 2
+line 2 changed
-line 29
+line 29 changed

$ rustage --vcs repo:/tmp/rustage-hunks stage-hunk:a.txt:9
rustage: hunk 9 does not exist; "a.txt" has 2 hunk(s)
（exit 4——注意报的是“暂存之后还剩 2 块”，不是原来的 3 块）
```

测试：`app::vcs` 29 passed（新增 2 项：三块中只暂存第 2 块且工作区保留其余两块、越界编号拒绝；
二进制改动没有可暂存的块）。
