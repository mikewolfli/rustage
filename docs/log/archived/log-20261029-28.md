## 1. 验收线

T20.02：**“设计 diff 不是只看格式，手写变化可见”**。两句话对应两个函数：

1. **设计结构 diff**：按文档路径报告增/删/改，而不是“四十行文本变了”。
2. **生成/手写分割**：同一个代码文件的两个版本，按库自己的 region 标记分开比，指出是**生成体**
   变了还是某个**具名手写区**变了。

## 2. 模型（`src/app/vcs/design_diff.rs`，新）

### 设计结构

| 项 | 说明 |
|---|---|
| 路径 | 从 `$` 开始；对象成员 `.name`，数组元素 `[i]` |
| 对象 | 按成员名并集逐项比较：只在旧侧→`removed`，只在新侧→`added`，两侧都在→递归 |
| 数组 | 按**索引**逐项比较，末尾多出的下标是 `added`/`removed`——插入一个元素不会被报成一整个数组变化 |
| 类型变化 | 同一路径值类型变了就是 `changed`，两侧打印各自的 compact JSON |
| 输出 | 每行一条差异，末尾一行 `design diff: A added, R removed, C changed` |

### 生成/手写分割

用 `generate::artifact::regions()`（库标记：`// region:generated` … `// endregion:generated`、
`// region:handwritten <name>` …）切出每一段，再按“哪一段”比较：

| 项 | 说明 |
|---|---|
| 键 | `Side::Generated` 或 `Side::Handwritten(name)` |
| 一个文件可以有多个生成段 | 最后一段手写区之后的文本也是生成段，所以同侧内容**拼接**而不是互相覆盖 |
| 标记不平衡 | 直接拒绝（`regions` 报错），不切一半——把半个文件判给错的属主比说“判不了”更糟 |
| 输出 | 逐段 `unchanged/changed/added/removed`，末尾 `code diff: generated changed, N hand-written region(s) changed` |

## 3. 命令行（`--vcs`）

| 操作 | 行为 |
|---|---|
| `design-diff:<revision>:<path>` | 该修订下的 JSON 与工作区文件的结构 diff |
| `code-diff:<revision>:<path>` | 该修订下的代码与工作区文件的生成/手写分割 |

两个都只读。修订侧的内容经 `git show <rev>:<path>`（T20.04 的 `commit_show`），工作区侧直接读文件。

```text
$ rustage --vcs repo:/tmp/rustage-t20-02 design-diff:HEAD:project.json
added $.other: true
added $.pages[1]: {"name":"settings"}
removed $.tags: ["x"]
changed $.title: "Checkout" -> "Checkout 2"
```

第二份输出正是 T20.02 要的：**生成体和名为 `save` 的手写区都被改了**，评审者不需要读整个文件就能
看出这一点。
