## 2. T16.09：日志诊断带来源与版本

验收缺口原是“`dag::Problem` 丢 owner；未入 `quality::Center`”。

| 项 | 说明 |
|---|---|
| `Problem.owner` | 由命中的 matcher 带上；`render()` 变成 `owner file:line: message`——日志里多个工具的输出，没有来源的条目没人能处理 |
| `--dag match:<line>` | 命中行除了打印，还作为**构建问题**进入 `quality::Center` |
| 问题中心条目 | `source: Build`、`target`（`target:<name>`，默认 `desktop`）、`revision`（`revision:<n>`，默认 0）、`location: file:line`、`severity: Error` |
| 去重 | 沿用 `Center::add` 的既有规则（同 source/target/revision/node/location 视为同一条） |
| 新增操作 | `target:<name>`、`revision:<n>` |

真实输出：

```text
$ rustage --dag node:build pattern:cargo:'(.+):(\d+): (.+)':0:1:2 \
      target:desktop revision:7 'match:src/main.rs:12: mismatched types' \
      'match:src/lib.rs:3: unused import' 'match:Compiling demo'
cargo src/main.rs:12: mismatched types
cargo src/lib.rs:3: unused import
no matcher read "Compiling demo"
wave 0: build
[error] build desktop@r7 src/main.rs:12: cargo: mismatched types
[error] build desktop@r7 src/lib.rs:3: cargo: unused import
matched problems: 2 (source build, target desktop, revision 7)
```

第三行是“未命中”而不是“无问题”：`Compiling demo` 不是问题行，扫描器不把它变成一条错误。

测试：`app::build::dag` 7 passed（owner 进入 `Problem` 与 `render`）。
