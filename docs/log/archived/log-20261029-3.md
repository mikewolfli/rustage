### C. T08.05：批替换落盘

文件：`src/app/search/batch_replace.rs`、`src/app/run/search.rs`

- `Batch::commit(root)`：先写隐藏临时文件，全部成功后再 rename；路径逃逸（绝对、`..`、根自身）
  在创建临时文件前拒绝。
- rename 中途失败：已落盘文件保留并记录；未落盘文件进入 pending；`is_complete()` 为 false。
- `Batch::rollback(root)`：用同一两阶段写入恢复旧文；本批新建的文件被删除。
- CLI：`commit:<root>` 与 `undo:<root>`；普通 `undo` 仍只回内存。

真实命令：

```text
$ target/debug/rustage --batch open:a.rs:1=one edit:a.rs:1:0:0:two run commit:target/t08
commit: 1/1 written, complete
$ cat target/t08/a.rs
twoone
```

测试：`app::search::batch_replace::` 10 passed。

未覆盖：符号链接逃逸未解析；commit 不重新做外部基线检查；无 fsync 持久性承诺。

### D. T02.05：设计引用重写

文件：`src/project/record/files.rs`、`src/project/record/page.rs`

- `PageDocument::rewire_asset(from, to)`：只改写 `PropertyValue::Asset`，保留未知字段/子节点/
  非资产属性，返回改写数量；`from == to` 为 no-op，空路径拒绝。
- `FilePlan` 在 `Move`/rename 时把页面文档改写纳入同一计划；页面解析/改写失败为 blocker；
  执行前校验页面仍与计划文本一致；任一步失败回滚页面写入与文件移动。
- `Delete` 仍有引用时拒绝；`Exclude` 不再因页面引用而阻塞（文件未移动）。

测试：`project::record::` 86 passed。

未覆盖：页面文档仍用 `std::fs::write` + 回滚，不是进程崩溃安全的两阶段提交；
删除的“改写或移除引用”策略 API 未提供，当前选择明确拒绝。
