## 1. 之前的状态与这一轮

`--e2e` 之前只**记录调用方声明的结果**（`check:ok`、`build:fail:…`）—— 报告形状对，但没有一次
真正的构建。这一轮加了 `walk:<directory>:<program>`：

1. `cargo check`（真的进程）；
2. `cargo build`（真的进程）；
3. 跑 `target/debug/<program>`（真的进程）；
4. 失败时把**编译器自己打印的第一条 `error` 行 + 紧随的 `--> file:line`** 作为 `feedback`。

失败即停：check 失败时 `build`/`run` 不会运行；配合 `skip` 会显式写成“skipped”，而
`Report::is_success` 不会把 skipped 当通过（这条规则本来就有，这轮用它）。

## 2. 真实证据（`tests/build_e2e.rs`，2 passed，0.23 s）

```text
# 正常工程（无依赖，构建快）
generate: skipped (an earlier stage blocked it)     # 本次 walk 不含生成阶段
check (cargo check): ok
build (cargo build): ok
run (.../target/debug/e2e-fixture exited 0 (built)): ok
feedback (the build reported no problem): ok

# 故意写坏的工程
check (cargo check): failed: error[E0308]: mismatched types --> src/main.rs:1:26
build: skipped (an earlier stage blocked it)
run: skipped (an earlier stage blocked it)
feedback (error[E0308]: mismatched types --> src/main.rs:1:26): failed: …
blocked at check
（exit 非零）
```

测试是**独立集成测试**（不在单测进程里），用 `CARGO_BIN_EXE_rustage` 调真实宿主二进制；`cargo`
不在 PATH 时打印原因并跳过。

## 3. 仍未完成（不伪造）

- **生成阶段不在这个 walk 里**：`walk` 只做 check/build/run/feedback；生成由生成器自己的测试覆盖。
  因此 T16.08 仍标“部分”，不是“已关闭”。
- **夹具不依赖 `rust_widgets`**：为了能在 0.3 秒内跑完门禁，夹具是两行 `main.rs`。它能证明
  “check/build/run/错误回流是真执行”，**不**证明“生成出来的代码能在干净工程里编译”。后者需要
  路径依赖 + 分钟级构建，单列为下一步（`RUSTAGE_E2E=1` 门控 + 缺上游路径时跳过 + 标注耗时）。
- 没有覆盖 `generate` 的 CI 形态（`--headless` 那条属 T16.11）。
