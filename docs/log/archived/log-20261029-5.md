## 1. T13.04：WIRE_RULES 与句柄生命周期

文件：

- `src/app/data/dispatch.rs`
- `src/app/data/events.rs`
- `src/app/run/workbench_events.rs`
- `src/app/run/data_events.rs`

实现：

- `Dispatcher` 使用库 `compatibility`/`WIRE_RULES`：
  - `Action::Command` → `PayloadFreeCommand`，载荷事件被拒并给出库的原因；
  - `Action::Set` → 属性目标，按载荷类型兼容性判断；
  - `Action::Call` 仍由函数契约检查，不硬套属性表。
- `Subscription` 携带 `ConnectionHandle`；`Wiring::attach` 返回句柄，重绑退旧句柄，
  `detach` 返回被移除的 `Attachment` 并退句柄。
- 新增 `BindingScope`，镜像库 `ConnectionScope` 的 drop 释放语义；`Dispatcher` 支持
  `unbind_handle`/`is_live`/`dispatch_by_handle`，旧句柄不能触发。
- `--events detach:<node>:<event>` 可释放接线记录；`--dispatch` 增加 `control:` 与
  `event:<name>:<kind|none|payload>`。

真实 CLI：

```text
# 允许
--dispatch control:button event:pressed:none command:save bind:1:pressed:command:save
node 1: pressed: installed

# 拒绝
--dispatch control:button event:state_changed:string command:save bind:1:state_changed:command:save
rustage: the library's WIRE_RULES refuses this wire: this command takes no payload, so a
value-carrying event has nowhere to put its value; use a property target or a command that
accepts one
```

测试：

```text

cargo test --bin rustage app::data::dispatch::tests         27 passed
cargo test --bin rustage app::data::events::tests           28 passed
cargo test --bin rustage app::run::workbench_events::tests  13 passed
cargo test --bin rustage app::run::data_events::tests        3 passed
cargo test --bin rustage app::run::gui_smoke::tests          7 passed
```

**仍未完成**：`EventSignalRef` 需要 mounted `Widget`，`EventSignalBinder` 还需要
`Arc<CustomSignalHub>`；面板路径没有两者，因此句柄是宿主记录身份，不声称真实槽已连接。
真实订阅留给 T14.02 的 mount 路径。`gui_smoke` 的 legacy `Dispatcher::install` 无声明，
仍宽松；CLI 帮助文本也未列出新操作。

## 2. T09.02：场景索引快照

文件：

- `src/app/canvas/scene.rs`
- `src/app/canvas/design.rs`

实现：

- `SceneIndex` 提供 `id_at(path)`、`path_of(node)`、`id_of_key(parent,key)`、`key_of(node)`、
  `keys()`、`duplicate_keys()`、`len()`、`generation()`。
- 键按兄弟作用域；重复兄弟键不映射到任一 claimant 并报告；路径是 generation 快照地址。
- `Scene` 有场景级 `generation`，插入/重建/删除/改父/raise/改键递增；`OnceLock<SceneIndex>`
  在首次查询时重建，成本为每次被查询 generation 一次 `O(n log n)` 遍历。
- `Surface::scene` 用树节点名作为键；tree/canvas 通过同一 scene/index 解析 NodeId。
- 多根文档用虚拟根：顶层路径从 `[i]` 开始。

测试：

```text
cargo test --bin rustage app::canvas::  88 passed
```

**仍未完成**：上游 `TreeIndex::build` 是 `pub(crate)`，唯一公开生产者是
`ViewEngine::tree_index`，索引的是 mounted `ObjectId`；画布未 mount，无法直接使用库类型。
`SceneIndex` 是有注释的适配层。对象树没有独立 key 字段，暂用节点名，因此重名键不可映射
并会报告。

## 3. T11.01：属性契约 Schema

文件：

- `src/app/style/property_editor.rs`
- `src/app/run/workbench_property.rs`

实现：

- `Schema::from_property_schema(control, &ContractPropertySchema)`：
  - `Int/UInt → Integer`（无符号强制 `min=0`）、`Float/Number → Number`（Range 边界）、
    `String → Text`、`Enum → Enum`（只用发布 tokens）、`Color → Colour`。
  - 显式拒绝 bool/rect/icon-spec/records/list 等当前编辑器无法诚实表达的 kind。
- `Schema::from_manifest` 映射所有可表达属性，把不可表达项记入 `gaps()`，不静默丢弃。
- 默认值来自契约（`with_default/default_of`），accepted tokens 来自契约。
- `PropertyState::for_control` 读 `WidgetFactory::property_schema` 与
  `default_property_value`；未知属性/类型返回 “schema unavailable”，不回退到猜测的 Text。
- 多选 agreed/mixed 行为保持。

测试：

```text
cargo test --bin rustage app::style::property_editor::      15 passed
cargo test --bin rustage app::run::workbench_property::    12 passed
```

**仍未完成**：工作台 GUI 仍初始化 `PropertyState::new("Demo")`，没有切换到
`for_control`；bool/rect/icon/list/records 类型尚未可编辑，扩展 `PropertyType` 会要求
`data/dispatch.rs` 的 `wire_kind` 匹配同步扩展。
