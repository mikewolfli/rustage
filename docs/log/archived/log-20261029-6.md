## 1. T11.01：Inspector 使用真实契约

文件：

- `src/app/run/workbench_scene.rs`
- `src/app/run/workbench_property.rs`
- `src/app/run/workbench_gui.rs`
- `src/app/style/property_editor.rs`

实现：

- `NodeContract { control, property }` 存在 `CanvasState` 的显式 map：
  - window → `window.title`
  - Demo panel → `panel.title`
  - button/footer → `button.text`
  - label/hidden note → `label.text`
  - 缺失映射/已删除节点返回错误，不按显示名猜。
- `PropertyState::retarget_control(node, control, property, initial)` 同时切 control 与
  property；`retarget_many_contracts` 处理 marquee。
- 多选：相同 control/property 才可编辑；不同 property/type 显示 mixed 并拒绝编辑，
  不同 control 但同 property 会报告差异。
- `Editor::rebind` 在类型不变时保留旧值；类型变化时丢弃，避免旧值冒充新契约。
- GUI 启动与选择路径都使用契约；只有 `title` 编辑重命名树节点，`text` 编辑不再改结构名。

测试：

```text
cargo test --bin rustage app::run::workbench_property::  18 passed
cargo test --bin rustage app::run::workbench_scene::      7 passed
cargo test --bin rustage app::style::property_editor::   16 passed
```

未覆盖：bool/rect/list/records 仍不可编辑（扩展 `PropertyType` 需同步
`data/dispatch.rs::wire_kind`）；button/label 的 `text` 值未在画布上渲染；真实文档导入
需要在建节点时填充 `NodeContract`。

## 2. T16.01：真实工具链探测

文件：

- `src/app/build/toolchain.rs`
- `src/app/run/build.rs`

实现：

- `Environment::probe()` 真实执行：
  - `cargo --version`
  - `rustc --version`
  - `rustup target list --installed`
- `CommandRunner` trait + `SystemCommandRunner` 使用 `host::subprocess::OwnedProcess`，
  argv-only、5s 超时、64 KiB 输出上限；超限拒绝解析，不把截断文本当完整结果。
- SDK 只信任显式信号：Windows `WindowsSdkDir`，macOS `SDKROOT`；没有探测到就写
  “not detected on this host”，不猜。
- `--toolchain` 从 probe 开始，再应用 CLI 覆盖；`check` 对 Missing/Unsupported 都失败，
  非 `check` 时 Missing 只报告。

真实 macOS 输出：

```text
$ --toolchain profile:desktop check
cargo: cargo 1.98.1 (797e8a9bc 2026-08-05)
rustc: rustc 1.98.1 (48a229cea 2026-09-01)
targets: aarch64-apple-darwin, aarch64-linux-android, x86_64-apple-darwin,
         x86_64-pc-windows-msvc, x86_64-unknown-linux-gnu
sdk: not detected on this host
toolchain: ready
```

测试：

```text
cargo test --bin rustage app::build::toolchain::  12 passed
cargo test --bin rustage app::run::build::        6 passed
```

未覆盖：SDK 探测不运行 `xwin`/`xcrun`；无 rustup 时 target 列表为空，保守报 Missing。

## 3. T21.02：契约能力与容量事实

文件：

- `src/app/quality/report.rs`
- `src/app/run/quality.rs`

实现：

- `Provenance::{Supplied,Contract}` 区分调用方事实与库事实。
- `DesignFacts::capability_from(factory, profile, names)` 使用
  `designer::availability_with`；Local/CrossProfile 接受，Unavailable/Unknown 诊断。
- `DesignFacts::capacity_from(profile)` 读
  `rust_widgets::platform::profile::surface_policy()`，记录
  `max_widgets/max_texture/font_cache_bytes/event_queue`。
- `--quality contract-control:<profile>:<name,...>` 与 `contract-capacity:<profile>`；
  容量溢出报告库限制并注明 “the library's surface policy”。

真实输出：

```text
contract-control:desktop:button,slider
  capability button local (contract desktop)
  capability slider local (contract desktop)
capacity:5000:0
contract-capacity:desktop
  capacity 5000/4096 from surface policy desktop
  (textures 4096, font cache 2097152 bytes, event queue 256)
  [error] ... over the target limit of 4096 (the library's surface policy)
```

测试：

```text
cargo test --bin rustage app::quality::report::  19 passed
cargo test --bin rustage app::run::quality::      6 passed
```

**仍是部分**：库 `surface_policy()` 没有 profile 参数，只描述当前构建 profile；desktop
构建请求 mini/embedded 时只能报告 gap。纹理/字形缓存/事件队列限制已记录，但文档事实模型
还没有对应字段，因此未检查。
