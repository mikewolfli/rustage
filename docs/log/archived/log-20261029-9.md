## 1. T16.03：JSON 诊断回流

文件：

- `src/app/build/build_diagnostics.rs`
- `src/app/run/build.rs`

实现：

- 保留原 text/file parser；新增：
  - `Diagnostic { message, node, unmapped }`
  - `Report { revision, diagnostics }`
  - `Batch::place(map, text_of)`：按 SourceMap 映射 span；revision 不匹配时拒绝映射，
    不跳到可能移动的行。
  - `Diagnostic::problem`/`Report::problems`：生成 `quality::Problem`，`Source::Build`，
    带 target、revision、severity、message/code，映射成功才带 node。
  - `Report::record`：写入 `quality::Center`，沿用同键去重。
- `--compile execute` 解析捕获的 JSON stdout，打印问题并可写到 `diag-record:<file>`。
- 新 `--compile` 操作：`diag-source`、`diag-model`、`diag-current`、`diag-span`、
  `diag-record`；没有 `execute` 时拒绝，因为没有真实流。
- `--build-diag` 复用 `Batch::place`，未映射诊断明确显示而非静默丢弃。
- 非编译器 JSON/非 JSON 行保留为原始输出，不压掉有效诊断。

测试：

```text
cargo test --bin rustage app::build::build_diagnostics::  10 passed
cargo test --bin rustage app::run::build::                10 passed
```

新增覆盖：JSON 解析、映射 NodeId、未映射仍报告、Center 去重、噪声不丢有效消息、
过期 map 拒绝。

**未覆盖**：cargo 相对 `file_name` 按后缀匹配；CLI help 未列 `diag-*`。

## 2. T10.03/T10.04：约束值与文档事务

文件：

- `src/app/layout/layout_plan.rs`
- `src/app/layout/arrange.rs`
- `src/app/run/layout.rs`

T10.03：

- `Value::{Scalar,Size,Cell,Word}`；`Constraint::value`/`with_value`。
- 库映射：
  - min/max/preferred → `Hints`/`AxisHints`
  - width/height → pinned hint
  - grow → stretch
  - margin → `LayoutParams::margins`
  - gap/padding → container spacing（冲突拒绝）
  - x/y → `AbsolutePosition`
  - cell → `GridLayout::set_widget(row,column,id)`
  - align → flex/grid alignment
  - order → flex item order
- 不支持/缺值/冲突返回带节点/属性的诊断。例如 flex 上的 x、grid 上的 min、stack 上任何
  带值约束、重复值、fractional grow。
- `constraint` 语法支持 `<node>:<property>:<origin>[:<value>]`。

T10.04：

- `Change { node, property, value }`。
- 纯文档 `apply_change`/`validate_change`/`validate_document` 与 `Inverse`。
- `Transaction::undo` 精确恢复 before 文档；`apply_to` 一个操作一次事务。
- align/distribute/match/nudge 产生真实 width/height/gap/坐标；几何缺失时拒绝而不是编坐标。
- 校验 min/max/preferred、非负长度、有限坐标、align 词法。

测试：

```text
cargo test --bin rustage app::layout::      100 passed
cargo test --bin rustage app::run::layout::   6 passed
```

**库 gap**：Flex 只读 `Hints::min`；Grid 只读 preferred；Stack 忽略 hint；
Absolute 无 hint 通道；无 column-only grid API；stretch 是 u32，fractional grow 被拒。

## 3. T15.07：整工程导出

文件：

- `src/app/generate/artifact.rs`
- `src/app/generate/export.rs`
- `src/app/run/generate.rs`

实现：

- `--export project:<project.json> [root:<dir>] commit`：
  - 读取 project document，枚举 `generated` entries；
  - 用真实 pipeline 生成每个计划文件；
  - 若源指向 dual pair（`ui_default.rs` + `ui_stripped.rs`），运行一次 `run_dual` 产出两份；
  - 生成 gap 会阻断导出。
- `PlannedGroup`/`ProjectPlan`/`plan_project`/`dual_outputs`：拒绝空路径、重复输出、
  一源两输出（除 canonical dual pair）、两源一输出。
- `export::commit`：先暂存全部临时文件；已存在目标走 `merge::prepare`：
  - 无 marker 拒绝；
  - 有 marker merge，保留手写区；
  - rename 前保存 `.bak`；后一个失败时恢复已 rename 的旧文件并删除新建文件。
- `artifact:<path>=<file>` 低层复制也走同一 guard。

测试：

```text
cargo test --bin rustage app::generate::      72 passed
cargo test --bin rustage app::run::generate:: 15 passed
```

新增覆盖：整工程输出、dual pair、unmarked 拒绝、merge 保留、第二次导出字节相同、
中途失败回滚。

**未覆盖**：项目模型没有 per-entry target/profile 与尺寸/函数名；canonical stripped
路径之外的自定义 stripped 输出不可表达。`dual` 命令的写路径仍逐文件。
