## 1. 范围与原则取舍

| 决策 | 依据 | 理由 |
|---|---|---|
| 只引用上游内置轮廓，不复制 69 项轮廓 | resources.md §4、§6.2；principle #55/#59 | 上游轮廓是依赖内数据；rustage 保存语义 ID 与映射，不建立第二条会漂移的几何来源 |
| 用 `upstream-tokens.json` 保存 token 契约快照 | resources.md §6.2、§16.1 | 校验和构建不依赖个人机器上的 sibling 仓库；快照只含 token 名，不含几何、路径或枚举序号 |
| 自有 glyph 限制在严格 SVG 子集 | resources.md §5.2、§2.2 | 绝对 `M/L/H/V/C/Z`、闭合填充、显式 `fill-rule`、无描边/变换/洞，转换可验证且不会静默丢弃特性 |
| 不建立 `src/resources/` 适配层 | resources.md §17.2；principle #26 | GUI 依赖与 JSON 依赖尚未决策；现在写只能是没有真实消费者的占位实现，且会先假设未核验的上游 API |
| 不建立 `tests/baselines/icons/` | resources.md §16.2；principle #26 | 视觉基线必须是真实后端截图，宿主 GUI 还不存在；伪造基线等于用印象代替证据 |
| 不手工修改每个平台的 PNG | resources.md §13.5 | 平台图标全部由品牌母版加固定参数派生，小尺寸走单独母版 |
| 应用身份保持未决策 | resources.md §17.2；roadmap T00.04/T25.02 | 不虚构 reverse-DNS 应用 ID、最低系统版本与发行形态；打包元数据因此报告阻塞而不是填占位值 |
| 面板图标复用同一批语义 glyph | resources.md §5.1 | 不为每种面板和状态组合画一张文件；首版只覆盖真实消费点所需的重叠集合 |

## 2. 新增结构

```text
resources/host/icons/manifest.json          语义 ID、来源、频道、颜色角色、RTL、来源许可
resources/host/icons/upstream-tokens.json   固定修订（c957fdec）的 69 项 token 契约快照
resources/host/icons/custom/*.svg           19 个自有单色 glyph（24 单位、2 单位安全留白）
resources/branding/app-icon.svg             512 母版（渐变底 + 白色标记）
resources/branding/app-icon-small.svg       64 母版（纯色底，供 ≤64 px 使用）
resources/branding/logo.svg                 单色标记（品牌主色）
resources/branding/logo-monochrome.svg      单色标记（跟随文字颜色）
resources/branding/manifest.json            色彩、留白、母版角色、派生规格（ICO/ICNS/hicolor 尺寸）
resources/licenses/manifest.json            许可与来源记录（含源摘要与本地副本路径）
resources/licenses/material-symbols/LICENSE Apache-2.0 副本（与上游字节一致，摘要已核验）
resources/licenses/material-symbols/ATTRIBUTION.md  归属与来源说明
packaging/identity.json                     应用身份、最低版本、发行形态、install prefix、token 列表
packaging/{windows,macos,linux}/            模板（.rc、Info.plist、.desktop）与平台配置
tools/resources/check-resources.mjs         资源校验入口
tools/resources/lib/*.mjs                   清单/路线图/SVG 子集/PNG/缩放/ICO/ICNS/光栅器探针
tools/resources/generate-resources.mjs      派生产物与生成报告
tools/resources/check-resources.test.mjs    27 项校验用例（含负向输入）
```

清单与路线图对齐方式：`manifest.json` 的 `commands` 覆盖路线图 §3.2 的全部命令组，
`panels` 覆盖 §2.2 的全部面板 ID，校验器直接解析 `docs/plan/roadmap.md` 作为唯一清单，
缺项、多项、重复、无理由的“无图标”都会失败。当前 71 个命令组 + 42 个面板全部有显式决策，
其中 15 项明确为“无图标”并写明理由。

图标总量：60 项（41 项复用内置 token、19 项自有静态几何），字符串注册通道 0 项
（预算 ≤12）。自有 glyph 源共 6907 字节（单文件 ≤32 KiB、合计 ≤256 KiB）。

## 4. 阻塞与未验证项

1. **应用身份未决策（阻塞打包元数据）**：`application_id`、各平台最低系统版本、
   `install_prefix` 与发行形态为 `null`。生成器对需要这些值的模板报告 `blocked` 并列出
   缺失 token，不写入占位值；平台图标按二进制名 `rustage` 输出，安装后 basename 必须等于
   应用 ID，这一点已在报告中单独标为阻塞。决策归属：roadmap T00.04、T25.02。
2. **没有任何真实控件绘制**：`manifest.json` 只声明来源与频道；把语义 ID 变成实际绘制需要
   固定 GUI 依赖与真实控件探针（F00/T05.02），本次未做。
3. **展平容量未验证**：`host-icons.geometry.json` 记录的是源声明的轮廓数与点数
   （源级预算 64/1024），曲线展平后的真实点数只能在依赖的展平 API 上测量。
4. **平台显示未验证**：Windows Explorer/快捷方式/任务栏/Alt-Tab、macOS Finder/Dock、
   GNOME/KDE 启动器均未验证——本机没有这些目标系统。ICNS 的展开与 ICO/PNG 的解码只证明
   容器与尺寸正确，不证明系统显示正确。
5. **主题、DPI、状态、无障碍未验证**：颜色角色、尺寸角色、禁用/焦点/读屏名称都只有清单
   和规范，没有真实主题切换、多 DPI 或辅助技术实测。
6. **RTL 全部声明为不镜像**：首版 glyph 都画成与方向无关（例如状态流转不含箭头），
   因此 `rtl_mirror` 全为 `false`；镜像接缝与逐语义决策留给 T24.02/T24.06。
7. **品牌稿未经批准**：`resources/branding/manifest.json` 的 `status` 为
   `proposed-pending-approval`，色彩与标记是待审阅提案，不是已批准的品牌规范。
8. **未做的工程环节**：无签名/公证、无 SBOM、无安装包、无 `OUT_DIR` 集成（无 `build.rs`）、
   无用户工程资源导入流水线（T12.05/T12.06/T12.09）。
