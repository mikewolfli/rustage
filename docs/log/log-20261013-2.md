## 1. 范围与原则取舍

| 决策 | 依据 | 理由 |
|---|---|---|
| 自有 glyph 改为 `stroke` 中线 + 构建期展开 | resources.md §5.2、§8.1 | 闭合环展开后必然是带洞轮廓，逐轮廓填充不保真；中线源可读可改，展开规则显式，输出多边形后容量可精确核算 |
| 一套图标只有一个光学重量（线宽 2、圆端圆角） | resources.md §5.2 | 与上游 Material Symbols outlined 的视觉重量对齐，不逐图调粗细 |
| 闭合外形拆成两段同向开放中线 | resources.md §5.2 | 接点落在直边中点，两段圆端头互补成完整带，接缝不可见，同时保证无洞 |
| 每图最多一个实心母题 | resources.md §5.2 | 保持轻量；AI 星形与令牌方块等语义确实需要实心 |
| 源内只写 `currentColor`，并拒绝按状态/主题命名的源文件 | resources.md §9.1 | "换色不换文件"从校验上堵住重复图形，而不是靠约定 |
| `theme.json` 只作评审色板并明确标注未批准 | resources.md §9.1、§17.2；principle #26 | 真实主题取值属 T05.02/T24.02；本次不虚构产品颜色 |
| 生成主题矩阵图作为"随主题变化"的证据 | resources.md §16.2 | 用可视证据替代口头声明，并同时列出它没有覆盖的项 |
| 新增鸿蒙桌面打包（清单与资源层） | 用户要求；resources.md §13.4 | 与另三平台同一形态；字段与路径按官方文档与真实工程核对，来源记入 `packaging/harmonyos/app.json` |
| 鸿蒙 `versionCode` 由 `package.version` 派生 | resources.md §13.4 | 平台只要求单调递增；派生避免与 `versionName` 脱节；方案无法表示的版本直接报错，不静默截断 |
| 不生成 ArkTS 入口代码 | resources.md §3.4 | `EntryAbility`、`pages` 属于宿主应用而非资源树；本目录只提供清单与资源 |
| 不对鸿蒙声明任何支持结论 | principle #26 | 固定版本的 winit/wgpu 能否在 2in1 上以原生模块承载**未验证**，需先做小样 |

展开与展平的实现要点（可核对代码与产物，不靠描述）：

* `strokeToOutline`：两侧按半笔宽偏移；外角插入半径等于半笔宽的圆弧，内角取两条内偏移线
  的交点（与 SVG `stroke-linejoin="round"` 一致：外圆内尖），两端加圆端头；结果是一个
  单连通、无洞的闭合轮廓，并按正面积方向统一缠绕。
* 填充曲线按 0.05 网格单位的容差展平；因此**送进渲染端的几何全部是多边形**，
  依赖侧的展平点数等于声明点数，不再有"曲线展平后点数未知"的空白。
* `H`/`V` 在输出时展开为 `L`，`y' = y - 24` 保持原约定不变。


一次独立复核（另一路只读官方文档与 DevEco 模板的检索）与上面的实现逐条对齐，并补出三条
必须写清楚而不能当规范的地方，已写进 `packaging/harmonyos/app.json`：

* **图标像素尺寸没有平台规定值**：官方文档只规定启动页图标与底色资源"不可缺省"，
  以及必须能被 `$media:`/`$color:` 解析；1024 是 DevEco 生成工程里的实测值（另一工程的
  启动页图标实测为 144），不是规格。本仓库取 1024/512 并在定义里标注为待验收项。
* **资源文件名是约定不是要求**：`background/foreground/app_icon/layered_image` 都是 DevEco
  约定，文件名可改，只有 `$media:` 引用要与文件名一致。本次沿用约定命名，
  以便与生成工程直接对照。
* **`versionCode` 与 semver 没有文档化公式**：平台只要求 32 位非负整数且严格递增。
  本仓库的方案是**本项目自定**的派生规则（写在定义里、生成器实现、越界即报错），
  不主张这是平台规范。
* 另外确认：`deviceTypes` 只写 `"2in1"` 合法，文档不要求同时写 `tablet`；
  Rust 在 OpenHarmony 的文档角色是系统级构建与 C ABI 互操作，
  应用侧原生套件文档只覆盖 C/C++ 与 Node-API，**没有任何文档描述 Rust 的窗口/事件循环路径**。

## 4. 阻塞与未验证项

1. **应用身份仍未决策（阻塞元数据，含鸿蒙）**：`application_id`、四平台最低系统版本、
   `install_prefix` 与发行形态为 `null`。`packaging/harmonyos/AppScope/app.json5` 与
   `build-profile.json5` 因此报告 `blocked` 并列出缺失 token。另外，共享的反域名标识还要满足
   鸿蒙 bundle name 约束（**不允许连字符**），校验器会用两条规则同时检查；决策归属
   roadmap T00.04、T25.02。
2. **没有任何真实控件绘制**：见 log-20261013-1 第 4 节第 2 条，本次没有变化。
3. **鸿蒙宿主承载未验证**：Rust 侧只有候选三元组；`winit`/`wgpu` 在 2in1 上以原生模块承载
   需要先做小样。本次交付的是清单与资源层，不是可运行应用。
4. **平台显示未验证**：Windows Explorer/快捷方式/任务栏/Alt-Tab、macOS Finder/Dock、
   GNOME/KDE 启动器、鸿蒙真机桌面与启动页均未验证；本机没有这些目标系统。
5. **主题、DPI、状态、无障碍未验证**：评审色板与矩阵图证明图形是单色且可换色，
   **不证明**任何控件已取到真实主题色，也不覆盖高对比主题、100%–300% 缩放、
   禁用/选中/错误状态、真实消费入口与 RTL 项；这些缺口同时列在 resources.md §16.2。
6. **品牌与主题取值均未经批准**：`resources/branding/manifest.json` 与
   `resources/host/icons/theme.json` 的 `status` 都是待批准提案。
7. **鸿蒙启动页图标尺寸无平台规定值**：官方文档未规定该资源的像素尺寸；本次取 512 并在
   `packaging/harmonyos/app.json` 中写明，实际观感属验收项。
8. **RTL 仍全部为不镜像**：本次新增 glyph 都是方向无关或按语义不对称（如 `source-map` 的
   `< >`、`translate` 的 `A→`），`rtl_mirror` 全为 `false`，接缝决策仍留给 T24.02/T24.06。
9. **未做的工程环节**：无签名/公证/鸿蒙签名配置、无 SBOM、无安装包、无 `OUT_DIR` 集成、
   无用户工程资源导入流水线（T12.05/T12.06/T12.09）。
10. **既有文档断链未修**：`docs/plan/capability-reference.md` 的 4 处链接缺失与本次无关，
    未创建该文件。
