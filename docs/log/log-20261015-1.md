## 2. 复核口径：什么叫"完成"

复核不是重读实现，而是按 blue1/blue2 每项任务的**路线图最低验收**去找一件可复核的东西。
本轮对每一项问三个问题，任何一个答不上就算未通过：

1. **交付物在位吗**——文件/命令/数据源存在，且是被真实调用链使用的（不是只被测试使用的孤岛）；
2. **验收词有对应的检查吗**——有自动化用例、门禁或探针输出能把那句话判成真/假；
3. **结论有原始输出吗**——命令、环境、退出码或产物路径，能被人重跑。

口径的来源是原则 #25（每项结论附可复核证据）与 #26（优先完整闭环而非占位）；判定红线是
"任何数据丢失、权限越界、未授权副作用、过期结果冒充当前结果或失败被显示成成功"（blue1/blue2 各
任务验收规范的共同末条）。

**本轮复核没有做的事**：没有把"实现存在"当成"验收通过"的唯一理由去改任何一个任务的交付物清单；
没有为了凑结论而放宽任何一条验收词；没有把设备相关（macOS/Windows）的格从 `blocked` 改成任何
"通过形状"的说法。

## 6. 本轮修掉的缺陷（逐项：现象 → 根因 → 修法 → 证据）

### 6.1 MS00 资源与工具栏的 8 处 lint 债

**现象**：`cargo build` / `cargo clippy --all-targets` 报 8 处 warning（`unused import`、
`never used`、`never read`），全部在 `src/resources/` 与 `src/app/toolbar.rs`。

**根因**：这些成员（`IconRole::ALL`/`from_str`/`color`、`HostIcon::record`、生成的
`ICON_ROLE_NAMES`、`ToolbarComposition`/`composition`/`glyphs_mut`/`refresh_if_stale`、`stale`、
`Tool::geometry`）**只被测试使用**：二进制 crate 在非测试构建里不编译 `#[cfg(test)]` 代码，于是
"只被测试用"就等于"没人用"。第三、四次记录都按"不改无关既有问题"保留，第四次明确记为
"本轮不修，免得被当成新引入的"。

**修法（按项目既有先例，不删行为）**：

1. 删掉 `src/resources/icons.rs` 里**没人用的 re-export** `pub use …::ICON_ROLE_NAMES`，测试改为从
   `crate::resources::generated_host_icons` 直接 import——这正是 `src/contracts/mod.rs` 模块文档
   写下的规则："a re-export nobody uses is an unused-import warning bought with nothing"；
2. `src/resources/mod.rs` 与 `src/app/toolbar.rs` 各加**一处**模块级 `#![allow(dead_code)]`，并把
   真正的原因写在上面（消费者是谁、哪个任务把它接到运行路径上：面板的角色赋值属 T12.04，绘制这条
   带的窗口属 T04）——与 `contracts`/`host`/`project` 三个模块的既有做法一致；
3. 顺带修正 `toolbar.rs` 模块文档里一句**与事实不符**的话：它写着这条带"a window and the baseline
   exporter both draw"，而窗口那一半当时并不存在（原则 #22/#27）。

**证据**：

```text
$ cargo build 2>&1 | grep -c warning          # 修前 8 处，修后 0 处
0
$ cargo clippy --all-targets 2>&1 | grep -E "^(warning|error)" | wc -l
0
```

### 6.2 工具链诊断把"没装上"与"装上了没答上"合并成一句话（T02.03 遗留）

**现象**：`toolchain: cargo: not found or did not answer`。两种事实（`PATH` 上没有 `cargo` / `cargo`
跑起来了但没给出可解析的版本行）在报告行上不可区分。

**根因**：事实在 `ProjectSession::diagnose_toolchain` 内部是知道的（`NotChecked::NotRunnable` 带
`reason`），但它被压成**自由文本**塞进 `ToolchainReport::checks`；报告行、`validate` 的 needs 与
`kit` 的 findings 三处各自再拼一句自己的话（后者甚至靠搜索 `` `cargo` `` 前缀从字符串里把原因捞
回来）。第四次记录 §43.4 第 5 条把这条列为"留待 T02.03/T16.01 收尾"，而 T02.03 就在本次复核范围里。

**修法**：加一个**类型化的**事实 `ToolUnavailable { NotInstalled, DidNotAnswer, DidNotFinish }`
（`NotChecked::NotRunnable` 随之删除——它只被一个测试构造，而"整体读不到"已由
`Checked` + 逐程序失败表达），三个消费者改为读同一个来源 `ToolchainReport::unavailable(program)`，
渲染行由 `ToolUnavailable::line()` 一处产出：这正是原则 #35/#59 要的"同一语义只保留一份定义"。

**同时补上超时**（第四次记录 §33.6 第 9 条："工具链检查没有超时与取消：一个挂在 PATH 上的坏包装器
会一直等"）：新抽出的 `read_tool_version(program, permit, limit, checks)` 用 T01.04 的
`wait_for` + `terminate`，超限即 `DidNotFinish` 并把它记进证据。

**证据（真实输出，本机）**：

```text
$ PATH=<一个只含"运行即 exit 3 的 cargo"的目录>:$PATH rustage --open-project …/project.json --trust --diagnose

$ env -u CARGO_HOME PATH=/usr/bin:/bin rustage --open-project …/project.json --trust --diagnose

```

两条命令在修前都会打印同一句 `not found or did not answer`。新增用例
`the_three_ways_a_toolchain_program_can_fail_are_told_apart` 用**真的会跑的程序**覆盖三种形态

### 6.4 `--help` 的用法块整块顶格（T02.09 遗留）

**现象**：`--help` 里所有续行都从第 0 列开始，`Usage:` 后面对齐的 `rustage …` 行与选项缩进全部
丢失。第四次记录 §40.5 第 8 条记下过："这是本轮之前就有的排版问题，与本轮无关，故没有顺手改"。

**根因**：`help_text()` 是一个用 `\n\` 续行写成的字符串字面量，而 Rust 的续行**会吃掉下一行行首的

```text
            rustage [--render-icons <directory> | --probe-apis <directory>]
            rustage [--probe-host <directory> | --project-check <file>]
                                 [--move <from> <to>] [--apply] [--trust]
       --log-level <level>           error | warn | info | debug | trace (default: info)
```

改法与改后的字节都做过核对：先用脚本按 Rust 的续行语义**重建旧字符串**（10 006 字节、138 行），
再按同一语义核对新实现的渲染结果与它**逐字节相同**（除了恢复的对齐）。新增用例
`the_usage_block_keeps_the_alignment_it_is_written_with` 钉住三处缩进，并断言不再出现顶格行。

## 7. 新发现一：本机的原生 Linux 桌面会话可达

**发现过程**：复核 T01.08 时去看"为什么 Linux 从来没有原生结果"。上游源码里 `runtime_gui_mode_for`

## 8. 新发现二：`--probe-host` 在原生会话里会自毁（已修）

**现象（原始输出，修前）**：

```text
$ ./target/debug/rustage --probe-host target/audit-20261015/host-gtk2 ; echo "exit=$?"
INFO host::startup: backend gtk initialised, gui mode NativeInteractive (+13 ms)
INFO host::startup: window 6000285942072475648 created 640x420 (+13 ms)
INFO host::platform: entering the event loop for a bounded session (+13 ms)
WARN host::platform: session deadline 120ms reached; ending the process because the pinned revision's quit() is main-thread-only (+134 ms)
exit=0
```

四行日志、**没有 `host-readiness.json`**、退出码 **0**：一个真的开了窗口的会话，被记成了一次
"看起来成功"的截断运行。这正是原则 #22 禁止的形状，而且它只在**原生会话**（也就是这条检查要验证的
那种环境）里出现——状态后端的机器上永远看不到。

**根因**：`startup-session` 检查在探针**自己的进程**里调用 `startup::launch()`；固定修订的
`--launch --exit-after-ms` 由 watcher 线程 `std::process::exit(0)` 结束**进程**（不是结束循环，见
[反馈文件第四节](../rw-feedback/feedback-20261015.md)），于是它结束的是**报告**。

**修法**：会话跑在**子进程**里（`rustage --launch --log-level info --exit-after-ms 150`），父进程
读子进程的退出码与输出作为证据；判定用退出码（0 = 会话起来了并结束；3 =
`ExitCode::EnvironmentUnavailable`，本环境开不了窗口 → `not-verified`；其余 → `gap`）。

**证据（修后，默认构建与原生构建各一次）**：

```text
$ ./target/debug/rustage --probe-host target/audit-20261015/final/host ; echo "exit=$?"
startup-session     not-verified the host's own launch command, asked for an exit after 150ms (the baseline
                                 window is its own default, 1280x800); a separate process ended exit code 3; it printed:
                                 WARN host::startup: backend linux-state-backend reports gui mode PreviewOrStub, so no
                                 window would appear; this host does not claim a started session (+11 ms)
summary: 12 ready, 1 gap, 2 not verified
exit=4

$ ./target/debug/rustage --probe-host target/audit-20261015/host-gtk3 ; echo "exit=$?"
startup-session     ready        … a separate process ended exit code 0; it printed: … window … created 1280x800 …
summary: 13 ready, 1 gap, 1 not verified
exit=4
```

**副产物一**：证据变强了——"一个独立的进程创建了窗口"比"本进程进过循环"更接近人真正跑一次的情形。
**副产物二**：报告与产物在两种环境下都能写全（`host-readiness.json` 两次都写出）。

## 12. 未覆盖项、阻塞项与未验证组合

**12.1 阻塞（需要真机或需要屏幕前的人）**

1. macOS 与 Windows 的 `--probe-host`：本仓库没有那两种测试机，记录里两列全为 `blocked`，
   并写明缺什么。T01.08 的验收词"各平台有真实结果，缺测试机标阻塞"因此只满足 Linux 一侧。
2. **窗口是否被合成到屏幕、是否接受真实输入**：本轮证明了"窗口被创建、循环进入、进程按期限结束"，
   没有证明"有人在屏幕上看见它并按了它"；这需要人在屏幕前确认（第五次记录 §43.4 第 2 条同一件事）。
3. 支持矩阵 15 格（宿主 × profile，模式 2 产物）：本阶段没有做过任何面向输出 profile 的交叉构建。

**12.2 本阶段明确不声称的**

1. GUI 面：多根/资源树、依赖面板、Kit/profile/triple 选择、凭据选择器、向导窗口属 T04/T18/T26；
   本阶段交付的是它们背后的命令与数据路径。
2. 没有真实 UI 线程：T01.03 的"不阻塞 UI"是用"提交在 16.9µs 返回而任务仍在跑"证明的，帧率没有证据。
3. `native-file-dialog` 仍是上游缺口（§7、§9）；`url-handover` 仍是 `not-verified`（探针不得打开
   用户的浏览器）；真实 TLS/HTTP 传输属 T16.x/T20.x/T23.x。
4. 非 unix 分支（无进程组清理、`presence` 无证据）只有代码与文档，没有现场证据。
5. 性能、资源体积、未引用资源清理、撤销、`.rustage-deleted`/扫描记录/备份的清理仍挂在 T21/T09。
6. Rust 侧门禁（`cargo test`/`fmt`/`clippy`/两个探针）仍是**人工**门禁：`.github/workflows/docs.yml`
   只跑 Node；把 git 依赖拉取与 GUI profile 构建放进 CI 需要先决定探针退出码是否作为门禁。
7. 文档只在仓库内闭环：白皮书的"已具备"陈述依赖本记录与前两次记录的证据指针，没有独立的外部复核。

**12.3 本轮新引入、尚未被外部复核的**

1. `linux-native` feature 转发（§7）：它改变的是**构建形状**，默认关闭；谁在 CI/发布里用它、
   是否改成默认，是需要决策的事（§13.3）。
2. 探针改为子进程（§8）：多了一次 `rustage` 进程的启动开销（本机约 150ms 的会话 + 启动），
   因此 `--probe-host` 的总时长略有增加；超时上限写死为 20s（`SESSION_CHILD_LIMIT`）。

## 13. 本轮决策记录

1. **签收由本轮复核给出，并把边界写在文件里。** blue1/blue2 的「阶段完成签收」四条按 §10 的证据
   逐条给出结论，同时把 macOS/Windows 的 `blocked` 与 §12 的未覆盖写进签收下方的边界说明——签收
   不等于"所有格都有证据"。
2. **`--probe-apis` 的退出码改为 `Reported`（4）。** 同一个含义（"有发现要人读"）不保留两个数字；
   旧行为只被文档描述过，没有脚本依赖它（`docs/plan` 与 `CONTRIBUTING.md` 已同步）。
3. **Linux 原生后端做成默认关闭的 feature，不改依赖策略。** 依据：原则 #4（不把未决选项当既定决策）、
   #34（公共/构建接口的变更要有理由与迁移说明）。默认值改不改，是下一次决策。
4. **lint 债用"写明谁将来消费"而不是"删成员"解决。** 依据：那些成员的行为已经被用例断言（原则 #26
   禁止占位，但删掉已验证行为不是修法），且项目里 `contracts`/`host`/`project` 三个模块已有同样的
   先例与理由写法。
5. **工具链失败事实类型化，而不是在报告行上多写几个字。** 依据：原则 #35/#59（同一语义一份定义），
   以及原先三个消费者各自拼句子的实际漂移。
6. **删掉没有消费者的 `system_path_summary()`，不删 `SystemPaths` 类型。** 依据：原则 #26/#61（无消费者的
   代码不留存）与 #35（同一语义一份定义）——但 `SystemPaths` 与 `HostDirectories` 是分层关系，
   `HostDirectories::from_environment()` 建立在它之上，删类型会删掉在用的那一半。
7. **不 re-pin，只取证。** 依据：re-pin 会连带让 §9.1 的 11 条绕行失去理由，需要一轮专门的迁移与
   复核（含 `--probe-apis` 期望值、依赖策略决策、反馈文件闭合），不能塞进复核轮。
