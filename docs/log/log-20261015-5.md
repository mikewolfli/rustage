## 2. re-pin：`58012c05` → `8178d048`（从“编译不过”开始）

**现象**：在 macOS 上第一次 `cargo check`，编译**依赖本身**就失败：

```text
.../rust-widgets-.../58012c0/src/platform/macos/file_picker.rs:65:71:
    error[E0054]: cannot cast `i32` as `bool`
.../58012c0/src/platform/macos/file_picker.rs:68:65:
    error[E0054]: cannot cast `i32` as `bool`
```

`msg_send![panel, setCanChooseFiles: NO]` 的返回值被当作 `bool`，而 Objective-C 的 `BOOL` 是
`i32`。这是“只在 macOS 上才看得见”的一类缺陷——与第二次记录在 Windows 上抓到的三处同源：钉住的
修订只在它被验证过的平台上编译过。

**修法**：把依赖钉到本地 HEAD（= `origin/main`）的 `8178d048`。该修订已把三处调用改成
`let _: () = msg_send![…]`，正是这条缺陷的上游修复。改 `Cargo.toml` 的 `rev` 后 `cargo build`
**零错误、零警告**，依赖树（含 `wgpu`、`boa`）在 macOS 上编译通过。

**同步到计划的四处**（与第三次记录 §7 同一份清单）：`Cargo.lock` 由 `cargo build` 落定；
`src/probe/contract.rs` 的 `DEPENDENCY_REVISION`（漂移测试把它钉在锁文件上）；
[`decisions.md`/`.json`](../plan/decisions.md) U1 的“当前修订”；
[`capability-reference.md`/`.json`](../plan/capability-reference.md) 的协议版本 `P-DEP`；
以及 [`host-probe.json`](../plan/host-probe.json)、[`support-matrix.json`](../plan/support-matrix.json)
的 `dependency.revision`。历史记录（`log-*`）与资源出处记录（`resources/**`）**不改**：前者是证据、
后者记的是图标**收到时**的修订。

**为什么不保留双修订**：项目只承认一个“当前固定修订”（决策 U1）。macOS 要能构建，就必须有一个
在三个平台都能构建的修订；`8178d048` 是那个修订，且它就是本地工作树与 `origin/main` 的 HEAD。

## 3. T03.04：`project::save`

**交付物**（`src/project/save.rs`，新增模块；命令行 `--save`）。验收词是“注入磁盘满/权限/中断后原
内容可恢复”，用三个结构性事实满足，而不是靠小心：

1. **先准备、再写入、后提交。** 文本先写进目标**旁边**的临时文件，再 `rename` 覆盖目标。同目录
   `rename` 是原子的，读者只会看到整个旧文件或整个新文件；代码里**没有**先截断目标的分支，所以不
   存在“原文件已消失”的窗口。
2. **`execute` = `stage` 然后 `commit`，两步可分别停住。** 中断这一路因此是**可执行的**而不是被
   描述的：测试 `stage()` 之后不 `commit()`（`mem::forget`），断言目标字节不变、且临时文件仍在，
   并由 `Saving::stray(target)` 找回（崩溃留下的临时文件是可辨认的：以点开头、以目标名加 `.tmp`）。
3. **一批文件是一笔事务。** `Commit::plan` 先把每个文件**全部** `stage`，只有全部成功才逐个
   `commit`；改名途中失败则用“计划时读到的字节”把已落地的文件写回（`put_back`），并把写不回的
   逐条列出——半提交永远不会被报成干净完成。

**四个动词是一个实现的一处差异**：`Save` 写回原文件（**文件不在了就拒绝**——那是一个需要人决定的
删除，不是这次保存可以顺手重建的），`SaveAs` 写别处并让文档跟随，`CopyTo` 写别处且文档不动。

**命令行**：`--save <file> [<file>...] [--set-text <t>|--set-text-file <f>] [--save-as <p>|--save-copy <p>]
[--plan]`。一个文件走 [`Buffer`](../plan/blue3.md)（`--set-text` 先打进去），所以“保存的文本”就是
“有人打进去的文本”；多于一个文件是一批，按现状整批写回。

**新增用例**（`src/project/save.rs` 的测试模块，9 项 + §4 的 1 项）：保存经临时文件且不留残留；
目标已是该文本时不写；另存/副本的采纳差异；文件不在时拒绝；中断只留可找回的临时文件；放弃暂存；
只读目录下写入被拒且原文件完好（unix，root 下跳过并说明）；一批全提交；一批在改名中途失败时把
第一个写回。

## 4. T03.05（部分）：外部修改不静默覆盖脏缓冲

**这为什么是现在就该加的**：`save` 会读目标字节来判断“是否已经是这段文本”，但**它原本不比较
“目标是否还是缓冲读到的那个文件”**——也就是有人在我们读之后改了文件，保存会**默默覆盖**那次修改。
这正是 T03.05 验收词“外部修改不静默覆盖脏缓冲”要禁止的形状。

**改了什么**：

1. `src/project/document.rs`：`Buffer` 新增 `on_disk: Option<Vec<u8>>`——它是“这个缓冲最后与磁盘
   一致的那一刻的字节”（`Buffer::open` 读到的原始字节；由文本构造的缓冲为 `None`），以及访问器
   `on_disk()`。这正是项目文档写入器已有的 compare-and-swap，落到页面文档上。
2. `src/project/save.rs`：新增 `Saving::plan_guarded(root, document, text, verb, agreed)`。当
   `agreed` 与目标当前字节不同，返回 `Problem::Changed`，消息写明“没有写入，所以那次修改没有被静默
   覆盖（比较两者并选择保留哪一个——T03.05）”。
3. `src/app/run.rs`：`--save` 单文件路径改调 `plan_guarded`，并把 `buffer.on_disk()` 传进去；另存/
   副本不传（目标是**另一个**文件，文档自己的字节对它没有发言权）。

**用例**：`a_save_refuses_to_overwrite_a_change_somebody_else_made`——缓冲读到 `PAGE`，随后别人把
文件改成另一段；`plan_guarded` 返回 `Changed`、文件仍是别人改后的内容；同一计划**不带守卫**时正常
写入（说明守卫是调用方做的一个选择，不是保存本身的行为）。

**T03.05 尚未做**（不在本轮声称）：三方冲突的可视合并、只读状态、文件删除/重建的处置。§10 把它们
列为下一步；本轮只关闭了“静默覆盖”这一条。

## 5. 三处只有 macOS 才暴露的事实

### 5.1 cocoa 后端的有界会话不退出（**上游请求**）

`rustage --launch --exit-after-ms 300` 在 macOS 上 25 秒后仍在运行。日志说明了一切：

```text
INFO host::startup: backend cocoa initialised, gui mode NativeInteractive (+42 ms)
INFO host::startup: window 6000285942072475648 created 1280x800 (+43 ms)
INFO host::platform: entering the event loop for a bounded session (+43 ms)
INFO host::platform: session deadline 300ms reached; asked the loop to stop
                     (no loop had ticked yet; the request is recorded for the next loop) (+351 ms)
```

宿主把停止请求排进循环自己的队列（第三次记录 §6 改用的 `quit()` 接缝），但 cocoa 的事件循环**一次
帧回调都没发生**，排进去的请求永远不会被兑现。`--probe-host` 的 `startup-session` 因此是 `gap`
（“a separate process was still running after 20s and was stopped”）。已按
[`feedback-20261015.md` 第十节](../rw-feedback/feedback-20261015.md) 提为上游请求（让 cocoa 循环按
节拍耗尽已排队的主线程工作，或提供不依赖“某一帧真的到来”的结束接缝）。

### 5.2 FSEvents 把删除报成 `Modified`（**上游请求**）

`host::watch` 的用例 `a_deletion_is_observable_and_classified_as_the_backend_reports_it` 在 macOS 上
观测到删除被归为 `Modified`（Linux 的 inotify 归为 `Removed`）。所以第四次记录里“删除与改名可观察”
这句话**只在 inotify 一侧成立**。本轮做了两件事：(a) 把 `src/host/watch.rs` 的模块文档改成按后端
如实说明（哪些种类由哪个后端产生，不把 Linux 的答案写成所有平台的承诺，原则 #27）；(b) 用例按平台
分别断言——**每个平台**都断言“删除是可观察的、不被静默丢弃”，只有 Linux 断言“归为 `Removed`”，
并把原因写在断言旁（原则 #25/#62：不删有效用例，也不假装 OS 报了一个它没报的种类）。修复建议已写入
上游反馈（`change_kind_of` 的判决带上路径：被判为 `Modify` 但路径已不存在时映射为 `Removed`）。

### 5.3 两个主机探针并发死锁（**宿主/测试侧，已修**）

并行跑 `cargo test` 时，`host::readiness::tests::both_renderings_name_every_capability_and_stay_well_shaped`
会**挂住**（单线程 10.8s 全过，并行时该用例 `has been running for over 60 seconds`）。`ReadinessReport::run()`
会运行整套主机检查，其中有 OS 级单例（一个原生窗口会话 + 用户剪贴板）；macOS 上两次并发运行会在窗口
服务器上死锁。修法在**测试**里：`src/host/readiness.rs` 的测试模块加一个 `static FULL_REPORT: Mutex<()>`，
两个跑整份报告的用例各取一次锁——报告内容与先后无关，也不会有谁同时需要两份。修复后并行 `cargo test`
**522 passed; 0 failed; 5.63s**。

## 8. 决策记录

1. **re-pin 到 `8178d048`，而不是在宿主要一处绕行。** 依据：决策 U1 的升级流程；`58012c05` 在
   macOS 上连依赖都编译不过，而“三平台都能构建”是该修订必须满足的最低条件；`8178d048` 同时是本地
   工作树与 `origin/main` 的 HEAD，可复现。**这是本轮唯一一次 re-pin，且本身带证据**（编译通过、
   522 项用例全过、两个探针照常）。
2. **T03.04 用“临时文件 + 改名”，并把 `stage`/`commit` 做成公开的两步。** 依据：验收词要求“注入
   中断后原内容可恢复”，而“中断”的唯一诚实注法是**真的停在中间**（原则 #60：每项修复独立验证）。
3. **外部修改守卫做成调用方可选的 `plan_guarded`，不写进 `plan`。** 依据：principle #38（共享抽象
   须有实际收益）——另存/副本写的是**另一个**文件，文档自己的字节对它没有意义；守卫只对“写回原文件”
   成立，把它塞进通用路径会制造一个假的“处处适用”。
4. **FSEvents 的 `Modified` 不改宿主去猜。** 依据：原则 #45（默认值须诚实）——把 `Modify` 在宿主
   重解释成 `Removed` 会让宿主自己成为第二个种类来源（#35），而正确的落点在上游（`change_kind_of`
   已能看到路径）。宿主只把文档收窄到“后端报什么就带什么”。
5. **整报告测试加锁，而不是禁用它。** 依据：原则 #62（不删有效用例）——用例断言的是报告的形状，
   死锁是 macOS 上“两个一次性探针并发”的问题，锁是就地、最小、可解释的修法（报告内容不依赖先后）。
6. **历史记录与资源出处记录不改修订。** 依据：#25（每项结论附可复核证据）——一至四次记录是**在
   Linux 上**得到的证据，改写它们会让“哪台机器得出的结论”失真；`resources/**` 记的是图标收到时的
   修订，与当前固定修订是两件事。

   真实启动**和退出**”只成立前半句。`--probe-host` 的 macOS 列因此**尚未**从 `blocked` 改成 `probed`

5. **`--save` 无法从命令行演示 §4 的守卫**：命令是一次性的（读文件、写文件在同一进程里），
