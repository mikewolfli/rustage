## 2. T03.05：`project::conflict`

**交付物**（`src/project/conflict.rs`，新增）。验收词是“外部修改不静默覆盖脏缓冲”，本轮把它做成
**可决定的**，而不只是可拒绝的。三个版本按人的直觉命名：**base**（文档最后与文件一致时的字节）、
**mine**（缓冲现在的文本）、**theirs**（磁盘现在的内容）。`decide(base, mine, on_disk)` 给一个判词：

- `Unchanged` / `DocumentOnly` / `DiskOnly` / `BothAgree` / `Merged { text }` / `Conflicted { regions }`
  / `Gone` / `NotAFile`。`is_clean()` 与 `needs_a_decision()` 把“无需打扰”和“要人决定”分开。

**合并是规则不是启发式**：`merge` 是 **diff3**——两侧各自相对 base 的行级改动用最长公共子序列算出来，
碰到**不同 base 行**的改动都保留，只有碰到**同一批 base 行**的才成为 `Region`（region 里并排列出
双方那几行）。它**从不**替人选边：`Conflicted` 是报告，不是自动解决。

**只读与删除/重建**是状态而非冲突：`writability(path)` 用“打开文件写”问 OS（不是读那个只在不写入时
才置位的元数据位），文件不在是 `Verdict::Gone`，回来且内容不同是普通的 `Changed`。

**命令行**：`--conflict <page-document> [--base <file>] [--set-text <t>|--set-text-file <f>]...
[--root <dir>] [--accept] [--recreate]`。一次性命令无法演示“读到写之间被改”，所以 `--base` 让调用方
**重放**真实设计器经历的顺序（读、别人改文件、决定）；`--accept` 写回合并结果，`--recreate` 在文件
已删时写回文档文本。冲突**从不**被写出：报告即结论。

**用例**（`src/project/conflict.rs`，9 项）：未改动/仅磁盘改/仅文档改；不同行双向保留；同一行冲突列出
双方；双方改成同一文本则一致；两侧插入按序合并；删除即 `Gone`、替换即 `Changed`；可写与不可写；
只读文件带上 OS 原因。

## 3. T03.06：`project::recovery`

**交付物**（`src/project/recovery.rs`，新增）。验收词是“崩溃恢复版本/来源明确，用户可拒绝恢复”。三条
结构性决定：

1. **副本不在工程里。** 恢复副本写在调用方指定的目录（真实应用里是宿主的 state 目录），所以工程本身
   永远是“你保存的那个”，副本是“另外收着的内存里那一份”。
2. **副本自带出处。** 每份文件开头是一小段头部（格式标记、工程根、文档相对路径、会话、写入时间），
   启动恢复就是一个列表，每条都说得出自己从哪来。正文按**字节**复制——包括开头的空行，`split` 规则
   “跳过前导空白”会吃掉它，所以头部与正文以**第一个空行**为界。
3. **恢复是问题不是动作。** `Copy::standing()` 把副本与**现在**的文件比较（一致 / 唯一版本 / 不一致），
   `--restore` 打印它，`--discard` 是“不”：只删副本，**永不碰文档**。

**命令行**：`--recovery <store-dir> [--root <dir>] [--record <file>|--restore <file>|--discard <file>]
[--session <name>]`。

### 3.4 修掉一个真缺陷：时间戳分辨率

保留策略要“每文档留最新 N 份”，而副本的时间戳原本是**秒**。同一秒内写的多份副本 `written` 相同，
排序退回到目录遍历的任意顺序，于是“最新”可能是任意一份——切会话时尤其容易撞上。修法：`written`
改为**纳秒**（`as_nanos`），既保留无符号 u64 的宽度，又让同一秒内的写入可排序。模块文档与断言同步
更新（`written()` 的语义明确为“纳秒”）。

## 4. T03.07：`project::closing`

**交付物**（`src/project/closing.rs`，新增）。验收词是“取消关闭保持全部视图与任务一致”。做法是让
“什么都没发生”成为一个**值**：

- `Closing::close(self, decision) -> (Self, Outcome)` **按值**拿走状态再还回来；`Decision::Cancel`
  返回同一个状态与 `Outcome::Cancelled`，于是“取消保持了一切”是**两个值的相等**，不是一句承诺。
- `Decision::SaveAll` 先用保存路径（`Saving::plan_guarded`，即 T03.04 的原子写 + T03.05 的守卫）写
  每一份脏文档；**任何一次写失败，关闭就不发生**，`Outcome::Blocked` 也把状态还回来。已经写成的
  文档如实报为 `saved`（内容确实在盘上），其余列在 `unsaved`。
- **工作只在关闭真的发生时停下**：`stop_tasks` 在两个成功分支里调用，取消与失败都不动它。

**命令行**：`--close <file>... [--unsaved <document>=<buffer-file>]... [--task <name>]... [--root <dir>]
[--decision save-all|discard-all|cancel]`；不给 `--decision` 就只打印计划。

**用例**（`src/project/closing.rs`，5 项）：干净集无需决定；**取消后文档与任务逐项相等**；丢弃关闭并
停任务且不写盘；保存关闭写盘并停任务；一次写失败**中止关闭且任务仍在跑**。

## 5. T03.08：`project::retention` 与联合故障

**交付物**（`src/project/retention.rs`，新增）。验收词是“无未解决数据丢失，保留策略不自动删工程文件”。
策略写成一条关于**路径**的规则：

- 只有 **store 之内**的路径才会被裁；每个候选在**计划时**与**删除时**各校验一次 `starts_with(store)`，
  不在其中的拒绝并报告。store 在工程之外（T03.06），于是“永不删工程文件”由“只在 store 里删”蕴含。
- 每文档保留最新 `keep` 份（默认 5）。
- **“唯一版本”永不作为候选**：文档已不在盘上（`Standing::OnlyCopy`）时，那份副本是仅存的一版，任何
  计数都不裁它。这条把“无未解决数据丢失”从期望变成性质。

**联合故障测试**（`a_failed_save_a_kept_recovery_and_a_prune_lose_nothing`）：一份恢复副本存在、一次
保存因目录只读而失败、随后一次裁剪——断言工程文件与失败前**逐字节相同**，且仅存的那份副本仍在。

**命令行**：`--recovery <store-dir> --prune [--keep <n>] [--apply]`，计划与执行分两步，与项目其余
“先计划后应用”的约定一致。

## 8. 未覆盖项与边界

1. **三向合并是行级 diff3**，不做字符级或语法感知的合并；一个 JSON 对象的两个字段分别被改会落在一行
   上而报冲突（保守，不丢数据）。
2. **磁盘满**没有单独注入：任何写失败都走同一条回滚码路，本机用**权限拒绝**作为注入的失败（root 下
   该用例自动跳过并说明）。
3. **恢复副本的位置由宿主决定**：本机演示放在一个外部目录，真实应用用宿主的 state 目录（T02.06 的
   机器本地配置）。
4. **GUI 面属 T04/T26**：本条命令行的每项都在其「未覆盖项」里写明。
5. **真实崩溃**（进程被杀）不重放：T03.06 的“启动恢复”由 `for_project` 的扫描与 `standing` 判定证明，
   不是靠真的杀进程；跨进程的会话 id 由调用方给出（真实应用用宿主启动时生成的 id）。
