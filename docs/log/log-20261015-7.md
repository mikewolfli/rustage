## 2. T05.01：`app::command` 类型化命令注册表

**交付物**（`src/app/command.rs`，新增）。验收词是“未授权/无效参数无法绕过菜单调用执行”。关键词是
**绕过**，所以用类型堵死，而不是靠自觉：

- **命令是值，不是字符串分支。** `Command` 带上 id（`CommandId`，严格 `命名空间.动作`）、标题、分类、
  类型化 `Param` 列表、它拥有的 `EffectClass`、它的改动落在哪个撤销域（`Undo`）、它作为哪个任务运行、
  是否要求工程被信任、它在哪个焦点可用、以及它是否被某个正在运行的任务阻塞。`Registry::register`
  **拒绝重复 ID**：两个命令同名会让“运行的是哪一个”取决于注册顺序。
- **只有一道门。** `Registry::resolve(&Call, &Context) -> Result<Invocation, Refusal>` 把菜单项、快捷键
  或命令行产出的原始 `Call` 变成 `Invocation`，而 `Invocation` **不能以任何别的方式构造**（字段私有、
  无公开构造器）。于是持有一个 `Invocation` 就是握有证据：该命令存在、此上下文允许、效果已授权、每个
  参数都解析成功——**没有它就没有可运行的东西**。这正是“菜单会检查”和“别处跑不了”的区别。
- **四种拒绝各自成一种失败。** `Unknown`（无此命令）、`Disabled`（焦点/信任/任务忙）、
  `Missing`/`BadArgument`（参数缺/错）、`Unauthorized`（效果未授权）。禁用与未授权是两件事：前者是
  “此处此刻不行”，后者是“不是你”——路线图要的正是这组区分。检查顺序也按人们想要的报告顺序：先问是
  否已知、再问是否可用、再问是否授权，最后才读参数。
- 复用 `contracts::permission::EffectClass`（`command`/`file-write`/`network`/`deploy`），不另造第二套效果词表（#35）。

**命令行**：`--command [<id>] [--arg k=v]... [--focus <area>] [--trust] [--authorize <effect>]...
[--running <task>]...`。无 id 列出全部命令。

**用例**（10 项）：id 形状；重复 ID 被拒；效果未授权被拒且点名效果；未信任工程不能跑需信任的命令；
**参数非法/缺失/未知在运行前被拒**；焦点不符是 `Disabled` 而非 `Unknown`；任务忙时禁用；`Invocation`
携带元数据与解析后的参数；`why_not` 可查原因；内置命令 id 均可解析。

## 3. T05.02：`app::menu` 菜单树

**交付物**（`src/app/menu.rs`，新增）。验收词是“每已实现叶项绑定唯一命令 ID”。三种错配都可检查，
且判据来自**注册表**而不是第二份清单：

- `Item::Command` 的 id 必须是注册表认识的（`Registry::why_not_exists` 回答），否则报“菜单会显示一个
  什么也不做的项”。
- **两个叶项不得共用同一个命令 ID**：菜单项是一个**位置**，别名应当是拥有自己 id 的第二个 `Command`，
  共用 id 会让“这是哪一项”变得暧昧。
- `Item::Planned`（本 build 未实现、写明将来由哪个任务给命令）**不得**命名一个已注册的命令 ID——那是
  同一错配的另一方向：菜单会把一个能用的命令藏在“敬请期待”后面。

刻意**不**在这里做的：平台菜单适配（把树渲染成 `NSMenu`/GTK/Win32 菜单是平台后端的活，树是它们共同
渲染的平台无关之物）。

**命令行**：`--menu` 打印树与检查结果；有错配则退出码 4。

**用例**（7 项）：内置树全部通过检查且确有绑定；未知命令 ID 是问题；两个叶项共用 id 是问题；`Planned`
指向已注册命令是问题；树按路径报告叶项（含子菜单）；标题非空且 `Planned` 带任务；菜单中的 id 与注册表
同形。

## 4. T05.03：`app::shortcuts` 快捷键

**交付物**（`src/app/shortcuts.rs`，新增）。验收词是“输入法/文本输入不被误触发全局命令”。它是一条关于
**键盘归属**的规则，放在判断的最前面：

- **裸字符属于文本。** 当文本域拿到键盘时，一个不带 `Ctrl`/`Alt`/`Cmd` 的字符键是
  `Resolution::Suppressed`——它进文本域，不管全局绑定写了什么。`Ctrl+S` 仍然保存（修饰键就是“我要的是
  命令，不是这个字母”）。**输入法组字期间一律抑制**，因为那串键是 IME 的，不是宿主的。
- **弦键是序列，未完成即 pending。** `Ctrl+K Ctrl+S` 在第一个键后是 `Pending`、第二个键后触发；接不上
  任何弦键的那个键把 pending 丢掉并单独解析，所以打错的弦键不会吞掉下一条命令。
- **冲突是报告，不是静默排序。** 同弦键、作用域可能同时生效的两条绑定是 `Conflict`，`Keymap::add`
  拒绝并点名两者。唯一允许的重叠是 `Global` 与更窄作用域之间：那里**窄者胜**，且写明白，而不是被发现。
- **覆盖是数据且可往返。** `export` 写 `chord = command (scope)` 行，`import` 读回；一条坏行**整份拒绝**
  并报行号，因为半导入的键盘不是谁要的。

**命令行**：`--keys [--press <chord>] [--mode <m>] [--panel <p>] [--text-field] [--composing]`。

**用例**（11 项）：裸字符进文本域而 `Ctrl+S` 仍是命令；大写字母是文本、组字期间一切都抑制；弦键
pending→触发、坏第二键不吞命令；面板作用域需其面板、全局作用域不需；窄作用域可有意覆盖全局；同特异性
冲突被报且未加入；覆盖往返导出/导入一致；坏行整份拒绝并报行号；弦键与键语法严格；可反查“哪个键跑这个
命令”；默认键表每条都能解析且无冲突。
