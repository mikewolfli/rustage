## 2. T05.04：`app::palette` 命令面板

**交付物**（`src/app/palette.rs`，新增）。验收词是“禁用原因可查，命令可从键盘发现”。两者都来自“面板
建在注册表之上，而不是另存一份会漂移的清单”：

- **每一命中都是注册表命令，带着注册表自己的判词。** `search` 对每个结果问 `Registry::why_not`，
  于是不能运行的项说得出原因（与菜单 T05.02 会是同一句话），能运行的项没有原因。给一个项“变灰而不说
  为什么”正是本任务禁止的形状。
- **模糊但可预测。** `score` 是子序列匹配（对 id、标题、分类三者取最高分），奖励连续与词首；它是文本
  的纯函数，同一查询给同一排序，手感学得会。子序列都不匹配的查询返回**空**，而不是返回全部。
- **最近使用是助推不是过滤。** `Recents` 记录跑过的命令并把它提前，但从未跑过的命令仍然找得到——把
  没见过的命令藏起来会让新功能无法被发现。
- **补全就是命令自己的参数。** `help_for` 返回标题、帮助行与类型化参数（含 `Choice` 的取值），取自注册表
  条目，所以面板不会给出命令并不接受的参数。

**命令行**：`--palette [<query>] [--help-for <id>] [--focus <a>] [--trust] [--authorize <e>]...
[--running <t>]... [--recent <id>]...`。

**用例**（9 项）：查询命中且紧匹配在前；禁用的命令出现并带原因、可用的没有；空查询列出全部（新命令
可发现）；最近使用提前但不隐藏其他；`Recents` 有上限且重复项提前；打分偏好连续与词首；无匹配不显示；
帮助给出命令自己的参数与取值；分类来自注册表且有序列出。

## 3. T04.01：`app::workbench` 工作台

**交付物**（`src/app/workbench.rs`，新增）。验收词是“活动工程/目标/文档身份明确”。用“身份只有一处、
标题由它派生”把“明确”变成可检查：

- **标题由身份派生。** `Workbench::title` 由当前文档、工程、目标算出，所以标题不可能说一套而状态说另一套
  ——没有第二份可漂移的副本。
- **缺失的身份就是缺失，不补。** 没有文档时标题写“Welcome”，不写空文件名、也不写“上一个恰好打开过的
  文档”。工程与目标同样：缺席即缺席，状态栏如实写 `(none)`。
- **脏标记是文档自己的状态。** `mark_dirty` 由改文本的人调用，保存或丢弃时清除；标题以 `•` 表示它，
  别的任何地方都不表示。
- **区域随模式。** `regions()` 回答某模式显示主窗口的哪些区域，模式切换因此是改一个值、布局随之而来，
  而不是每个消费方各自定义“代码视图里有什么”。模式为路线图 §2.1 的七个中本 build 已展示的六个
  （welcome/design/code/debug/test/release）。

**用例**（8 项）：标题同时点名文档/工程/目标；脏标记跟随文档状态（含关闭即遗忘）；缺席身份不被编造
（标题与状态栏都写 `(none)`）；工程目标设定后可见；消息只在有时出现；区域随模式；每个模式有名字且报告
说明当前是哪个；切换模式不改动已打开的东西。

## 4. T04.02：`app::panels` 面板

**交付物**（`src/app/panels.rs`，新增）。验收词是“已接入面板可关闭恢复；未实现服务不显示假面板”。
后半句需要规则而非小心，因为诱人的做法是画一个空面板叫“尚未加载”：

- **面板声明它需要的服务。** `PanelSpec::service` 命名它，`Panels::visible` **不会**返回服务不在可用集合
  里的面板——不是变灰、不是空框，而是**不显示**。
- **显隐是布局状态，布局状态被记住。** `hide` 记住尺寸与焦点，`show` 恢复之；这就是“关闭并恢复”，也是
  “停靠回来的宽度还是原来那个”与“回来时变成随便一个宽度”的区别。
- **未知面板被拒而不是被创建。** 显示一个从未注册的面板是报错并点名 id：能从字符串凭空造出面板的宿主
  会让“有哪些面板”无法回答。
- **布局不带句柄。** 面板是 id 加描述；停靠、尺寸、焦点都是值，于是布局能写进文件再读回而不携带窗口
  指针或进程身份——正是 F04 任务表顶部的规则。

**命令行**：`--workbench ... [--service <s>]... [--show <p>]... [--hide <p>]... [--focus <p>]
[--resize <p>=<n>]`（与 T04.01 同一个命令）。

**用例**（8 项）：重复 id 被拒；缺服务的面板完全不出现在 available/visible，且列在 unavailable；隐藏再
显示恢复尺寸与焦点；未知面板被拒（四种操作都不创建）；隐藏未显示的面板不算错、重复显示无副作用；布局
只有 id 与值；内置面板保留 id 与默认值但只显示可用的；每个停靠有名字且报告点名每个面板。

## 5. T05.07：`app::operations` 批操作；T05.08：`app::audit` 命令清单审计

### 5.2 T04.03：`app::tabs` 文档标签；T05.05：`app::focus` 焦点路由与上下文菜单

**交付物**（`src/app/operations.rs`，新增）。验收词是“多选不适用项不静默跳过”。关键词是**静默**，
所以结构上让静默不可能：

- **预览先给每个被选项分类。** `BatchPreview` 把每个项分为“适用”或“不适用并带上原因”，于是一个人
  看到的不是“处理了 5 个”而是“4 个适用、1 个因……不适用”。想跳过某项的操作不可能不让原因出现在预览里。
- **跳过是一个决定，不是默认。** 选择里有不适用项时 `Choice::ApplyAll` 被**拒绝**并点名它们：要往前走
  只能选 `Choice::ApplyNone`——跳过在那里变成故意的。这正是验收词的全部。
- **历史也记下跳过。** `History` 每次操作同时记 `applied` 与 `skipped`，所以以后“这个为什么没做”能从
  记录回答，而不是凭记忆。取消的操作**不入历史**（它不是一次操作）。
- **权限先解释再检查。** `Operation::explain` 说明它有哪些外部效果、是否已授权；`apply` 在未授权时用
  这句解释拒绝，而不是一句“denied”。

**命令行**：`--operation <name> [--note <t>] [--effect <e>]... [--select <id>]...
[--inapplicable <id>=<reason>]... [--authorize <e>]... [--choice apply-all|apply-none|cancel]`。

**用例**（9 项）：预览点名每项与不适用原因；`apply-all` 遭遇不适用项被拒（不静默跳过）；`apply-none`
故意跳过且结果记录它；干净选择一次到位；未授权效果用解释拒绝且预览里已可见；取消不改动且不入历史；
历史保留跳过（可按操作查询）；历史有上限且最新在前；无效果的操作说“只动文档”而不是看着已授权。

### 5.1 T05.08：`app::audit` 命令清单审计

**交付物**（`src/app/audit.rs`，新增）。验收词是“无悬空已启用菜单；新域接入时增量重验”：

- **`audit` 走遍每一处“点名命令”的地方并问注册表。** 菜单叶项、快捷键绑定（以及 T05.04 面板经由
  注册表）都点名 id；注册表不认识的 id 就是**悬空引用**，并连位置一起报出。一个被画成可用、却什么
  也不运行的菜单项，正是这个检查禁止的形状。
- **它是全清单的，所以新域接入即被重验。** 没有“每个域一个开关”要记：新增一个命令/菜单组/快捷键就是
  往同一次遍历里加行，下次运行就覆盖它们。这就是“增量重验”在清单小到能一次走完时的含义。
- **可达性只报告不强制。** 既不在菜单、也无快捷键的已注册命令是 `unreachable`（提示而非失败）：只从
  命令面板可达是合法的，而面板搜索的正是注册表本身。
- **三个来源各有一个所有者**（`app::command`/`app::menu`/`app::shortcuts`），本模块**不持有自己的表**，
  所以它不会变成“命令的第二处定义”。

它当场找到了一个真错配：菜单把 `view.palette` 标为 `Planned`（T05.04 尚未做），而 T05.04 已经把它**实现**
并注册了——子任务 5.2 的规则把“把能用的命令标成未实现”报了出来，已改正为普通叶项；同时把键表里被绑定
但未注册的五个命令（`file.save-as`/`view.palette`/`keys.show`/`panel.close`/`tree.activate`）正式注册。

**命令行**：`--audit`。

**用例**（5 项）：内置清单无悬空；菜单叶项指未注册命令被报（含菜单名）；快捷键指未注册命令被报；
不可达命令是提示而非问题；新增一个域（新菜单组）经同一次遍历被重验。

### 5.3 T04.03：`app::tabs` 文档标签

**交付物**（`src/app/tabs.rs`，新增）。验收词是“关闭视图与关闭文档区别正确”，是一条关于**身份**的区分：

- **标签是视图，文档是它显示的东西。** `close_view` 关掉一个标签——文档在别处仍然开着，它的脏文本
  不被碰；`close_document` 关掉一个文档的**每一个**视图并回报有几个。混用两者的调用方要么关掉一个
  窗口就丢掉文档，要么以为自己关了一个文档却还留着它的视图。
- **打开先是预览，钉住才永久。** `preview` 开在预览标签里，替换现有预览标签（这正是单击树里下一个文件
  的行为）；`pin` 使其永久。**只有在替换会关掉一个“有未保存改动、且只有这一个视图”的文档时**才不平
  ——那是一条数据丢失路径。第二条视图必须显式用 `another_view` 要。
- **关闭集合是以起点命名的集合。** `close_others`/`close_to_the_right` 都保留被问及的那个标签。
- **溢出是一张表，不是一次丢失。** 超过条带上限的标签进入 `overflow` 而非被丢弃。

**命令行**：`--tabs [--limit <n>] <op>...`，op 形如 `preview:pages/a.json`、`close-view:0`、`move:0:2`。
**用例**（9 项）：关视图留下文档、关文档关掉所有视图（含无视图时不报错）；预览被下一个预览替换、
钉住不被替换、不替换脏文档的唯一视图；已打开则激活而不重复；重排后活动标签跟随；关闭集合保留被问及的
标签；溢出不丢失；非法索引被拒；关掉活动标签后活动指针仍指向存在的标签。

### 5.4 T05.05：`app::focus` 焦点路由、上下文菜单与工具栏

**交付物**（`src/app/focus.rs`，新增）。验收词是“同命令各入口行为一致，无重复执行”：

- **`press` 只解析一次，只返回一个 `Route`。** 键表决定是哪个命令（T05.03），注册表决定它能不能跑
  （T05.01），结果是一个值：`Ran`/`Refused`/`Suppressed`/`Pending`/`Ignored`。被拒的命令**不向下穿**
  （键已被占用），所以一次按键不可能跑两件事。
- **上下文菜单与工具栏是同一个问题的三个打印处。** `menu_entries` 与 `toolbar_entries` 都对每个命令问
  `Registry::why_not`，所以菜单栏里被置灰的项在工具栏与右键菜单里同样置灰、同样台词——三者不可能漂移。
- **焦点是一个值、是路线的输入，不是第二张注册表。** `Target` 说明键盘在哪；它派生场景（T05.03）与
  上下文（T05.01），“画布有焦点”因此经由已经决定可用性的那一条路起作用。

**命令行**：`--focus <target> [--mode <m>] [--press <chord>] [--menu <title>] [--trust]
[--authorize <e>]...`。
**用例**（8 项）：绑定的键只跑一个命令并占用该键；命令不可用时被拒且仍占用；编辑器里裸字符被抑制、
未绑定的键为 `Ignored`；半键入的弦键为 `Pending` 且占用；菜单/工具栏/上下文菜单对同一命令一致（含
相同原因）；上下文菜单保留禁用项的原因而不丢弃；目标决定场景与裸键含义；工具栏里不存在的命令说得出原因。
