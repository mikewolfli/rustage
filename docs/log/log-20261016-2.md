## 3. T09.01：控件能力适配、分类/搜索/收藏、schema 与限制说明

**交付物**（`src/app/widget_catalog.rs`，新增）。验收词是“**名称来自契约，不支持项有原因**”。两句都是“不要发明”，
于是模块什么都不发明：

- **每个名称都是契约名称。** `WidgetDescriptor` 带契约给的 id 与显示名；目录只索引它们，从不合成。查询一个契约
  没有描述的控件答空，而不是看起来合理的条目。
- **不支持的控件说明原因。** `Support` 是 `Supported` 或带原因的 `Unsupported`；`Catalog::reason` 答它——
  与 T05.04 命令面板同一形状，灰掉的控件因此可解释。
- **契约表达不了的东西是列出来的，不是丢掉的。** `WidgetDescriptor::limits` 带没有 schema 的属性及说明，
  于是“不提供”不会被误读为“不存在”。
- **搜索是同一条模糊规则。** `Catalog::search` 复用 `quick_open::fuzzy_score`（对 id/名称/类别），
  收藏只提升、不隐藏其余。

**命令符**：`--catalog <op>...`（`widget:<id>:<name>:<category>`、`unsupported:<id>:<reason>`、
`property:<id>:<name>:<type>[:<default>]`、`limit:<id>:<note>`、`search:<query>`、`category:<name>`、
`favorite:<id>`/`unfavorite:<id>`、`schema:<id>`、`show`）。

**用例**（`app::widget_catalog` 7 项 + CLI 解析 1 项）：名称来自契约（查询不存在的控件为空）；不支持项有原因、
支持项无原因；schema 即契约属性；限制列出不丢；搜索提升收藏但保留其余；类别分组；支持的 `reason` 可查询。

### 3.1 由测试当场发现的缺陷

**借用/导入（编译期）：** ① `descriptor.unsupported(...)` 对 `&mut` 后的值取值移动，改为 `descriptor.clone().unsupported(...)`；
② 命令行 `favorite` 分支首版用 `Catalog::search("")` 重建描述符列表（会打乱顺序且丢失收藏），改为在循环外维护

## 4. T09.02：NodeId 到渲染实例/命中/选择映射与生命周期

**交付物**（`src/app/scene.rs`，新增）。验收词是“**删除/重建后不引用旧实例**”。一个比它命名的实例活得久的句柄
正是该行描述的 bug，于是模块让句柄自证：

- **句柄带着它被造时的世代。** `Handle` 是 `NodeId` 加一个 generation；`Scene::resolve` 对已消失的节点答
  `Stale::Removed`、对已重建的答 `Stale::Rebuilt`，所以旧句柄不会意外读到新实例。
- **重建是新世代，不是就地修改。** `Scene::rebuild` 递增世代，正是旧句柄变 Stale 的原因。
- **命中测试就是绘制顺序。** `Scene::hit` 答包含该点的最上层节点，`raise` 改变该顺序。
- **选择是一组 node id。** `resolve_selection` 映射为当前有效句柄，并把已消失的报出来（而非静默丢弃）。

几何是普通矩形；真实后端的命中是库的，本模块是对象树/画布/检查器**共享**的那一份“一个点指哪个节点”。

**命令符**：`--scene <op>...`（`add:<node>:<x>,<y>,<w>,<h>`、`rebuild:`、`remove:<node>`、`hit:<x>,<y>`、
`resolve:<node>:<generation>`、`raise:<node>`、`show`）。

**用例**（`app::scene` 6 项 + CLI 解析 1 项）：重建后旧句柄变 Stale（不被读为新实例）；删除后句柄 Stale；
命中按绘制顺序且 `raise` 改变；选择映射到有效句柄并报出缺失；矩形半开；句柄读自己的世代。

### 4.1 由测试当场发现的缺陷

**命名冲突与路径导入（编译期）：** ① 模块内 `parse_node` 与 T08.01 命令行的同名函数冲突，改名为 `parse_scene_node`；
② `--scene` 函数里 `Rect`/`NodeId` 导入未用，改为按需引用。实现与语义无误。

## 5. T09.03：单选/多选/框选、父子导航、树/画布联动

**交付物**（`src/app/selection.rs`，新增；并扩展 `src/app/scene.rs` 与 `--scene` 命令）。验收词是“**重叠的节点可选，
隐藏不被误认为锁定**”。第二半最容易写错，于是模块直接用 [`Scene`] 自己已有的区分，而不是再发明一套：

- **选择是树与画布共享的一个集合。** `Selection` 只存 node id；两个界面读同一个集合，所以“树与画布一致”是结构
  性的，而不是靠同步维持。
- **隐藏与锁定不同，且都属于场景。** 隐藏的节点不被绘制（`Scene::hit` 自然命中不到），锁定的节点被绘制但不可选；
  `Selection::click` 拒绝锁定节点、`Selection::marquee` 从不框选它。清除一个标志绝不清除另一个。
- **重叠节点都能选到。** `Selection::click` 取最上层；`Selection::cycle` 在同一地点向下走，于是被大节点盖住的小节点
  仍可达。
- **导航就是场景的层级。** `Selection::parent_of`/`children_of` 读场景的 parent 链接，所以树与画布不会对“谁是谁的子”
  有分歧。

这次为 `scene.rs` 补的**结构决策**（同一验收词的另一半所需）：`parent`/`children`/`set_parent` 让场景有层级；
`hidden`/`locked` 与 `is_hidden`/`is_locked`/`is_visible`/`is_selectable` 让两个标志正交且**沿祖先生效**（`is_visible` 走
父链）；`Rect::intersects`、`Scene::hit`（跳过不可选者）、`Scene::within` 供框选使用。

**命令符**：扩展 `--scene <op>...`：`parent:<node>:<parent|->`、`hide`/`unhide:<node>`、`lock`/`unlock:<node>`、
`click:<x>,<y>`、`cycle:<x>,<y>`、`marquee:<x>,<y>,<w>,<h>`、`select-all`、`prune`、`show`。

**用例**（`app::selection` 8 项 + `app::scene` 扩充项）：重叠节点靠 `cycle` 都能选到；隐藏与锁定不被混淆；框选命中
全部重叠者；锁定节点永不被框选；导航读场景层级；子树拾取取全部后代；`prune` 丢弃变得不可选的节点。

### 5.1 由测试当场发现的缺陷

**我的断言写错了（测试发现，改测试而非改代码）：** `hidden_and_locked_are_not_confused` 首版断言“**隐藏父节点的子节点仍可选**”。
正确答案相反：`is_visible` 走祖先链，隐藏父节点下的子节点**不可见也不可选**——那正是“隐藏”应否沿层级生效的问题，实现给
的是沿层级生效这一更有用的一半。于是修正的是**测试的期望**，不是实现。此改动如实记于此，不留为静默。

## 6. T09.04：对象树结构编辑（插入/删除/复制/改名/重排/改父）

**交付物**（`src/app/structure.rs`，新增）。验收词是“**无环且无重复 id，删除被引用节点时告警**”。三条不变式，
每条都只在**唯一可能破它的地方**守住：

- **id 唯一靠分配器实现，而非事后检查。** `Tree::insert` 从 [`IdAllocator`] 取 id，它从不重发，于是“重复 id”不是
  树能到达的状态——不是每次插入后去检查，而是让它不可能发生。
- **成环在连线之前就被拒。** `Tree::reparent` 拒绝“已经在节点自己子树内”的父节点，于是树始终是树（`is_acyclic` 仍
  作为对外可查的事实）。
- **删除报告谁引用了它。** `Tree::delete` 返回 `DeleteReport`，其 `references` 列出所有指向被删者的节点（作为
  `(引用者, 被删者)`），于是“这会断一条绑定”是**返回给调用者的事实**，而不是事后才发现。
- **子节点必须是父节点允许的种类。** `Kind::allows_child` 是唯一条嵌套规则，在插入与改父两处都查，非法嵌套被拒且
  点名两个种类。

**命令符**：`--structure <op>...`（`root:<kind>:<name>`、`insert:<parent>:<kind>:<name>`、`delete:<node>`、
`copy:<node>`、`rename:<node>:<name>`、`reorder:<node>:<index>`、`reparent:<node>:<parent|->`、`reference:<from>:<to>`、
`show`）。

**用例**（`app::structure` 11 项 + CLI 解析 1 项）：子节点种类必须被父节点允许；id 因分配器不重发而唯一；复制子树
取新 id 且保结构；成环的改父被拒；删除报出每条引用；重排在兄弟间移动；改名只改名字；种类名往返。

值返回），`clippy` 报 unused import；删去 `Kind`。实现与语义无误，无逻辑缺陷。

## 7. T09.05：平移/缩放/适合/实际尺寸、网格/标尺/参考线

**交付物**（`src/app/viewport.rs`，新增）。验收词是“**设计辅助不污染生成模型**”。辅助是设计师为工作而打开的
一切——平移、缩放、网格、标尺刻度、对齐参考线——没有一样属于文档。模块靠结构而非纪律做到：

- **视口是模型旁边的值，不在模型里。** `Viewport` 持有 `Transform`/`Grid`/`Rulers`/`Guides`；方法只读模型、只答
  屏幕空间描述，所以没有从辅助回到节点的路径。
- **适合与实际尺寸只动变换。** `Transform::fit` 与 `Transform::actual_size` 只改平移与缩放，矩形原地不动——
  这正是“不污染”对两条最容易被误以为无害的命令的含义。
- **吸附是候选，不是编辑。** `Grid::snap` 答“点会落在网格哪里”；被取消的拖拽因此不留痕迹，因为什么都没写。
- **辅助是叠加层。** `Viewport::overlay` 返回 `Overlay`（网格线、刻度、参考线），画布把它画在模型**旁边**，
  于是模型渲染与辅助开关无关。
- **辅助开销随可见量走。** 当网格间距在屏幕上太小以致不可读时，`overlay` 省略网格，于是拉远不会让设计器画出
  无界多的线（原则 23）。

**命令符**：`--viewport <op>...`（`transform:<px>,<py>,<zoom>`、`pan:<dx>,<dy>`、`zoom:<f>`、
`zoom-at:<f>:<x>,<y>`、`fit:<x>,<y>,<w>,<h>:<vw>,<vh>[:<margin>]`、`actual-size:<vw>,<vh>`、`spacing:<s>`、
`ruler:<step>`、`grid:<on|off>`、`snap:<on|off>` 或 `snap:<x>,<y>`、`align:<rect>:<rect>[:<tol>]`、
`to-screen:<x>,<y>`、`to-model:<x>,<y>`、`overlay:<vw>,<vh>`、`state`、`show`）。

**用例**（`app::viewport` 14 项 + CLI 解析 1 项）：变换经屏幕往返；`fit` 居中且落在视口内；`actual_size` 保持中心
且设为 100%；绕锚点缩放该点不动；缩放两端夹紧（含 NaN）；吸附是候选且不写；网格线跨边界；刻度落在步长上；
共享边/中心出现参考线；两条参考线重复只报一次；对不齐则无参考线；网格不可读时省略；叠加层同时带网格/刻度/参考线；
**辅助不污染模型**（场景 `render()` 前后一致）。

## 8. T09.06：拖拽候选、插入位置/容器预览、取消与批事务

**交付物**（`src/app/drag.rs`，新增；并扩展 `src/app/structure.rs` 与 `src/contracts/identity.rs`）。验收词是“**无效落点不留下
半移动，单次撤销恢复**”。模块把“决定”与“写入”分开，两半都由此成立：

- **拖拽只决定，不写入。** `Drag` 保存被拖节点与当前瞄准点；`Drag::begin`/`aim` 不改模型，于是被取消的拖拽**靠构造**不留
  痕迹，而不是靠事后清理。
- **释放只报三种结果之一。** `Drag::release` 答 `Drop::Cancelled`、`Drop::Refused`（带原因）或 `Drop::Move`；只有最后一种
  是写入，所以“无效落点不留下半移动”就是“拒绝不是移动”这个事实。
- **候选与移动共用同一条规则。** `Drag::candidates` 与 `Drag::release` 都问 `Tree::can_reparent_at`，于是拖拽给出的容器
  就是移动接受的容器（不会出现“能拖却不能放”）。
- **批次先施加于副本、整体采纳。** `Design::apply` 把每条编辑施于克隆，只有全部成功才替换树，于是中途被拒的批次什么都不改。
- **一次撤销就是一次事务。** `Design::undo` 恢复的是成功批次之前那棵树，所以一整次拖拽——或一整次粘贴——一步就能取回。

**为复用而扩展的既有模块：**

- `contracts/identity.rs`：`IdAllocator` 补 `Clone`/`PartialEq`/`Eq`（快照要连分配器一起取，撤销才不会重发 id）。

**命令符**：`--drag <op>...`（`root:<kind>:<name>`、`insert:<parent>:<kind>:<name>`、`begin:<node>`、`candidates`、

## 9. T09.07：设计隐藏/锁定/层级状态、对象过滤/定位与多页标签

**交付物**（`src/app/objects.rs`，新增）。验收词是“**隐藏不改变发布可见性**”。这里有两种“可见性”，且它们不是一回事：
节点被 **hidden** 是人在设计时把它拨开；节点被 **published** 是文档说生成的应用要画它。模块保留前者、只读后者，
两者不会被混同：

- **设计状态是自己的映射，不持有文档。** `Objects` 把 node id 映射到 `State`，**不**保存任何 `Node`，于是没有任何字段能让
  一次 hide 通到发布值。隐藏对文档不可见是**靠构造**，而不是靠自觉。
- **发布可见性从文档读。** `published(node)` 答模型怎么说（`visible` 属性，缺省为绘制），那是生成应用的问题，不是设计师的。
- **绘制顺序只有一条。** `Objects::order` 是画布与对象树共享的绘制顺序，于是 raise 一个节点在两个界面上都移动。
- **过滤同时问文档与设计状态。** `Filter` 按种类、标签与设计状态匹配节点，`Objects::filter` 只答 id、不改任何东西，
  于是“找出隐藏的 image”是一次读。
- **页面就是标签，且总有一个。** `Pages` 保存打开的页与活动页；关闭最后一页被拒绝，而不是让设计师无物可看。

**命令符**：`--objects <op>...`（`node:<id>:<kind>[:visible=<bool>][:name=<text>]`、`hide`/`unhide:<id>`、
`lock`/`unlock:<id>`、`raise`/`lower:<id>`、`published:<id>`、`visible:<id>`、`filter-text:<text>`、`filter-kind:<kind>`、
`filter-state:<hidden|shown|locked|unlocked>`、`filter-clear`、`filter`、`locate:<text>`、`page:<id>:<name>:<root>`、
`activate:<id>`、`close-page:<id>`、`rename-page:<id>:<name>`、`state`、`show`）。

**用例**（`app::objects` 11 项 + CLI 解析 1 项）：隐藏不改变发布可见性（文档逐字不变）；无 `visible` 属性即绘制；
隐藏与锁定相互独立；raise/lower 改变绘制顺序且顶端不能再升；过滤按种类/标签/状态匹配；定位按标签模糊匹配；
最后一页不能关闭；关闭活动页移到仍存在的页；重复页被拒；激活未打开的页被拒且不改活动页；改名保留身份与 root。

## 11. T10.01：布局适配与计算结果/诊断展示、约束来源

**交付物**（`src/app/layout_plan.rs`，新增）。验收词是“**预览与生成复用同语义，不复制算法**”。让这句话为真的唯一办法
是把算法只留在一个地方、谁都不再拥有一份副本：

- **算法是引擎的，且只是引擎的。** `Engine` 是库实现的缝；本模块自己不计算任何盒子，于是没有第二份会漂移的算法。

  从不改答案。
- **结果自带解释。** 布局要么给出 `Computed` 盒子，要么给出一列 `Diagnostic`，每条点名节点、并在能时附上 `Source`
  （节点/属性/来源），于是“这个盒子为什么这样”可回答、可跳转。
- **约束记得自己从哪来。** `Origin` 区分显式/继承/默认，属性面板因此能显示来源，而不是一个没有历史的取值。

**命令符**：`--layout-plan <op>...`（`available:<node>:<w>,<h>`、`constraint:<node>:<property>:<origin>`、
`box:<node>:<x>,<y>,<w>,<h>`、`run:<preview|generation>`、`source:<node>`、`state`、`show`）。
命令行的引擎是无头版本里对库的**明确替身**：它只回答 `box:` 给的盒子、对没给盒子的节点给诊断（真正的库引擎在 T10.08 的库探针）。

## 12. T10.02：容器布局选择/切换/解除、子节点约束迁移

**交付物**（`src/app/layout_choice.rs`，新增）。验收词是“**不能表达的转换拒绝且说明损失**”。布局种类是一种**词汇表**
——它能容纳哪些约束——所以切换就是问每个子节点的约束在新词汇里有没有词：

- **每种布局一次性声明自己能表达什么。** `LayoutKind::expresses` 是唯一规则；切换、迁移、解除都问它，于是不会对“某布局
  能装什么”有分歧。
- **切换保留新布局能说的，并报出不能说的。** `switch` 返回保留者的 `Migration`，或点名每条 `Loss`（节点+属性）的 `Refusal`，
  于是“这条不能被表达”是一个**带位置的事实**，而不是静默丢弃。
- **解除就是切到自由布局。** `detach` 是 `switch` 到 `LayoutKind::Free`，于是“把布局拿掉”没有自己的一套会漂移的规则。
- **不隐式迁移。** 只有当新种类能容纳**同一个**属性时约束才被保留；没有把 `x` 悄悄重新解释成别的东西。

**命令符**：`--layout-switch <op>...`（`layout:<kind>`、`child:<node>:<property>`、`switch`、`detach`、`state`、`show`）。

**用例**（`app::layout_choice` 9 项 + CLI 解析 1 项）：流动布局间切换保留共性约束；会丢位置的切换被拒并点名；解除为 free
会拒 `grow`；解除保留 free 能表达的位置；free 能表达位置而流动不能、反之亦然；种类名往返；无损失时全保留；
拒报告**全部**损失而非只报第一条；`Loss` 点名属性与原因。

## 13. T10.03：最小/最大/首选尺寸、伸缩、边距、间距、溢出

**交付物**（`src/app/constraints.rs`，新增）。验收词是“**非法/冲突约束定位具体节点**”。约束集**整组校验**，每个问题
都按布局诊断同一种方式报告——节点、属性、来源——于是一个问题是一个**位置**，而不只是一句话：

- **违规自带节点与属性。** `BoxConstraints::validate` 返回的 `Diagnostic` 的 `Source` 点名节点与出错的确切属性，
  面板因此能指向字段而不是笼统的节点。
- **不可满足的集合被拒绝，绝不静默夹紧。** 本模块只**找出**冲突，不挑一个赢家：悄悄收窄一个 `max` 是没人要求过的编辑。
- **两个方向都查。** 最小值高于最大值是冲突，首选尺寸落在区间外也是，于是尺寸自相矛盾的两种情形都被捕到。
- **溢出是带后果的设置。** 当内容大于盒子、而盒子又不滚动时，溢出设置就是说这件事的那个属性，于是诊断点名它。

**命令符**：`--constraints <op>...`（`min:<node>:<w>,<h>`、`max:<node>:<w>,<h>`、`preferred:<node>:<w>,<h>`、
`grow:<node>:<f>`、`margin:<node>:<f>`、`gap:<node>:<f>`、`overflow:<node>:<visible|hidden|scroll|clip>`、`validate`、
`state`、`show`）。

**用例**（`app::constraints` 10 项 + CLI 解析 1 项）：合法集无诊断；最小值高于最大值定位在 `min-width`；首选在区间外定位在
首选尺寸；负 grow/margin/gap 各自被定位；内容大于不滚动盒子定位在 `overflow`；只给 max 的首选仍被查；
只给 min 的首选仍被查；恰好放得下的滚动盒子不是问题；溢出名往返；只有 scroll 保持内容可达。

## 14. T10.04：对齐/分布/匹配尺寸、键盘微调与吸附转换

**交付物**（`src/app/arrange.rs`，新增；并扩展 `layout_choice.rs` 的词汇表加入 `align`）。验收词是“**一次操作变更

## 16. T10.06：焦点顺序、键盘导航可视化、不可达节点提示

**交付物**（`src/app/focus_order.rs`，新增）。验收词是“**可导出为目标支持的焦点语义**”。Tab 序列因此是一个有序列表，
其余一切从树与声明的输入推导：

- **顺序就是一个列表，原样导出。** `FocusOrder::order` 是 Tab 序列，`export` 原样交给生成器，于是预览与生成应用不会对
  “Tab 去哪”有分歧。
- **可达性是算出来的，不是声明的。** 一个候选不可达当它或它的祖先是排除的；`build` 把它单列出来，于是不可达的焦点目标
  被报告，而不是从序列里静默丢掉。
- **不能接受焦点的节点永不在序列里。** `build` 从可聚焦集合出发，于是夹在两个真停靠点之间的装饰不可能变成 Tab 停靠点。
- **显式序号优先，其余由树决定。** 带 `tab index` 的节点按其值排在前；其余按树自身顺序，这就是“自然顺序”。

**命令符**：`--focus-order <op>...`（`root:<kind>:<name>`、`insert:<parent>:<kind>:<name>`、`focusable:<node>`、
`exclude:<node>`、`index:<node>:<n>`、`build`、`step:<node>:<delta>`、`export`、`state`、`show`）。

**用例**（`app::focus_order` 9 项 + CLI 解析 1 项）：可聚焦节点按树序；排除祖先下的节点不可达；被排除节点本身不可达；
不可聚焦节点不入序；显式序号排前；两个显式序号按值排序；Tab/Shift-Tab 首尾回绕；导出序列即顺序；报告把导航画成链。

## 19. T11.01：属性 schema 编辑器：数值/枚举/文本/颜色/尺寸/资源

**交付物**（`src/app/property_editor.rs`，新增）。验收词是“**类型/范围校验，错误不改有效模型**”。编辑器因此把
**有效取值**与**正在键入的文本**分开，这正是让错误无害的原因：

- **有效值是一个拒绝碰不到的东西。** `PropertyType` 解析文本；成功时 `Editor` 替换存下的值，失败时存下**文本**与原因、
  把值留在原地，于是一次误击不能破坏模型。
- **正在键入的文本被保留。** `Editor::pending` 答文本、`Editor::problem` 答原因，于字段显示所键内容并在旁给出错误，
  而不是弹回旧值。
- **类型只说一次。** `PropertyType::parse` 是字符串变成值的唯一地方，于是面板、文件读取器与检查器不会对“某属性接受什么”
  有分歧。
- **schema 没描述的属性不可编辑。** 尝试这样的属性被拒且什么都不动，于是编辑器不会发明模型没有位置的属性。

**命令符**：`--property-editor <op>...`（`schema:<property>:<type>`、`set:<node>:<property>:<text>`、
`value:<node>:<property>`、`pending:<node>:<property>`、`state`、`show`；类型写作 `number:<min>:<max>`、
`integer:<min>:<max>`、`enum:a,b,c`、`text:<max>`、`colour`、`size`、`asset`）。

**用例**（`app::property_editor` 9 项 + CLI 解析 1 项）：合法数值被接受并存下；超范围数值被拒且有效值不变、文本保留；
未描述属性被拒且什么都不动；枚举接受列内变体、拒绝其他；文本超长被拒；颜色/资源按各自家族解析；随后的合法编辑清除问题；
尺寸不能为负；每种类型都能自述。

## 21. T11.03：CSS 文本/规则视图、选择器、计算样式与来源跳转

**交付物**（`src/app/css_view.rs`，新增）。验收词是“**无效 CSS 保留，计算值可解释**”。两者都是关于“不丢信息”
的承诺，于是模块留住每条规则与每处来源：

- **读不懂的 CSS 被留下，而不是丢掉。** `Rule::Invalid` 带原文与原因，于是解析器读不懂的块会进入报告——
  用户看得到并能修正它，而不是眼看它消失（原则 9 对解析失败的要求）。
- **计算值点名它来自哪条声明。** `Computed::source_of` 答 `Source`——规则序号、选择器与声明的 `Span`——
  于是屏幕上的值能跳回产生它的那段文本。
- **级联只有一条规则：先比权值，再比先后。** `compute` 让权值更高者胜、权值相同则由靠后的规则胜，
  于是内联文本与规则视图不会对“哪条声明生效”有分歧。
- **选择器只匹配元素自身的事实。** `Selector` 只读简单复合（tag、`#id`、`.class`）；子集之外的语法被当作
  无效拒绝，而不是悄悄匹配不到，于是“不支持”可见，不会变成“没匹配”。

**命令符**：`--css <op>...`（`css:<规则文本>`（追加一行 CSS）、`element:<复合选择器>`、`value:<property>`、
`source:<property>`、`properties`、`state`、`show`）。

**用例**（`app::css_view` 15 项 + CLI 解析 1 项）：合法规则保留声明与 span；声明缺 `:` 的规则为无效；

## 22. T11.04：设计令牌、颜色/字体/间距资源、引用重命名与主题

**交付物**（`src/app/design_tokens.rs`，新增）。验收词是“**库不支持变量时仅在生成期合法展开并可追踪**”。
这一句把模块分成两半，而分开正是要点：

- **模型保留引用，只有展开才内联。** `Usage` 存下设计师键入的值——`var(--accent)`——并保持如此；
  `TokenSet::expand` 是把它变成字面量的**生成期**步骤。于是读不懂变量的目标靠生成期内联
  （原则 13）得到服务，而不是让设计模型悄悄丢掉引用。
- **展开可追踪。** `Expansion` 带字面量与经过的令牌链，于是生成的 `#3b82f6` 仍能与手写值区分。
- **展开要么合法，要么被拒。** 未知令牌、环、读不懂的 `var(...)` 都是 `TokenError`，绝不产出一个
  “看起来已解析”的字面量。
- **重命名修复每一处引用。** `TokenSet::rename` 改令牌名，并改写主题键、其他令牌值与主题值里的引用；
  `rename_references` 改写用途。于是重命名不会留下悬空名字；重命名到一个已存在的名字被拒，
  而不是把两个资源静默合并。

**命令符**：`--tokens <op>...`（`token:<kind>:<name>:<value>`、`theme:<name>:<token>=<value>[,...]`、
`use:<property>:<value>`、`expand[:<theme>]`、`rename:<from>:<to>`、`state`、`show`）。

**用例**（`app::design_tokens` 16 项 + CLI 解析 1 项）：令牌保留类型与值；用途在展开前保留引用；
展开替换引用并点名令牌；嵌套引用按链展开；未知引用被拒；环被拒；主题改变展开所用值；不存在的主题被拒；
展开字面量不点名令牌；非自定义属性的 `var` 被拒；重命名更新令牌、主题键与其他令牌值内的引用；
重命名到已存在名字被拒且什么都不变；重命名不存在的令牌被拒；`rename_references` 改写并计数；报告
列出令牌/主题与计数。

### 22.1 由测试/证据当场发现的缺陷

1. **展开链的顺序（测试发现）：** 首版把令牌名在递归**之后**入链，于是 `var(--brand)->var(--accent)`
   得到 `[--accent, --brand]`（内层在前）。改为递归前入链，得 `[--brand, --accent]`（外层在前），
   与“从用途到字面量的路径”一致。

   **其他令牌值/主题值**里的 `var(旧名)`；于是 `--brand = var(--accent)` 在 `--accent→--primary` 后
   变成悬空，展开被拒。这与模块自称“重命名不留悬空名字”相矛盾，已修为“令牌值 + 主题值 + 主题键”一并改写，

## 25. T11.07：CSS 内联/级联一致性、令牌迁移与无效引用诊断

**交付物**（`src/app/style_emit.rs`，新增）。验收词是“**同输入预览/生成结果一致**”。这是一个**结构**承诺，
于是模块只造一个发射器：

- **预览与生成是同一个 `emit`。** 两个消费者都调这一个函数；`Mode` 只改结果**怎么打印**，从不改值。
  于是两者无法漂移：没有第二条需要同步的级联（原则 6/14）。
- **内联胜于样式表，两种模式都是。** 内联声明替掉规则的值，并记为 `Origin::Inline`，
  于是优先级是一条规则而不是预览专属约定。
- **解不开的引用是诊断，不是这里的值。** `emit` 答 `Err` 并列出每个无法展开的属性，于是生成期会因整组而阻断，
  而不是发出目标读不懂的引用（原则 13/22）。
- **迁移点名“哪个令牌命名了这个字面量”。** `migrate` 答这个样式会采用的引用与所做的迁移，确定（按名取第一个令牌），
  于是把硬编码值搬到令牌是可审阅、可重复的。

**命令符**：`--style <op>...`（`css:<规则文本>`、`element:<复合选择器>`、`inline:<property>:<value>`、
`token:<kind>:<name>:<value>`、`theme:<name>:<token>=<value>[,...]`、`under:<theme|->`、`preview`、`generate`、
`migrate`、`state`、`show`）。

**用例**（`app::style_emit` 12 项 + CLI 解析 1 项）：预览与生成携带相同值；同输入两次发射同一结果；引用展开为字面量；
内联胜于规则；仅内联的属性也被纳入；未知引用变成诊断且什么都不发射；一个坏引用不遮蔽一个好属性；
预览形式点名来源；生成形式是声明列表；迁移找到命名字面量的令牌；无令牌匹配时迁移为空；迁移后再发射得到相同字面量。

## 26. T11.08：多选/主题/Unicode 字体/对比度/状态边界测试

**交付物**（`src/app/style_boundary.rs`，新增）。验收词是“**撤销恢复样式引用与计算结果**”。模块围绕这一点：

- **会话在变前先快照。** `Session` 在每步被接受前记下令牌、内联值与主题，于是 `Session::undo` 把**引用**放回，
  并因为计算值是由它们派生的，**同一个值**也一并放回——没有一半的恢复。
- **被拒的步不记任何东西。** 重命名到已存在名或切到不存在的主题答 `Err` 且不动历史，
  于是撤销永远不会跨过一个从未发生的步。
- **对比度要么是一个数，要么缺席。** `contrast` 对读不懂的颜色答 `None` 而不是一个看起来合理的比例，
  于是不可读的颜色不能“通过”检查（原则 22）。
- **Unicode 不是特例。** 令牌名与值就是文本；`Session` 与令牌集能处理 `var(--字体)`，因为名字由字母数字组成，
  而 CJK 字符就是字母数字。

**命令符**：`--style-boundary <op>...`（`css:<规则文本>`、`element:<复合选择器>`、`token:<kind>:<name>:<value>`、
`theme:<name>:<token>=<value>[,...]`、`inline:<property>:<value>`、`clear:<property>`、`rename:<from>:<to>`、
`use-theme:<theme|->`、`undo`、`emit`、`contrast:<a>:<b>`、`state`、`show`）。

**用例**（`app::style_boundary` 17 项 + CLI 解析 1 项）：撤销内联编辑恢复引用与值；撤销令牌重命名恢复引用；
撤销主题切换恢复计算值；新会话无可撤销；被拒的步不记历史；撤销逐步回退；黑白对比度为最大值；短写颜色等价；
同色对比为 1；对比对称；非法颜色无对比度；两级阈值是 WCAG 的 4.5/7.0；Unicode 令牌名可展开；
四种状态都能预览（含无规则的）；大选中交集成立（100 节点）；大选中混合值报 Mixed；陈旧主题键惰。
