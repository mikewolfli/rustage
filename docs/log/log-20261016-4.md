## 3. T15.01：页面/入口/模块产物规划、生成区标记、手写区边界

**交付物**：`src/app/generate/artifact.rs`（新增，`src/app/generate/` 为新域）。验收词是“**输出粒度与入库决策可复现**”。

- **一份源出一份文件。** `plan()` 把项目文档的 `generated[]`（`from`→`output`）变成 `Plan`，并拒绝三种形状：
  空白源/产物、一份源两个产物、一个产物两份源。计划按**源路径排序**，故同一文档必得同一计划（原则 16）。
- **提交策略是值。** `CommitPolicy::Committed` 记录库决策 `D7-b-3`（生成物入库、随源一起审阅），
  “这个文件是否可以被我覆盖”由计划回答，而不是写盘处临时判断。
- **生成区/手写区标记。** `FILE_MARKER` 直接引用 `rust_widgets::designer::GENERATED_MARKER`（**同一份定义**，
  原则 35/59）；手写区用行注释 `// region:handwritten <name>` … `// endregion:handwritten <name>` 围起，
  `regions()` 把文件切成 `Region` 序列，拒绝“有闭合无开始”“开始从未闭合”。

**当场缺陷**：`regions()` 最初丢弃“空的具名区”（`start == end`），于是再生文本里那句“这里属于手写区”的
**空占位**被丢掉，T15.04 的合并随之无法把手写区放回去。改为：具名区即使为空也保留（见 §6 的当场缺陷同源）。

## 4. T15.02：接入库生成器、能力/布局/CSS/容量预检与确定输出

**交付物**：`src/app/generate/document.rs` + `src/app/generate/pipeline.rs`。验收词是“**同输入字节稳定；不静默丢节点**”。

- **翻译只有一份。** 库的生成器读的是 `{"button": {…, "children":[…]}}` 这种单键嵌套文档；rustage 的页面文档是
  `{format, page, nodes}` 的扁平节点表。`document::to_library_document()` 是**唯一**的翻译，带深度上限、环检测、
  缺子节点拒绝；属性值的标签（`{"text": "Save"}`）被解包为裸值（`"Save"`），JSON 放不下的值（非有限数）是拒绝。
  （原则 59：不做第二份翻译。）`document::node_keys()` 同时给出每个节点的库键（`root`、`n_0`、`n_1_0`），供 §5 的映射。
- **预检在发码之前。** `pipeline::precheck()`：对每个控件名问**目标自己的工厂**（`availability`，原则 12），
  统计每个容器的子数对目标容量（`child_capacity()`），并折入调用方已算出的 CSS/布局诊断。跨 profile 只记“caveat”不阻断
  （设计器本就跑在桌面上，否则永远无法为 `mini` 生成）；`Unavailable`/`Unknown` 与超容量、样式/布局诊断一律 `Gap` **阻断**。
- **发码是库的。** `pipeline::run()` 调 `rust_widgets::designer::generate`；`run_twice()` 跑两次并**拒绝**两次不一致的结果，
  于是“字节稳定”是被检查的，而不是被声明的。

## 5. T15.03：NodeId/实例 ↔ 源 span、源版本、格式化映射修正

**交付物**：`src/app/generate/mapping.rs`。验收词是“**Unicode/跨模块位置与生成区边界正确**”。

- **按库键定位。** 生成器为每个节点写出 `.key("n_0_1")` 字面量；`build()` 找到该字面量所在**整行**的字节区间，
  用契约 `C-SOURCEMAP` 的 `SourceMap` 记录 `NodeId → span`。偏移是**字节**，故前面有多字节字符也不串行；
  跨文件就是一张图里 span 各带自己的文件（`node_at(file, offset)` 按文件过滤）。
- **源版本随图走。** `SourceMap` 自带 `VersionStamp`（生成器版本 + 模型修订）；编辑后 `staleness()` 报 `Stale`，
  而不是拿旧图跳到已经移动的行。
- **格式化映射修正 = 重建。** `relocate()` 在新文本里**重新找键**，而不是给偏移量加一个差值——格式化会重排行，
  只加差值会随每次重排漂移。库没写出的节点（被拒）没有条目，`span_of` 返回 `None`，不猜。

**验证**：
```text
$ rustage --mapping source:target/ms07/ui.rs file:src/generated/ui.rs key:1:root key:2:n_0 model:3 locate:2 staleness:3
mapped 2 node(s) in src/generated/ui.rs
node 2 -> src/generated/ui.rs:105..145
current
```

## 6. T15.04：模型→文本局部合并、手写保留、生成 diff 审阅

**交付物**：`src/app/generate/merge.rs`。验收词是“**小改动不全量覆盖手写逻辑**”。

- **手写字节拷贝，不重发。** `merge()` 把已提交文件里的每个手写区**逐字**搬走；生成器从来看不到它们，所以再生改不动里面。
- **有标记就原位，没有就追加。** 再生文本带同名标记则原位放置（`InPlace`），否则追加到生成半之后并报 `Orphaned`——
  丢人的代码比文件多一条尾巴更糟。
- **生成半的 diff 给人看。** `Review` 列出生成半里增删的行（LCS 行 diff，超 `REVIEW_LINE_LIMIT` 行则改为一句概述），
  让审批者不必读全文（原则 16）。

**当场缺陷（两处，均由本轮测试当场发现并修掉）**：
1. 见 §3：空具名区被丢，`InPlace` 判不出来。修：具名空区也保留。
2. 更深的：`merge()` 最初只把**孤儿**追加到末尾，`InPlace` 只记在 `review` 里、**没有真正写回文本**。修：
   改为按再生文本的 `Region` 顺序重建——生成区补内容，手写标记处补“标记 + 上一版正文 + 标记”，未匹配者追加。

**验证**：
```text
$ rustage --gen-merge old:target/ms07/old.rs new:target/ms07/new.rs
kept save (appended (no marker in the regenerated body))
- let a = 1;
+ let a = 2;
// Generated by the rust_widgets designer. Do not edit by hand.
let a = 2;
// region:handwritten save
fn save() {}
// endregion:handwritten save
```

## 7. T15.05：JSON/CSS→模型候选、反解析支持表、冲突三方视图

**交付物**：`src/app/generate/reverse.rs`。验收词是“**不可识别变化保留文本、可取消**”。

- **支持表是显式的。** `SUPPORT` 逐条给出生成文件里用到的构造（`.key`、`Node::new`/`create_*`、`.prop`、`.child`
  可读回；函数体语句、`#[cfg]` 只保留为文本）及其含义。表外的构造不猜（原则 29）。
- **未识别变化留文本。** `read()` 只把 `.prop("name", value)` 与上一版比对产生 `Change`；其余改动（如手写的函数体）
  收进 `unrecognised`，且整个被编辑文本存在 `Candidate::text` 里，`cancel()` 原样交还——什么都不丢（原则 19）。
- **三方是视图，不是裁决。** `conflicts(base, mine, theirs)` 逐属性列出三方的值并渲染，永不替人选择。

**当场缺陷**：解析器最初在遇到 `.key(` 时 `continue`，于是**同一行**里链式的 `.prop("text", "Go")` 被跳过；
且取值时用 `trim_end_matches(')')` 处理 `"Go"))`，因结尾是 `;` 而失败，值变成 `Go"));`。修：同一行先更新当前键、
再用循环扫描所有 `.prop(`；取值改为“逗号后扫描到第一个不在字符串内的 `)`”，再剥引号。

**验证**：
```text
$ rustage --reverse base:target/ms07/rev.rs edited:target/ms07/rev2.rs
n_0 .prop("text", "Stop")
kept (unrecognised): fn mine() {}
```

## 8. T15.06：位置重算器、循环阻断、跨视图 undo 与映射失效恢复

**交付物**：`src/app/generate/position.rs`。验收词是“**连续格式化/编辑后不定位错节点**”。

- **位置按字符、偏移按字节。** `Position{line,column}` 与 `position_of`/`offset_of` 是唯一的换算对；多字节字符不会把列按字节算。
- **编辑搬动其后的偏移，删掉的没有答案。** `Edit::apply` 对落在被删区间内的偏移返回 `None`，调用方必须处理，
  而不是收到一个恰好还落在范围内的旧偏移。
- **循环阻断是计数的。** `LoopGuard` 限制“一次编辑触发多少趟”；超限返回带原因的错误，而不是转圈。
- **跨视图 undo：一份历史。** `Journal` 记录任意视图的步骤，`undo()` 取回最后一步——一个拖拽跨树/画布/代码一次撤销。
- **映射失效恢复。** `recover()` 对新文本重定位并按前后节点集合报告 `lost`，而不是交回一张悄悄少了几项的图。

**当场缺陷（测试期望错，语义更正）**：`position_of(text, 4)` 对 `"αβ\n…"`——字节 4 是**换行符本身**，属第 1 行行尾；
第 2 行第 1 列在字节 5。原测试期望 4 是错的；已改为按“列 c 表示 c−1 个字符之后”的语义断言，并写明在用例里。

## 9. T15.07：单页/全工程生成、产物提交/导出与独立构建契约

**交付物**：`src/app/generate/export.rs`。验收词是“**生成失败保留旧文件，产物不依赖宿主运行**”。

- **两阶段提交。** `commit()` 先把每个产物写到目的地旁的临时文件，**全部**写成功后才逐个 `rename` 就位；
  任何一步失败即清掉临时文件、原文件一字未动（把 `project::document::save` 对单文档的纪律推广到一组）。
- **未变不动。** 内容与生成一致的产物报 `Unchanged` 且不重写，不推动 mtime，下游增量构建不受影响。
- **越界即拒。** 绝对路径或含 `..` 的产物在写之前拒绝。
- **独立构建契约是行列表。** `standalone_contract()` 明说：只依赖固定的 widget 修订、只用一个 profile feature、
  默认模板用 `crate::view` 而 stripped 不用、产物在 `src/generated/`、不引用设计器进程/端口/预览会话。

## 11. T16.01：工具链/SDK 探测、Cargo 配置/feature/模式与预检

**交付物**：`src/app/build/toolchain.rs`（`src/app/build/` 为新域）。验收词是“**缺环境与能力不支持分开诊断**”。

- **两条不同的结论。** `Finding::Missing{capability, remedy}` 是“本机缺东西，装上就好”；
  `Finding::Unsupported{capability, reason}` 是“这个请求任何机器都做不了”。两者是同一 enum 的两个变体，
  而不是一条带前缀的消息——把 profile 名拼错却被告知“去装 SDK”正是要避免的。
- **单一 profile。** `Selection::feature_arguments()` 只发 `--no-default-features --features <profile>[,<extra>]`
  （原则 51）；把另一个 profile 当 feature 传入是 `Unsupported`（一个构建只有一个输出 profile）。
- **交叉目标分开查。** 目标三元组的标准库与（Windows 的）SDK 分开查；`xwin` 作为 Windows SDK 的补救被点名。

**验证**：

## 12. T16.02：异步 check/build/rebuild、实际命令、退出码与取消

**交付物**：`src/app/build/compile.rs`。验收词是“**成功依据真实退出，取消不留误激活产物**”。

- **命令是数据。** `Job::command()` 是 argv 的唯一拼法；`Action::Rebuild` 额外先 `cargo clean -p <包>`，
  **只清这个包**，不炸掉整个依赖缓存。
- **成败看退出码。** `Outcome::from_exit(job, Some(0)|Some(code)|None, …)`：`None`（被取消）是 `Verdict::Cancelled`，
  **永不算成功**，并明说“任何产物都是陈旧的”。
- **真跑。** `--compile execute` 用 `std::process::Command` 直接跑上面那条 argv（不经 shell），拿到**真实**退出码与输出。

**验证（真实 cargo，非模拟）**：
```text
$ cat target/ms07/consumer/Cargo.toml   # 一个只带 `desktop` feature 的空包
$ rustage --compile action:check profile:desktop manifest:target/ms07/consumer/Cargo.toml execute
cargo check --no-default-features --features desktop --manifest-path target/ms07/consumer/Cargo.toml
check [profile desktop with --no-default-features]: succeeded
stderr: 168 bytes
exit=0
```

## 13. T16.03：构建 JSON 诊断/日志、源位置/NodeId 回流与过期标记

**交付物**：`src/app/build/build_diagnostics.rs`。验收词是“**诊断带源位置、回指节点、过期而非当前**”。

- **读 cargo 自己的 JSON。** `parse()` 逐行读 `--message-format=json`，取 `level`/`message`/`code`/首个 `spans`；
  非编译消息的行收进 `raw` **而非丢弃**（人需要看的输出不能被吞）。
- **位置变成节点。** `locate()` 把 `file/line/column` 变成字节偏移，再问 `SourceMap::node_at` 是哪个节点——
  “main.rs:3:5 的错误”就成了“那个 `save` 按钮”。
- **带时间戳。** `Batch` 带模型修订，`is_stale(current)` 与 `staleness()` 让旧诊断**被标注**而不是冒充当前。

## 14. T16.04：运行配置/参数/环境、独立运行、停止/重启与退出原因

**交付物**：`src/app/build/runner.rs`。验收词是“**程序独立运行，停止会说明原因**”。

- `Config::command()` 是 argv 的唯一拼法；`Run` 是 `Idle→Running→Ended` 的状态机。
- **独立是一条纪律。** `standalone` 为真时，环境里出现 `RUSTAGE_*`（指向设计器会话）即拒绝启动
  （原则 15：交付产物不得依赖宿主）。
- **停止有原因。** `Reason` 区分干净退出、非零码、信号、显式停止。

## 15. T16.05：任务配置、前后置任务、并发/缓存与定向产物清理

**交付物**：`src/app/build/tasks.rs`。验收词是“**前/后置被遵守，安全时才跳过，清理只删本任务的产物**”。

- **顺序是算出来的。** `order()` 是拓扑排序，按名破平局（确定性）；环、重名、缺依赖各自拒绝并点名。
- **缓存键要挣。** `cache_key()` = 命令 + 环境 + 已声明输入的指纹（指纹由调用方给），输入变了不会被跳过。
- **默认 = 没人依赖它的那个任务**；有多个候选则要求显式 `default:<name>`，不猜。
- **清理只删声明过的输出。**

**当场缺陷（测试期望错，语义更正）**：`[build, run(after build)]` 的默认任务应是**`run`**（“没人依赖的那个”，也即人实际要跑的），
原测试写的是 `build`。已改正用例，并保留“显式 default 优先”。

## 16. T16.06：三平台 PTY 终端、多会话/目录/环境、授权与选择复制

**交付物**：`src/app/build/terminal.rs`。验收词是“**三个宿主各自是真实会话，工作目录与环境明确，运行须授权**”。

- **本模块是会话模型，不是字节泵。** `mechanism(Platform)` 回答 macOS/Linux 用 POSIX PTY、Windows 用 ConPTY，
  **由宿主后端提供**；本文件不写 `cfg(target_os)`（原则 42 把平台分支留在后端，不留在上层）。
- **授权在前。** `start()` 必须先 `authorize()`，未授权即拒绝——不存在“终端自己开起来”的状态。
- **输出有界。** 缓冲保留最近 `BUFFER_LIMIT` 字节并**计数**丢弃量；`copy(start,end)` 越界拒绝。

**边界**：真实 PTY 的字节泵（`openpty`/ConPTY 的读写线程）属宿主层；本模块交付的是它必须满足的模型，§23 记明。

## 17. T16.07：外部工具定义、参数占位、输入输出定位与命令确认

**交付物**：`src/app/build/external.rs`。验收词是“**参数来自具名占位、输入输出位置明确、可能越界的工具先确认**”。

- **具名占位。** `expand()` 替换 `${name}`，**未知占位即拒**（把 `${typo}` 当字面量交给程序比不跑更糟）；`${` 无 `}` 也拒。
- **输入/输出是字段。** `Tool::inputs`/`outputs` 是设计器监视的位置。
- **确认。** `Tool::confirm` 为真的工具，`invoke()` 未确认即拒。

## 18. T16.08：生成→检查→构建→独立运行→错误回流端到端用例

**交付物**：`src/app/build/e2e.rs`。验收词见 [blue8.md](../plan/blue8.md) T16.08（本里程碑退出演示）。

- **每步都记账，包括没跑的。** 因前一步失败而没跑的步骤记 `Skipped`（**不是静默的成功**）；`skip_missing()` 补齐。
- **回流收口。** `Stage::Feedback` 带“几个问题回指到设计”，于是这趟不停在“它编过了”。
- **`blocked_at()` 点出第一步失败。**

**验证**：
```text

generate (2 files): ok
check (E0308): failed: E0308
build: skipped (an earlier stage blocked it)
run: skipped (an earlier stage blocked it)
feedback: skipped (an earlier stage blocked it)
blocked at check
```

## 19. T16.09：类型化任务 DAG、默认任务、problem matcher、后台就绪与终端关联

**交付物**：`src/app/build/dag.rs`。验收词见 blue8.md T16.09。

- **边带顺序语义。** `Order::After`（等它跑完）/`Order::Together`（与它同波）。`waves()` 用**波层不动点**算层级：
  `After` 取依赖层 + 1，`Together` 取依赖层；层数单调上升，环会一直升而被界转成点名拒绝。
- **problem matcher 是真匹配器。** `compile()` 把 `(.*)`/`(.+)`/`(\d+)` 编译成分段，`match_line()` 递归匹配整行取分组；
  不引入正则依赖，也不用 `split(':')` 那种一遇路径里带冒号就崩的做法。分组下标越界在 `matcher()` 处即拒。
- **后台就绪靠观测。** `Ready::is_ready(output)` 看标记；`terminal_of()` 回答任务在哪个终端。

**当场缺陷（语义更正）**：首版 `waves()` 把 `Together` 兄弟直接放进**第 0 波**（因为“依赖名存在”就放行），
于是 `watch` 跑到 `gen` 那波去了。改为上面的波层不动点：`build` 与 `watch` 同在第 1 波。

**验证**：
```text
$ rustage --dag node:gen node:build after:build:gen node:watch together:watch:build node:server background:server:listening terminal:build:build 'pattern:cargo:(.+):(\d+): (.+):0:1:2' 'match:src/main.rs:12: mismatched types' waves 'ready:server:server: listening on 1'
src/main.rs:12: mismatched types
server ready: true
wave 0: gen, server
wave 1: build, watch
```

## 20. T16.10：可复现/离线 Cargo 构建配置、locked/frozen/offline/vendor 与缓存边界

**交付物**：`src/app/build/reproducible.rs`。验收词见 blue8.md T16.10。

- **flag 是推导的。** `flags()`：`locked` 且 `offline` → 只发 `--frozen`（一个含义一个 flag）；否则各发 `--locked`/`--offline`。
- **缓存边界受检。** `cache_is_outside_source()` 拒绝把 target 放进已提交源目录内（否则构建依赖别的机器留下的东西）。
- **vendor 是目录，写在明处。** `vendor_config()` 给出 `.cargo/config.toml` 的行，而不是远距离设环境变量。

**验证**：
```text
$ rustage --reproducible locked:yes offline:yes cache:target source:src
flags: --frozen
cache is outside the committed source
```

## 21. T16.11：headless 校验/生成/检查 CLI 与 CI 配置导出、机器可读结果

**交付物**：`src/app/build/headless.rs`。验收词见 blue8.md T16.11。

- **三步与桌面同一趟。** `Step` = validate/generate/check；无头与窗口做同样的事，故 CI 绿与预览绿含义一致。
- **结果是 JSON。** `render_json()` 用项目自己的 JSON writer 产出**成员顺序固定**的文档（同输入同字节）。
- **退出码只算一次。** `exit_code()` 只在**每一步**通过时为 0。
- **CI 导出。** `github_workflow()` 导出固定工具链与修订的 GitHub Actions 工作流。

**验证**：

**关键设计。** 英文包不是手写的，而是**从词汇表派生**的（`vocabulary::pack`），词汇表又从真实的注册表/菜单/键位表
派生，所以“界面显示的字符串”和“语言包里的字符串”**不会漂移**（原则 #59）：键来自既有标识符（命令 id、菜单 id、子菜单 id），
不来自英文文本，所以改英文不会移动键。选定的语言经 `catalog::install` 装到进程上（同 `host::log` 的做法），
`Catalog::current()` 把它解析到对应包，因此一句诊断会随语言变化——即使目前只有一个包。

### 27.2 为什么不是“字面上的所有字符串”（诚实边界）

程序里带字母的字符串字面量约 2.15 万个、`println!/eprintln!` 约 819 处；其中绝大多数是**内部**文本
（测试期望、格式片段、文档注释、命令面 op 动词、路径与键）。把全部内部诊断模板在一次性改动中机械改写，
既越过了原则 #65“按覆盖本次变更的最小验证”的预算，也会把大量无测试的模板改成高风险批量改写。

因此本轮定义的“程序字符串”是**设计器面向使用者的界面词汇**，也正是 T24.03 的最低验收
“菜单/弹窗/诊断/快捷键帮助无遗漏”所指的集合：

- **命令注册表**（`app::commands::command`）：每条命令的 title/category/description 与每个参数的 help — 37 条。
- **菜单树**（`app::commands::menu`）：菜单/子菜单标题与每个叶的标题（叶按它绑定的命令 id 建键）— 24 条。
- **诊断**（`diag.command.*`）：拒绝句的模板 — 7 条。
- **外壳**（`shell.*`）：版本行、状态摘要与 `rustage:` 前缀 — 5 条。

共 **73 条**（去重后键唯一）。**未收录**的是各 `run/*.rs` 处理器自选参数拼出的原因子句与用法（`--help`）大段正文：
它们已作为待办明列在 §27.5，而不是被默默当成已翻译。

### 28.3.3 未关闭与未覆盖（必须如实保留）

1. **Windows/Linux 构建与运行**：本轮只安装了 `x86_64-apple-darwin`；Windows target/SDK 与 Linux 链接器
   未准备。矩阵中对应格保持 `unverified`，`--target-build-matrix ... check` 如实 exit 4。
2. **tablet/mobile 设备**：没有 iOS/Android SDK 或真机。`Support` 能记录真实设备证据，但本轮只演示了
   声明式 simulator/device 两条路径；**不得**把本轮结果读成“已支持移动设备”。
3. **生成物未链接**：`mini`/`embedded` 的真实构建对象是固定依赖的 profile（rlib），不是生成的
   `build_mini()` 源码；生成的 default/stripped 源码只做了真实生成，未编译。
4. **本地安装只到计划**：`plan_install` 产出并打印命令，未启动 `adb`/`xcrun`/`probe-rs`；这是
   “计划不等于安装”的显式边界，不是静默成功。
5. **签名只到引用**：没有调用 `codesign`/`apksigner`；`Signing` 只保存身份与凭据引用，类型里没有密钥值。
6. **命令/菜单/面板**：F18 的窗口层（目标配置面板、构建矩阵面板、设备选择器）属 F04/F21 尚未实现的
   部分；本轮交付的是可复现的 CLI 接缝与数据，支持矩阵已更新。
