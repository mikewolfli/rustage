## 4. blue10 剩余：真实暂停/排空/切换

### 4.1 worker 协议

`app::logic::worker` 新增三个请求：

| 请求 | 回答 | 语义 |
|---|---|---|
| `pause` | `paused` | 幂等；之后业务事件被拒绝而不是排队或静默丢弃 |
| `drain` | `drained` | 仅在暂停时成立；同步双工管道中“收到 pause”已经蕴含此前请求全部应答 |
| `resume` | `running` | 仅在暂停时成立；否则 `error=` |

manifest 的能力列表变为 `reduce, state, pause, drain, resume`。`state`/`snapshot`/`restore`/`quit`
在暂停期间仍可用，因为驱动需要在暂停后取快照。

### 4.2 驱动

`--logic-process` 新增 `pause-limit:<ms>`，隐含 `preserve`。流程：

1. 启动旧代并跑完 `first-event`；
2. `Swap::begin` → `pause_ticked(实测耗时)`；超过上限则不启动新代，旧代被再次询问状态；
3. `pause` → `paused`；`drain` → `drained`；
4. `snapshot` 并记录到 `Swap`；
5. 启动新代、`restore`；成功则 `import(true)`、`confirm`、`resume`；
6. 旧代实际退出后才 `retire_old()`，打印 `retired`。

### 4.3 新证据

`tests/logic_process.rs` 新增两项，均通过：

```text
test a_paused_swap_walks_every_phase_against_two_real_processes ... ok
test a_pause_past_its_limit_leaves_the_old_generation_serving ... ok
```

第一条的实际输出包含全部阶段：

```text
swap phase: pausing
swap phase: paused
swap phase: drained
swap phase: snapshotted
swap phase: imported
swap phase: confirmed
swap phase: resumed
swap phase: retired
```

第二条用 `pause-limit:0` 确定性地超时，输出包含：

```text
swap phase: pausing
generation 5 still serving: running
rustage: the pause reached 0 and its limit is 0
```

退出码为 4，且没有启动第二代。原来的 9 项 `logic_process` 测试同时通过（共 11 项）。

## 5. blue11 剩余：Windows desktop 组合真实构建

### 5.1 环境准备

```text
$ rustup target add x86_64-pc-windows-msvc
$ xwin --accept-license --cache-dir ~/.xwin-cache splat --output ~/.xwin
```

xwin 只警告宿主的文件系统大小写不敏感并禁用符号链接；SDK 的 `crt/include`、`sdk/include/*`、
`crt/lib/x86_64`、`sdk/lib/um/x86_64`、`sdk/lib/ucrt/x86_64` 均已就位。

### 5.2 构建命令

```text
CC_x86_64_pc_windows_msvc=clang \
AR_x86_64_pc_windows_msvc=/opt/homebrew/opt/llvm/bin/llvm-lib \
CFLAGS_x86_64_pc_windows_msvc="-I$HOME/.xwin/sdk/include/ucrt -I$HOME/.xwin/sdk/include/um -I$HOME/.xwin/sdk/include/shared -idirafter$HOME/.xwin/crt/include" \
RUSTFLAGS="-Lnative=$HOME/.xwin/crt/lib/x86_64 -Lnative=$HOME/.xwin/sdk/lib/um/x86_64 -Lnative=$HOME/.xwin/sdk/lib/ucrt/x86_64 -Clinker=<toolchain>/lib/rustlib/aarch64-apple-darwin/bin/rust-lld" \
cargo build --target x86_64-pc-windows-msvc --bin rustage
```

结果：

```text
Finished `dev` profile [unoptimized + debuginfo] target(s) in 41.92s
$ file target/x86_64-pc-windows-msvc/debug/rustage.exe
PE32+ executable (console) x86-64, for MS Windows
$ ls -lh target/x86_64-pc-windows-msvc/debug/rustage.exe
48M
```

### 5.3 当场发现并修掉的问题

1. **`minimp3-sys` 的 C 编译把 SSE intrinsics 变成外部符号。** 初版把
   `~/.xwin/crt/include` 放在 `-I` 里，导致 clang 选中 MSVC 的 `intrin.h`；当前 clang 对
   `__declspec(intrin_type)` 只发 warning，`_mm_*` 因而成为未定义外部符号，链接失败。
   改为**不把 `crt/include` 放进 `-I`**，用 `-idirafter` 提供 `stdlib.h`，让 clang 使用自己的
   intrinsic 头；清理 `minimp3-sys` 的旧对象后链接通过。
2. **Windows 构建的 `unused variable: grace`。** `host::subprocess::signal_and_reap` 的
   `#[cfg(not(unix))]` 分支没有使用宽限期；补 `let _ = grace;` 并在注释里说明非 unix 宿主没有
   进程组可信号，因此直接杀进程就是全部操作。这使 Windows 构建不再带该 warning。
3. **`src/app/run/build.rs` 的 CI workflow 修订是手写的。** 已改为引用 `DEPENDENCY_REVISION`，
   与探针和 `Cargo.toml` 同源。

## 5.6 补记：真实 POSIX 伪终端（T16.06）

此前 `app::build::terminal` 是会话模型，真实字节泵被列为未覆盖。现在：

- 新增 `src/host/pty.rs`：`posix_openpt` → `grantpt`/`unlockpt` → `ptsname`，子进程的
  stdin/stdout/stderr 全部接 slave，master 用 `TIOCSWINSZ` 设尺寸并有界读取；
- `--terminal` 新增 `exec:<program>`、`arg:<value>`、`start`（有 `exec` 时启动真实进程）、
  `input:<text>`、`read`、`wait:<ms>`、`terminate`；未授权仍拒绝；
- `tests/terminal_pty.rs` 三项通过：`/bin/sh -c 'printf pty-ok'` 真实输出、`/bin/cat` 收到
  输入并回显、未授权启动 exit 4。

命令证据：

```text
$ target/debug/rustage --terminal authorize exec:/bin/sh arg:-c 'arg:printf hello-from-terminal' start wait:5000 read
started /bin/sh pid ...
exit 0
output "hello-from-terminal"
dropped 0
```

Windows 的 ConPTY 由 `host::pty_windows.rs` 接在 `portable-pty` 上（仅在 `cfg(windows)` 声明），
`cargo check --target x86_64-pc-windows-msvc` 通过；本机没有 Windows 运行环境，因此只到构建级证据，
不把它写成已运行。

## 5.9 真实语言服务传输（T07.01）

新增 `src/host/lsp.rs`：

- 子进程 stdio，`Content-Length` 帧的读写；
- `initialize` 请求 + `initialized` 通知；能力从服务器返回的 `capabilities` 对象读取；
- 按 id 匹配请求/响应，超时有界（默认 10s）；
- `shutdown` → `exit` → 等待 2s → 必要时 kill；`Services` 析构时停止仍开着的会话；
- stderr 有界捕获（64 KiB），失败时作为诊断返回。

`--language` 新增真实路径：

```text
$ rustage --language exec:rust-analyzer root:/tmp/lsp-proj view:/tmp/lsp-proj close:/tmp/lsp-proj show
view: project /tmp/lsp-proj: running, capabilities: completion, hover, definition, references,
  symbols, diagnostics, code-action, formatting, rename, inlay-hint, code-lens, call-hierarchy,
  semantic-selection (pid 48970)
close /tmp/lsp-proj: released=true
```

能力集来自 `rust-analyzer` 自己的 `initialize` 结果，不是脚本填的；缺失的 `type-hierarchy`
也如实不在集合里。`tests/language_service.rs` 三项通过：真实服务器启停、不可执行程序以 exit 4
结束而不是挂起、真实补全。

### 5.9.1 补全结果已接线

`--language ... wait:<ms> complete:<file>:<byte-offset>`：

1. 用 `protocol::to_units` 把字节偏移换成 LSP 的 UTF-16 位置；
2. 首次打开文件时发送 `textDocument/didOpen`（`languageId` 按扩展名）；
3. 发送 `textDocument/completion`，用 `features::completions_from_lsp` 把
   `CompletionList` / 裸数组转成类型化 `CompletionItem`；
4. `insertTextFormat: 2` 保留为 `ItemKind::Snippet`，detail/documentation 同带入模型。

真实 `rust-analyzer` 在一个含 `let alpha`/`let beta` 的小 crate 上返回：

```text
completion: beta [variable] (i32)
completion: alpha [variable] (i32)
```

`wait:<ms>` 是显式等待，不把「索引未完成」伪装成「没有补全」。

**边界：** 握手、能力、补全已真；hover/definition/diagnostics 等结果仍未接到模型，真实 FS 遍历
也未接。
