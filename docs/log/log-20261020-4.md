## 1. issue 第 5 步：事件/数据与运行检查

### 1.1 新增模块

**`src/app/run/workbench_events.rs`（T13.03/T13.04）**

- `EventsState` 持有 `data::events::{Registry, Wiring}` 与一个 `NodeId`。
- 声明带载荷类型；`rows()` 每行显示 `event [payload] — declared/wired`，三种事实分开。
- `bind(event, handler)`：未声明事件、空 handler 被拒；重复绑定替换同一个 `Attachment`。
- `unbind(event)`：只删除所选节点的那个附件；第二次移除被拒。
- `fire(event)`：按声明构造类型化载荷，调用共享的 `events::fire`；合法载荷但未接线明确报告
  “no handler is wired”，不伪装成成功；**不调用任何业务函数**。
- 7 项测试覆盖声明/接线分离、非法绑定、替换不叠加、解绑、无线接触发、已接线触发、未声明触发。

为支持解绑，在 `src/app/data/events.rs` 增加 `Wiring::detach(node, event) -> bool`——这是模型缺的
一个真实操作，而不是 UI 里手工清表。

**`src/app/run/workbench_inspect.rs`（T14.05/T13.04）**

- `InspectState` 持有 `preview::inspection::Inspection`、数据 `Schema`、sample/runtime `Data` 与版本。
- `retarget(scene, selected)` 从同一个 `CanvasState` 记录每个节点的 kind、父节点、生成行号与矩形。
- `inspect()` 只读地返回 `title`/`bounds` 的 design、computed、runtime 三层及版本，以及
  `locate` 的源位置与布局路径；runtime 在没有真实 adapter/instance 时显示 `not available`，
  不复制设计值。`effects()` 始终来自 `Inspection`，只读检查后仍为 0。
- `edit(field, text)` 用 schema 的 `FieldKind` 解析 sample 值；成功推进版本，失败保留文本并返回原因。
- 6 项测试：三层与版本、只读不派发、合法编辑推进版本、非法值不动模型、未声明字段、布局树。

### 1.2 窗口接线

## 2. T11.02：多选交集与重置

`src/app/run/workbench_property.rs` 从“一个节点一个值”扩展为“一个选择一个值”：

- `retarget_many(&[(NodeId, &str)])` 记录每个节点的结构名基线；每个节点保留自己已接受的值。
- `common()` 通过共享的 `style::multi_property::{common, value_of}` 回答：全部相同为 `Agreed`，
  否则 `Mixed`；字段在 mixed 时为空并显示 placeholder，绝不拿一个节点的值代表其余。

  合法值与 revision 不变，避免半完成事务。
- `reset()` 用 `multi_property::reset` 的答案把显式编辑退回结构名，并报告 `reverted to …`；
  Inspector 的 `Reset` 按钮同步重命名树与画布。
- 6 项测试：单选合法/拒绝/retarget、mixed 显示、多选一次校验、Reset 恢复来源。

`marquee_select` 现在把整个选择交给 `retarget_many`；`apply_property` 重命名所有选中节点。
