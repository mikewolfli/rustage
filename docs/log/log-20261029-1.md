### T20.05 之前的状态

`Repository::switch_branch` 只要求工作区干净，然后执行 `git switch` 并打印结果。它没有回答
路线图要求的两个问题：

1. **切换不丢缓冲**：调用方通过 `dirty:<path>` 报告了未保存文档，切换仍会执行；脏工作区只有
   “拒绝”一种处置，没有可恢复的显式替代。
2. **不把旧目标状态沿用新分支**：切换后没有重新读取工程文档，也没有比较目标/profile/page 列表；
   旧分支的 target 选择与构建状态会被默认当成仍有效。

## 1. 落地内容

### 1.1 新的状态失效模型（`src/app/vcs/branch.rs`）

- `Snapshot`：从真实的工程文档读取格式版本、迁移来源、target（名称/profile/features）、page
  文档和生成物路径。读不懂的格式是错误，不是“空工程”。
- `Snapshot::read_optional`：区分“这个分支没有工程文件”（`Ok(None)`）与“文件存在但不可读”
  （`Err`）。权限/内容错误不会被伪装成缺失。
- `compare`：比较切换前后两个快照，产出三类可分别呈现的事实：
  - `reload`：需要重新读入的文档/页面/生成物（含格式变化与旧格式迁移）；
  - `invalidated`：不能沿用的状态（旧 target 被删除或 profile/features 改变、工程文件在新分支消失）；
  - `migration`：新分支上的旧格式必须在写入前迁移。全部一致时给出“target 状态仍有效”的正面结论。
- `refuse_dirty_buffers`：有未保存缓冲时拒绝切换，逐个列出文档名，并说明缓冲不是 Git 能 stash 的文件。

比较的语义是“两份真实模型对照”，不是打印一句“已切换”。`None`/`None` 不产生比较结论，
调用方必须显式说明没有工程文件可比，不能用空报告冒充通过。

### 1.2 脏工程的可恢复处置（`Repository::switch_branch_stashing`）

- 干净工作区：直接切换，不产生 stash。
- 脏工作区：先 `git stash push -u`（消息 `rustage: switch to <branch>`），再切换，并把 stash
  消息写进输出，工作可找回。
- 切换失败：立即 `git stash pop` 恢复；恢复也失败时，错误同时给出 stash 位置与失败原因，
  不留下“切换失败 + 工作消失”的半完成状态。

### 1.3 CLI（`--vcs`）

新增操作：

```text
project:<path>        切换前后读取的工程文档；相对路径按仓库根解析
switch:<branch>       有 dirty:<path> 时拒绝；脏工作区拒绝
switch-stash:<branch> 有 dirty:<path> 时仍拒绝（缓冲无法 stash）；脏工作区先 stash 再切换
```

`switch`/`switch-stash` 在工程文件存在时输出比较结果；未命名工程文件时明确输出
“没有命名工程文件，target 状态未比较”，不伪造“无变化”。发生 stash 时，比较标签写成
“the worktree before the switch”，因为此时比较的是被 stash 的脏工作区，而不是旧分支的提交内容。

### 1.4 编辑器：`CodeEditor` 是唯一引擎

宿主 `src/app/editor/` 原本有一套自己的高亮、坐标、多光标和视图实现（`highlight.rs` 里还有三套
手写 Rust/JSON/CSS lexer），与库 `code_editor` 并行。按路线图 §12“宿主代码编辑视图以库
`code_editor` 控件为基”和原则 #59，本轮开始收敛，不新增宿主编辑器：

- **高亮**（T06.02）：`lex_line` 改为调 `BuiltinHighlighter::highlight_line`，语言从 4 种扩到库的
  20 种；宿主只保留增量缓存与 `TokenKind` → `Role` 主题投影（新增 type/function 两个角色）。
  `LineState` 直接用库类型，删除宿主的三变体枚举。
- **适配层**（T06.01/T06.04）：新增 `app/editor/adapter.rs`，组合而不是继承 `CodeEditor`，
  提供 set_text/set_language/caret(s)/selection/set_caret/add_caret/insert/type_text/
  backspace/delete_forward/move_line/duplicate_line/delete_line/toggle_comment/undo/redo/
  matching_brackets/protect/is_editable_at。宿主不实现任何编辑原语，多光标插入是一次控件事务。
- **`--edit-ops`**：carets/select/insert/type/backspace/delete/up/down/duplicate/delete-lines/
  comment/matching/undo/redo 全部转调适配层；字节 offset ⇄ `TextPosition` 的转换只放在命令边界
  （`position_at`/`offset_of`），越界或落在字符中间即拒绝。
- **坐标**（T06.03）：`--coordinates` 改用 `CodeEditor::visual_lines` 与 `TextPosition`；折叠、
  可视行、可见行范围都是控件的。删除宿主 `coordinates.rs`（710 行）。
- **视图**（T06.05）：`--editor-view` 的折叠改用 `fold_all`/`fold_regions`，窗口内容用
  `line_text`；minimap 不再由宿主算 band，报告改为控件视口。删除宿主 `editor_view.rs`（469 行）。
  行号/空白字符是纯排版，留在 CLI 层。
- **窗口编辑器**（T06.01）：`workbench_gui.rs` 不再把文档灌进 `list_box`，改为
  `mount_widget_by_name("code_editor", …)`；`sync_editors` 用
  `runtime::with_widget_mut` + `Any::downcast_mut::<CodeEditor>` 更新文本，路径全部是库的公开
  API（`Widget: Any`）。编译级接线已完成；窗口视觉与输入仍需人工跑一次才计完成。
- **片段**（T06.09）：未迁移。控件没有多选区编辑（`ExtraSelection` 只是装饰），
  `Session` 的占位符联动需要一次修改多个选区；保留 `editing.rs`，并写入上游请求。

### 2.5 百万行基准（T06.08 第一组数据，debug 构建）

1,000,000 行 / 21,777,780 字节：

| 操作 | 控件 `CodeEditor` | 宿主 piece table |
|---|---|---|
| 打开 | 81.4 ms（`with_options`/`set_text`） | 3.9 ms（`TextStore::new`） |
| 首位置插入 | 19.2 ms | 0.22 ms |
| 一次 undo | 85.8 ms | 0.03 ms |
| 取第 50 万行 | 22.7 µs（`line_text`） | — |
| 全量可见行 | 55.9 ms（`visual_lines`，1,000,001 行） | — |
| 高亮 `set_text` / `step(1000)` | 120.6 ms / 2.18 ms | — |

结论：控件打开已低于 roadmap `editor-2m` 的 100 ms 目标（debug 构建），但**位置→可视行仍需全量
`visual_lines`**，单次坐标查询在百万行下约 56 ms，不可放在每帧/每次光标移动路径；已在
`rw-feedback/feedback-20261029.md` §6 请求单点查询。piece table 纯文本操作更快，但它不提供控件
能力，不能因此保留第二套编辑器；T06.07 的“打开可取消/分级降级”未接，本条不完。

高亮测试中只有 JSON 一项需要按库行为调整：库不给 JSON 的 `{}` 结构符生成 span，只标记值、分隔符和
`true/false/null`。这是库的渲染选择，不是缺陷；不为了旧断言去恢复宿主 lexer。
