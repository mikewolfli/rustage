## 1. T07.02：LSP 四类通知与版本同步

文件：

- `src/app/language/protocol.rs`
- `src/app/language/session.rs`
- `src/host/lsp.rs`
- `src/app/run/language.rs`
- `src/app/language/features.rs`

实现：

- `Notification::{Open,Change,Save,Close}` 为类型化通知；`Sync::apply` 统一推进版本。
- `DocumentSession` 组合 `Sync` 与每文档 `Completions`，排队通知并提供 `request/accept/items`。
- 宿主 `lsp` 客户端新增 `did_open/did_change_full/did_change_incremental/did_save/did_close`
  及 JSON 参数构造。
- `--language` 的 `complete` 打开一次，后续按字符边界安全的前缀/后缀 diff 发增量
  `didChange`；新增 `save:<file>` 与 `close-document:<file>`；项目 `close` 发送所有
  `didClose`，`restart` 丢弃旧会话。
- 完成回复只有 digest/version 匹配当前文档才被接受；过期回复不覆盖新列表。
- 传输失败仍保留服务器错误信息，不伪装成功。

## 2. T09.01：控件目录来自库契约

文件：

- `src/app/canvas/widget_catalog.rs`
- `src/app/run/design.rs`

实现：

- `Catalog::from_contract(&WidgetFactory, profile)` / `from_contract_at`：
  - `constructible_names()` 与 `widget_names()` 合并；不可构造但注册表知道的名称保留为
    unavailable，不静默丢弃。
  - 每个控件读取 `designer_manifest`；若默认值读取失败，退回 capability 的
    `PropertySchema`/`EventSchema` 并把失败写入 `limits`，不编造默认值。
  - 属性、事件、别名、`WidgetKind::css_name()` 分类来自契约。
- `Provenance` 记录 crate、库版本、`DEPENDENCY_REVISION`、manifest protocol、build
  profile/triple、目标 profile、捕获时点与 capture version。
- `Support::{Local,CrossProfile,Unavailable,Unknown}` 对应库四态并各自带原因。
- `run/design.rs` 默认从契约构建；`widget:`/`property:` 变成核对声明而不是创建目录；
  `unsupported:` 被拒绝，因为支持性是库的回答。

真实 CLI：

```text

  contract: rust_widgets 3.0.0 (revision 17771641...), manifest protocol 4,
  built for desktop aarch64-apple-darwin, target desktop, capture v1

```

测试：

```text

cargo test --bin rustage app::run::design::              1 passed
```

未覆盖：库不提供设计师分类，分类暂用 `WidgetKind::css_name()`；manifest `commands` 未捕获
（属 T13.03/T13.04 的命令契约）；desktop 构建下 `Unavailable` 只能在 stripped profile 触发。

## 3. T13.03：事件声明来自 EventSchema

文件：

- `src/app/data/events.rs`
- `src/app/run/workbench_events.rs`
- `src/app/run/data_events.rs`

实现：

- `EventDecl.declared` 保存库的 `PropertyValueKind` + `EventPayloadShape`；原有 `payload`
  仍是一次校验能检查的字段。
- `Registry::from_event_schemas` / `from_manifest` / `from_control`：未知控件返回错误，
  不返回空注册表；载荷字段从 shape 派生（Scalar/Optional → `value`，tuple → `value.0..n`）。
- 库声明了但数据词汇不能表达的形状（list/mixed/color/rect/icon/records）保留原声明，
  `fire` 明确拒绝，不用空字段列表冒充匹配。
- `--events control:<name>` 加载真实声明；`event:`/`field:` 只核对，不能新增声明。
- 声明/接线/触发三种事实保持分离；未接线触发仍报 “no handler is wired”。

测试：

```text
cargo test --bin rustage app::data::events::          21 passed
cargo test --bin rustage app::run::workbench_events:: 10 passed
cargo test --bin rustage app::run::data_events::       3 passed
cargo test --bin rustage events                        41 passed
```

真实订阅缺口：`EventSignalRef` 需要已挂载 `Widget`，`EventSignalBinder` 还需要宿主的
`Arc<CustomSignalHub>`；Events 面板两者都没有，因此 `Wiring` 仍是接线记录，不声称已连接
真实槽。真实订阅留给 T13.04/T14.02。
