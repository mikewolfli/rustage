## 1. T10.01/T10.08：库布局引擎

文件：

- `src/app/layout/layout_plan.rs`
- `src/app/run/layout.rs`

实现：

- `LibraryEngine`：
  - `Row` → `FlexLayout(FlexDirection::Row)`
  - `Column` → `FlexLayout(FlexDirection::Column)`
  - `Stack` → `StackLayout(StackMode::All)`
  - `Grid` → `GridLayout`（row-major，显式列数）
  - `Free` → `AbsoluteLayout`
- `Selection` 明确记录所用库布局类型。
- 新增 `Context { layout_scale, font_scale, min_touch }` 与
  `Engine::layout_with_context`，直接调用 `Layout::arrange_with_context`。
- `LayoutInput::available` 作为子节点 preferred size；`grow` 映射为库 stretch。
  容器尺寸显式给出或由子节点测量，所有 child box 均来自库。
- `--layout-plan` 的 `preview` 与 `generation` 都走 `LibraryEngine`；`box:` 仍接受但
  显示为调用方输入且不被引擎使用。
- `--layout-probe`：`box:` 是宿主渲染侧对比值；`probe-box:` 被明确忽略；差异报告
  `preview ... but probe ...`。
- 新增 `layout:<kind>`、`container:<w>,<h>`、`gap:<n>`、`padding:<n>` 操作。

测试：

```text
cargo test --bin rustage app::layout::     82 passed
cargo test --bin rustage app::run::layout:: 2 passed
```

真实 CLI：

- 同一输入下 preview/generation 都报 `FlexLayout` 且 box 相同；
- `layout:row container:100,20 constraint:2:grow:explicit` 得到节点 2 宽度 90；
- probe 差异同时打印 preview 与 probe 两个值。

**仍未完成**：约束仍只有 `grow` 翻译；min/max/preferred/gap/margin 值、free x/y、
grid 每节点 cell、布局诊断属于 T10.03/T10.04。

## 2. T14.01：真实预览会话

文件：

- `src/app/preview/preview_service.rs`
- `src/app/preview/state_keep.rs`
- `src/app/run/preview.rs`

实现：

- `Preview` 持有 `Option<ViewEngine>` 与最后成功挂载的 `Document`。
- `mount_view` 用 `NodeId` 作为每个节点的 key 调 `ViewEngine::mount`；记录 engine generation。
- `update_view` 调 `ViewEngine::update`；未变控件不重建，焦点/滚动由 patch preservation 保留；
  更新计数与 generation 推进。
- `stop` 注销本会话创建的全部控件，再 drop engine；`runtime::is_mounted` 测试确认无残留。
- 更新失败（root replacement 或控件创建失败）时，在同一 engine 上重建上一份好文档，
  不把失败计为一次更新。
- 焦点通过 `widget::runtime::focused_widget`/`focus_widget` 按 `NodeId` 捕获/恢复；
  滚动/选择明确记为 `state_keep::SCROLL_GAP`，不假装已恢复。
- CLI preview 新增 `mount`、`update`、`capture`、`restore`、`gap` 操作。

测试：

```text
cargo test --bin rustage app::preview   111 passed
```

**仍未完成**：滚动/选择无通用库读写；`hot_update` 的编辑分类到 patch 映射未接；
真实窗口/UI 线程接线仍是宿主工作。

## 3. T15.02：双产物生成与 `--check`

文件：

- `src/app/generate/pipeline.rs`
- `src/app/run/generate.rs`
- `src/cli/command/generate.rs`

实现：

- `run_dual` 从同一输入生成：
  - `src/generated/ui_default.rs`（Default：desktop/tablet/mobile）
  - `src/generated/ui_stripped.rs`（Stripped：mini/embedded）
- 每份产物带库 `GENERATED_MARKER` 与 `// rustage generator 0.1.0 (format v2)`。
- `Finding` 将库报告映射为五类 gap：
  `unsupported`、`capacity-overflow`、`cross-profile`、`unresolvable-event`、
  `incompatible-wire`；cross-profile 只警告，其余阻断。
- CLI：`--generate project:<file> root:<dir> dual check`
  - 无 `check`：写两份产物；有阻断 gap 时拒绝写；
  - `check`：只在内存比较，不写；
  - 退出码：0 相同/已写、1 stale/缺失、2 拒绝/gap。
- 单目标 `--generate` 行为保留；相对产物路径来自上游 `ArtifactPaths::path_for`。

测试：

```text
cargo test --bin rustage app::generate::      58 passed
cargo test --bin rustage app::run::generate::  4 passed
```

真实 CLI：

```text
missing files -> 1
written, then check -> 0
edited file -> 1
unknown control -> 2
upstream example with stripped wire gap -> 2
```

**仍未完成**：1/2 退出码通过进程退出实现，因为 `src/app/run/mod.rs` 的 dispatcher
只区分 true/false；precheck 拒绝不是库 `GenerationGap`；源码 span（T15.03）与
merge 写入（T15.04）仍未接。
