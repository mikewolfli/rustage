## 1. 关键改动说明

### 1.1 可诊断性（原则 #22）

**join 失败不再等于“输出静默停止”。** 终端、子进程、LSP 和后台执行器的 reader/worker 线程在
panic 后 `join()` 返回 `Err`。此前 `let _ =` 把这一事实丢掉，终端看起来只是“没有更多输出”。现在
各模块用 `host::log` 的 `Warn` 记录“哪一个 reader/worker 失败、丢了什么”；线程仍然不被重新拉起，
但失败会在日志里可见。

**清理失败不再伪装成成功。**

- `build` 的 `stop` 失败：错误文本同时包含原始失败与“程序可能仍在运行”。
- 逻辑 generations 的 `DuplexProcess::finish`：`Termination::SignalFailed` 记录进程名与原因；其余
  `Stopped`/`Killed`/`AlreadyExited` 是事实，不需要告警。
- 扩展启动探针的 `terminate`：超时错误里附带停止失败原因。
- 构建执行器 `shutdown`：`ShutdownReport::is_clean()==false` 时记录未在宽限期停止的任务。
- `release::sbom`：`Sbom::add` 从 `let _ =` 改为 `Result` 传播；`release` 命令在写文件前报告拒绝的
  组件，避免“合规工件少了一个组件却仍写出”。

### 1.2 画布热路径（原则 #23）

改动前，每个指针事件都会：

1. 由 `CanvasState::nodes()` 对每个节点线性 `find` 矩形（O(n²)）；
2. 为每个节点 `to_owned()` 名字并构造完整 `Vec`；
3. 之后才检查 `canvas_scheduled`，所以去重没有省掉步骤 1–2；
4. 绘制帧再 `snapshot.clone()` 整个 `Vec<String>`。

改动后：

- `CanvasState` 的矩形表是 `BTreeMap<NodeId, Rect>`，`rect()` 是一次查找；`nodes()` 沿 scene 的
  绘制顺序单遍产出。
- `CanvasState::revision()` 只在改名、选择变化、删除时递增。`sync_canvas` 在 revision 未变时复用
  `Arc<[CanvasNode]>`，拖拽只更新 marquee。
- `CanvasSnapshot` 的节点表共享为 `Arc`，调度帧只克隆 `Arc<CanvasSnapshot>`；字体是进程级
  `OnceLock`，`[locked]` 后缀在快照期拼好，绘制循环不再逐节点分配字符串。

这些改动不改变点击/命中的语义：`hit()` 仍由 `Scene` 决定，`nodes()` 仍只返回可见节点。

### 1.3 服务门与静默 UI 失败

`workbench_gui` 原先先 `let _ = panels.register(...)`、`let _ = panels.show(id)`，再把
`services` 集合用 `let _ = &services;` 丢弃。现在：

- 面板注册/显示/隐藏失败写入 `app::run::workbench-gui` 的 Warn；
- `show_panel_if_available` 用 `PanelSpec::is_available(&services)` 决定是否显示；服务缺失时面板
  仍占用 id 与默认布局，但不出现，并记录哪个 service 不可用；
- 标签激活、布局应用、菜单栏挂载、初始选择失败同样记录，不再 `let _ =`。

### 1.4 死代码与注释

- `HostRegistry::prompt()` 无消费者，删除；真实信任路径是 `PermissionService::trust` +
  `ProjectSession::decide`，`--trust` 已接通。
- `TrustState` 的“仅测试构造”注释已过时，改为说明 `trust_project()` 与 `--trust`。
- Inspector 的 `accepted_tokens()`/`contract_default()` 不再是 `#[allow(dead_code)]` 死代码：
  它们现在出现在 Inspector 的行里（`default: …`、`accepted: a | b`），枚举属性不需要用户猜 token。

1. 所有代码实现、逻辑、接口、数据结构，**只能以Plan文档写的内容为准**。Plan没写明的功能、约束、参数，一律不要自行脑补、新增功能、擅自优化、私自修改设计。
