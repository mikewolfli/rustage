## 1. 关键改动说明

### 1.1 升级到 rust-widgets 3.2.0 / 3.2.1（原则 #24/#34）

固定修订从 `d44ca0e`（3.1.0）改为 `69f8ba72`（3.2.0），feedback C-8/C-9 修复后再升级到
`be69fa2b`（3.2.1），`rust-widgets-suites` 同步（3.2.1）。两次升级后 `cargo check --bin rustage` 均通过；
3.2.0 的适配点是 `DesignerManifest::category`（上游已关闭 blue21 W-4.1 / feedback F-8），3.2.1 无宿主适配点（纯追加 API）。

### 1.2 W-2f：自研 `SceneIndex` 退役

3.2.0 公开 `TreeIndexBuilder<Id>`，因此 `src/app/canvas/scene.rs` 不再维护 path/key/duplicate-key 的第二套规则：

- `pub type SceneIndex = TreeIndex<NodeId>`；
- `build_index` 只做一次 DFS，把 `(path, node, key)` 交给 `TreeIndexBuilder`；
- 上游负责兄弟作用域 key、重复 key 归零并报告、路径快照语义；
- 原有 10 个场景/索引测试全部通过，未改测试断言。

### 1.3 W-2d：Inspector 与 Data 改用上游 `PropertyGrid`

- Inspector 面板：`mount_widget_by_name("property_grid", ...)`，行依次为节点、类型/契约、可编辑属性、主题、默认值、可接受值、检查结果；`cell_changed(row, text)` 只有在可编辑行（第 3 行）才进入契约 schema 校验，再写入模型。
- Clear 只清可编辑单元格（模型有效值不变）；Reset/Values/Theme 仍是命令按钮，走原模型；Values 的输出作为只读行追加到同一网格。
- Data 面板：网格第 1 行为只读数据集行，之后每个字段一行；提交即原 Apply，未通过 schema 的文本保留并显示拒绝原因；诊断行（`problem:`/`sample refused:`）保留为只读行。
- 两个面板不再创建 ListBox；`PropertyGrid` 的格子提交是唯一的编辑入口。

### 1.4 W-2a：Escape 关闭命令面板

3.2.0 的 `CommandPalette` 新增 `dismissed`（feedback F-12 已关闭）。宿主订阅该信号并调用现有 `close_palette`，因此“Escape 清空查询并关闭”恢复为与自拼装版本一致；`focus_lost` 仍是第二条关闭路径。

### 1.5 L-1/L-4：JSON 语言包是运行期数据，不是编译产物

- 词条位置：`language/en.json`、`language/zh-Hans.json`；共 169 条，其中 96 条是本轮新增的窗口标签（面板、菜单、工具栏、按钮、状态、错误、注释行）。
- 加载顺序（`vocabulary::language_dir`）：`RUSTAGE_LANGUAGE_DIR` → 工作目录 `language/` → 可执行文件旁 `language/`。**没有 `include_str!`**，打包产物需随附该目录；找不到或解析失败会记录 Warn，而不是静默回退。
- `zh_hans.rs` 的 73 条常量表删除；`vocabulary::pack` 从 JSON 读取并缓存；英文也来自 `en.json`，测试会把它与注册表派生词表逐键比对，防止两份数据漂移。
- CLI（`Catalog`）与 GUI（上游全局 `I18nManager`）读同一目录：`catalog::install_global()` 用 `init_with_options { preload_dir }` 一次装载全部语言文件，再 `set_language`。
- 标签归一口径：文件名、JSON 的 `language`、管理器当前语言三者相同（`en` / `zh-Hans`），不再混用上游内部的 `zh-cn` 干。

### 1.6 L-4：GUI 文案、热加载与重刷

- 菜单：改为遍历注册表菜单树（`commands::menu::built_in`），叶子键为 `menu.<menu>.item.<command>`；File 追加窗口自有 Quit，View 追加面板开关（窗口自有动作）。窗口 API 没有嵌套菜单，View 的 Panels 子菜单被扁平化到 View 下，键仍保留 `menu.view.submenu.panels.item.*`。
- 工具栏：item 标签使用 `ui.toolbar.*` / `ui.panel.*`；热加载时 `ToolBar::clear` + 重新插入标签。
- 面板标题、菜单标题、菜单项、按钮、状态行、检查器/数据行、错误前缀、占位符均走 `tr`/`tr_args`。
- 热加载：启动时 `enable_global_hot_reload(language/)`；主线程 250ms 轮询 `pump_hot_reload()`，有事件时 `retranslate` 重设 remembered 控件文本并刷新状态栏。菜单/面板标题分别通过 `Menu::set_title`、`GroupBox::set_title` 更新。

### 1.7 T05.02：菜单不再是与注册表脱节的第二份清单

File/Edit/View/Build 四个菜单直接来自 `commands::menu::built_in()`，每个叶子绑定其命令 id；窗口把 `command:<id>` 交给 `run_command`：
`view.palette` 打开命令面板，`view.welcome` 切欢迎模式，`panel.outline`/`panel.inspector` 切换面板，`panel.close`/`keys.show`/`tree.activate` 给出模型级结果，未实现的命令诚实报告“resolved; no handler”。
菜单组从 4 组增加到 6 组（File/Edit/View/Build + Layout/Editor），消除了 GUI 菜单与已编目菜单树各写一份的分叉（blue21 L-2）。

### 1.8 T24.10：键提取与伪本地化

- `tools::extract_keys` 把多行/单行 `tr`/`tr_args` 调用归一后读取键，并补充扫描 `ui.*` 字面量（窗口在循环里通过变量传键）；排除文件名、前缀碎片和 Windows 扩展名列表等误报。
- `rustage --locale-audit src`：报告“代码用到但词表未识别”的键（失败）和“词表有但窗口未用”的 UI 键（仅报告）。当前审计为 349 个源文件、98 个使用键、166 个识别键，0 missing / 0 unused。

## 7. 关键改动说明

### 7.1 I-10：配置不生效时不再假装生效

`connect()` 原先总是开一条明文 TCP，却把 `TlsPolicy` 的“必须校验”留在 permit 里。现在：

- `ResolvedTls::is_carried()` 恒为 `false`，明确表示“策略已解析，但本构建的传输不承载它”；
- `NetworkPermit::transport()` 回答 `plain TCP; this build has no TLS client`；
- 以下三种情况在开 socket 之前拒绝，并给出原因：解析到非回环地址、配置了附加信任锚、配置了客户端证书；
- 回环地址 + 默认锚点仍可明文连接，这是 `readiness` 的本机探针所需，且不会对外发送任何内容。

这不是“新增 TLS 客户端”，而是让能力的缺失可查询、可诊断（原则 #22/#37）。

### 7.2 T23.11：授权调用真正到达 MCP server

新增 `app::ai::mcp`：

- `McpServer::start(spec, timeout, permit)` 只经由 `host::subprocess::DuplexProcess` 启动子进程（需要 `ExecutionPermit`，独立进程组与会话标记）；
- `initialize()` 发送 `initialize` 并读取服务器的 `result`，随后发送 `notifications/initialized`；
- `call_tool(call, decision)` 先看决策：`Refused` 一个字节都不发；未完成 handshake 也拒绝；参数不是 JSON 对象时 `Unsendable`；
- 请求体与 `--ai tool-mcp` 的预览共用 `ToolCall::mcp_params()`，避免“预览一份、发送另一份”（原则 #59）；
- 等待有上限；服务器的通知被跳过，服务器主动请求（本客户端不支持）显式报错，JSON-RPC `error` 原样带出，绝不折叠成空结果；
- `shutdown(grace)` 关闭 stdin、等待并升级，返回 `Termination` 作为证据。

`ToolCall::mcp_json()` 从 `String` 改为 `Result<String, String>`：MCP 的 `arguments` 必须是对象，旧实现把任意文本塞成字符串，服务器不会把它当参数。`--ai tool-mcp` 现在对非对象参数报错而不是输出一个不可用的请求体。

CLI 新增 `mcp-server:<program>`、`mcp-arg:<arg>`、`mcp-start`、`mcp-tools`、`mcp-call`、`mcp-stop`；程序名只是登记，`mcp-start` 才启动。

`mcp-tools` 调用 `tools/list` 并把服务器的 `result` 原样输出：宿主不维护第二份工具名表，也不把分页结果伪装成完整清单（服务器给 `nextCursor` 就是它自己的声明）。

### 7.3 T23.12：会话 journal

新增 `app::ai::journal`：

- `Journal` 保存角色/模型/预算/工具白名单/凭据引用/用量账本、候选与 handoff；
- `save()` 先读磁盘上的 `seq`，与内存副本不一致就拒绝并同时报出两个序号；文件不存在而副本 `seq != 0` 同样拒绝；
- 写入走 `project::record::json::write_atomically`（临时文件 + rename），中断不会留下半份 journal；
- 读取时每个候选都经 `Candidate::new_at` 重建并比对存储的摘要，改动过变更内容的文件会被拒绝；
- 未知 format `version`、未知字段形状、未知角色/验证/结局都报错，不猜测。

CLI 新增 `session-save:<file>`、`session-load:<file>`；保存自动带上当前候选与 handoff，加载恢复最后的候选与 handoff（revision 冲突仍由 `handoff-check` 判定）。

### 7.4 T05.08：三平台快捷键一致性

- `shortcuts::Platform { MacOs, Windows, Linux }`：主修饰键 macOS=`Cmd`、其余=`Ctrl`；`Platform::keymap()` 把同一张默认表改写成该平台的键位；
- `audit::audit_platform()` 在完整清单审计之上增加规则：非 macOS 不得用 `Cmd`、macOS 不得用 `Ctrl`、带命令修饰键的键必须包含平台主修饰键；
- `--audit` 逐平台输出 `platform macos (Cmd): clean` 等三行，任一平台有问题都会让命令失败；
- 测试同时验证“把默认表原样喂给 macOS 会报错”，确保检查本身不是空转。

## 12. 关键改动说明

### 12.1 控件库面板（blue21 W-4）

- 行来自 `Catalog::from_host_contract("desktop")`，按 `category` 排序并带类别前缀，**不是手写清单**；契约读取失败时记录 Warn 且不注册 `widget-catalog` 服务，面板保持隐藏而不是空壳（T04.02 的服务门）。
- `CanvasState::insert_widget(control, name, property)`：父节点取“选区及其祖先中最近的 Container”，否则取第一个根 Container；名字冲突时加序号；位置是随文档大小变化的级联偏移（同文档可复现）；插入后 `revision`/`content_revision` 同时递增。
- 条目属性优先 `text`、再 `title`、否则第一个已发布属性；**没有属性就拒绝**，不编造属性名（Inspector 不会得到一个假契约）。
- 激活使用 `item_activated`（回车/双击），不用 `item_selected`：方向键浏览不应每按一次就插入一个控件。
- 收藏持久化在宿主数据目录的 `widget-favorites.json`（原子写入）。文件不存在是“还没收藏”，读取失败不会假装空并覆盖；未来版本拒绝读取。行右键 `Toggle Favorite`，行前缀 `*` 表示已收藏，`Catalog::search` 会把收藏提前。
- 面板顶部是检索框：空查询按 `category` 列出全部，非空查询调用 `Catalog::search`（沿用库的模糊排序与收藏权重），窗口不写第二套过滤。
- 列表行只存 `contract id`，激活时回查 `Catalog`，因此“显示的行”和“插入的契约”不会因为两份数据结构而漂移。
- **锁内不得写字段文本**：检索框的 `text_changed` 订阅者会锁同一个 `Gui`，所以任何程序化 `set_widget_text` 必须放到下一轮主循环；smoke 因此直接调用 `filter_widgets`。这不是测试专用注意事项，任何新控件带“变更即回调”的信号时都适用。
- 插入成功后复用 `select_node`，画布、大纲、Inspector 一次同步；失败把原因写进状态栏与 Messages，不只进日志。
- 账目：`panel.widgets` 的 host id 改为 `widgets`，GUI 启动从 “6 shown / 33 missing” 变为 “7 shown / 32 missing”。

### 12.2 计划菜单项

`Item::Planned` 仍在 `commands::menu` 里作为“哪个任务会补这个入口”的台账，但窗口不再把它画成菜单项：本修订的原生菜单没有启用/禁用开关，画出来就是一个点了只得到 “no handler” 的启用项，正是 T05.08 禁止的悬空已启用菜单。`--app-menu` 仍输出计划项及其任务。

### 12.3 画布的父子导航与删除

`CanvasState::first_child` 返回大纲顺序里的第一个子节点；场景右键菜单新增 `ui.context.select-child`。没有子节点时报告 `{name} 没有子节点`，不把点击当成成功。

删除是上一轮自己标记的阻塞项，本轮先补前置：`PropertyState::clear()` 把 Inspector 置为“无选中”（`count() == 0`，`apply` 以 `no node is selected` 拒绝），`refresh_inspector` 在空选中时只画一行 `no selection`。随后场景右键新增 Delete：删除整棵子树、移除场景实例与矩形、清理选中集与契约，并让 Inspector 进入无选中状态；空画布点击也走同一复位。

复制是就地 Duplicate：`CanvasState::duplicate` 用 `Tree::copy` 的 pre-order 对应关系，把源子树的矩形（偏移 16px）、契约、隐藏/锁定状态逐节点复制到新 id，根节点取唯一名（`Demo` → `Demo copy`），并在可选时选中副本。它没有走系统剪贴板，因此不冒充 T05.06 的跨工程粘贴。

**大纲重选竞态**：`list_box_set_current_index` 同步发 `item_selected`，而删除前排队的大纲重建可能在新选择清空后才执行，于是“模型同步”被当成“用户点击”，重新选中旧节点（smoke 里表现为删除后 700ms 又选中 `button 2`）。现在程序化同步期间置 `Gui::outline_syncing`，订阅者在窗口内直接返回；无选中时不再把当前行指向末行，而是 `ListBox::clear_selection`。

**层级顺序**：`Scene` 新增 `raise_one`/`lower_one`/`lower`（置底），`CanvasState` 同步包装。右键菜单原来的 “Bring forward”（中文“上移一层”）实际调用的是置顶，名称与行为不符；现在拆为 Bring to Front / Bring Forward / Send Backward / Send to Back 四项，各对应一个真实操作。

**包装为容器**：`CanvasState::wrap_in_container` 在原父节点下新建 `Container`，把节点重挂进去，矩形为节点外 8 单位，契约沿用演示场景的容器约定 `panel.title`。`Scene::place_below` 把新容器直接放在被包节点之后（因此节点仍是命中），而不是把容器放到整个画布最底层。包装失败时会回滚树、场景、矩形与契约，不留下半成品；新容器被选中，所以下一次控件库插入会落在它里面。

**移出容器**：`CanvasState::move_out_of_container` 是包装的逆操作——重挂到祖父，容器保留（可能还装着其他节点），节点矩形不动；根节点会以“already at the root”拒绝。smoke 在包装后重新选中子节点并调用它，计数保持 8，随后复制/删除子节点。

**快捷键路由**：GUI 至今只能通过 `keys.show` 列出键位，无法响应按键；`WindowHandle` 没有窗口级 `on_key_press`/`set_key_handler`，按键只交给焦点控件。这是上游接缝缺口，已写入 `feedback-20261101.md` C-10（P1），不拿控件级信号拼一个假装全局的快捷键系统。

**重命名**：场景右键 `Rename` 挂载库自带的 `InputDialog`（模态）。对话框信号运行在 runtime 的事件分发里，**不能锁 `Gui`**（smoke 就是在持锁状态下发 Enter 的），因此它们只写 `Gui::rename_slot`；50ms 轮询在主循环上取出答案、注销对话框并应用。空名字拒绝；成功后 `property.clear()` 再 `select_node`，否则 Inspector 的 Reset 会恢复旧名字。

**复制/粘贴**：`CanvasState::copy_subtree` 只复制结构（kind/name/矩形/契约/隐藏与锁定），`paste_clipboard` 在最近容器内以新 id 重建，粘贴前校验形状（单根、不跳层），失败不留半棵树。这是**应用内场景剪贴板**，不写系统剪贴板；T05.06 仍负责 OS MIME 载荷与跨工程 ID 重分配。命名会把已有序号继续下去（`button 2` 粘贴为 `button 3`，不再堆成 `button 2 2`）。粘贴在无选中时也可用，落到第一个根容器。

**移入已有容器**：拖拽需要 `Canvas` 作为 `DropTarget`，上游没有这个接缝（feedback C-11），所以菜单提供确定性的 `Move Into Container Above`：目标就是上一层兄弟节点，它必须是容器，否则报出它的名字并拒绝。不跳到“某个其他容器”替用户猜测。

仍未接入：复制/粘贴到系统剪贴板（T05.06）、控件库拖拽插入（等 C-11）、提取组件、事件与源码跳转。
