## 2. 批次 A

### 2.1 H-1：预览回收改用引擎报告

`src/app/preview/preview_service.rs`：

- 删除 `prune_controls(document)` 的 tree-index 路径反推，改为 `release_controls(removed)`：
  只注销 `view_ids` 里确实由本会话创建、且报告说已销毁的 id。
- `mount_view` 用 `ApplyReport::removed_ids`；`update_view`/`restore_document` 用
  `DiffReport::removed`。
- 现有测试 `an_update_releases_the_control_of_a_removed_node` 保持通过，证明“移除节点后控件
  不再挂载且从账本消失”。

### 2.2 H-2：工具栏原地改文本

`src/app/run/workbench_gui.rs::retranslate`：删除 `bar.clear()` + 逐项重插，改为按索引
`ToolBar::set_item_text`。action id、选中/禁用状态不再因语言热重载重建。

### 2.3 H-3：View → Panels 嵌套子菜单

`workbench_gui.rs` 的菜单装配：

- `Item::Submenu` 改用 `MenuHandle::new_submenu` 创建真实子菜单；
- 订阅父菜单的 `submenu_requested`，用 `row_rect(branch)` 定位并 `open_at` 子弹层；
- window-only 的 7 个面板开关移入 registry 的 `View > Panels` 子菜单，不再平铺在 View 下；
- 子菜单标题登记为 `LabelKind::MenuTitle`，热重载可刷新。

### 2.4 H-4：Inspector mixed 行

`GridRow` 增加 `mixed` 与 `kind`；`set_property_rows` 对 mixed 行使用
`PropertyItem::mixed(name).with_placeholder(tr("ui.placeholder.mixed"))`。删除原先额外的
“selection = mixed”只读拼接行；混合行本身可编辑，提交后由 `PropertyState` 应用到全部选中节点。

### 2.5 H-6：主题单次快照

`src/app/shell/toolbar.rs` 的 `backdrop()`/`accent_surface()` 改用
`theme::theme_snapshot()` 一次取锁；删除“同一管理器取两次锁会死锁”的绕行注释。行为保持不变：
仍先看 high-contrast 强制色对，否则使用当前主题的 background/primary。

### 2.6 H-7：编辑器坐标换算

`src/app/editor/adapter.rs` 增加 `offset_of`/`position_of`，委托给 `CodeEditor` 的
`CodeEditorDocument` 共享文档实现；`src/app/run/editor.rs` 的 `position_at`/`offset_of`/
`positions_of` 只保留宿主的两条拒绝规则（越过末尾、落在字符中间），换算走适配器。
纯 `&str`（生成器、DAP 列语义、构建诊断）与调试映射的独立换算未动。

### 2.7 H-8：占位符填充

`src/app/locale/catalog.rs::Catalog::fill` 删除自写 `substitute`，改用
`rust_widgets::i18n::interpolate_into`。缺失键仍答 `"<key> (has no text)"`。

### 2.8 H-12：schema 的 step/places

`src/app/style/property_editor.rs`：

- `Bounds` 增加 `step`/`places`，分别来自 `Constraint::Range.step` 与
  `Constraint::Precision.places`；designer manifest 的 `"range"`/`"precision"` 行同样读取。
- `PropertyType::Number` 增加 `step`/`places`，`Integer` 增加 `step`；`render()` 显示它们。
- `PropertyState::number_bounds()` 暴露 `(min,max,step)`；Inspector 的可编辑行带
  `PropertyItem::with_bounds`，`PropertyGrid` 的数值提交/步进因此使用控件自己的契约。

### 2.9 H-15：URL 打开

`src/host/open_url.rs`：

- 新增 `PlatformOpener`，生产路径调用
  `rust_widgets::platform::platform_facts().open_external(...)`；
- `OpenOutcome` 新增 `HandedOff { target }`，诚实表示“已交给平台，平台处理器拥有后续生命周期”；
- 删除宿主的 `program_for` 平台映射、`for_this_platform` 程序探测、`is_on_path`/`PATH`+
  `PATHEXT` 查找；
- `ProgramOpener` 保留为 **`#[cfg(test)]`** 受控处理器 seam，仅用于验证退出码/超时/ETXTBSY；
- `host/readiness.rs` 改用平台能力标志，不再报告某个程序是否在 PATH。

宿主策略 `accept()` 保留：空目标、`-` 开头、控制字符、无 scheme、非 `http/https/file`、
不存在的路径均在交给平台前拒绝。

### 2.10 H-16：系统语言

`src/host/locale.rs::Language::system()` 改为调用
`rust_widgets::platform::platform_facts().system_locale()`，再走宿主的 `from_locale`；
`zh-Hant`/`zh-TW`/`zh-HK`/`zh-MO` 仍被拒绝（宿主只随附简体中文包）。

### 2.11 H-25：主题登记不激活

`src/app/style/design_tokens.rs::load_theme_file` 改用 `ThemeManager::load_theme_named`，
再用 `get_theme(&name)` 读取文件内主题名对应的主题；不再“先激活再读取”。

### 2.12 H-17：FlexLayout max 约束

`src/app/layout/layout_plan.rs` 在 `FlexLayout` 预览前，用 `items_mut()` 把
`ChildInfo.hints.{width,height}.max` 回填到 `FlexItem::max_size`；`u32::MAX` 保持 `0`（无上限）。

### 2.13 H-13 / H-14：复核已满足

- **H-13**：全仓 `grep register_property_defaults` 在宿主 `src/` 零命中；宿主只在
  `src/app/contract.rs` 构建一次 factory 并调用一次 `rust_widgets_suites::install`，没有二次注册。
- **H-14**：`workbench_gui.rs::tab_at` 已调用 `TabWidgetHandle::tab_index_at`，手写命中计算不存在。

## 3. 批次 B（可立即落地部分）

### 3.1 H-18：Inspector 颜色族

- `PropertyState::is_colour()` 从 schema 判断颜色属性；Inspector 行使用
  `PropertyItemKind::Color`。
- `workbench_gui.rs` 新建一个隐藏的 overlay 面板，容纳上游四件套：
  `ColorPicker`（主编辑）、`ColorWell`（当前值）、`ColorHistory`（最近颜色）、`Swatch`（预设）。
- `PropertyGrid::color_picker_requested(row, seed)` → 打开 overlay 并以当前 hex 初始化；
  picker `color_committed` → `apply_property`；history 选中与 swatch 激活同样提交；
  picker `canceled` → 关闭 overlay。
- hex 仍可手输：grid 的 `Color` kind 保留文本编辑回退，提交走同一 `apply_property`。
- 新增界面文案键 `ui.canvas`（中英各一条，供 tooltip 使用）。

### 3.2 H-20：tooltip 管线

- 启动时通过控件后端创建 `TooltipManager` 作为窗口子控件（初始 1×1 且隐藏），运行时会把
  hover 与控件的 `tooltip` 属性转发给它；
- 给 Inspector/Data/Messages/Outline/Widgets/Events/Pages 与画布设置控件级 tooltip；
- `schedule_tooltips` 每 100 ms 调 `tick`；仅在气泡可见时把管理器几何移到 hovered 控件附近
  并显示，隐藏时收回——避免一个整窗 overlay 拦截所有点击。条目级 tooltip（RW-62）仍不
  作为已完成项。

### 3.3 H-5：列表面板差异删插

`set_list_rows()`：列表相同直接返回；不同则从首个差异位置起 `remove_item` 后 `insert_item`。
替换了 Events/Pages/Messages/Outline/Widgets 五处 `clear_items + add_item` 全量重建。
上游仍无逐行 set text，因此文本变化的行是“删+插”，注释已如实说明。

### 3.4 H-11：生成报告展示 icon token

`src/app/generate/pipeline.rs::Outcome::render` 在 `icon_tokens` 非空时输出
`icons: N token(s): ...`。

### 3.5 H-19：画布拖拽 ghost

- 按下时用 `Drag::begin` 记录候选；越过阈值后注册全窗口 `DragGhostLayer`，用
  `CanvasTransform` 把节点矩形放到窗口坐标并 `begin`。
- 拖动期间的 Move/Release/Escape 由 overlay 自己处理；宿主的 `ghost_dropped` 接收最终点与
  “是否在画布外”，`ghost_cancelled` 接收取消。
- 落下时按命中容器（或父容器/根）`Drag::aim` + `Drag::release`；`Drop::Move` 经
  `CanvasState::move_node` 调用 `Tree::reparent_at`，失败带原因、不修改树。
- overlay 在结束信号返回后通过 `schedule_on_main` 注销，避免在信号发射栈里析构控件。
- 新增 `CanvasState::{tree,child_count,move_node}` 与单测
  `a_drag_move_reparents_without_moving_the_scene_rectangle`。

### 3.6 H-10：未接线信号

`Preview::unwired_events()` 对每个 live control 调用上游
`rust_widgets::signal::unwired_events(id)`：有未接线事件时列出事件名，库答 `None` 时写成
`wiring not observed`，不把未知当成功。预览命令的 `mount`/`update` 输出带 `unwired:` 行，
并新增 `unwired` 操作按需查询。

### 3.7 H-21：资产面板

- `panel.assets` 从“只有账目”变成真实面板：`src/app/shell/panels.rs` 的 host id 指向 `assets`，
  GUI 以 `Dock::Left` 注册并显示。
- 面板内是上游 `ImageGallery`；它自己持有 `ThumbnailCache`，缩略图条由缓存位图绘制。
  没有 raster fixture，因此用 `Image::from_raw(Rgba8…)` 生成 6 个渐变示例资产，
  使缩略图/缓存路径在新检出上真实运行，而不是一排占位框。

### 3.8 H-22/H-23：主题编辑器

- 新 `theme` 面板（`Dock::Right`，映射 `panel.styles`）：主题名 combo + Switch、度量档 combo、
  `BezierCurveEditor`、说明标签。
- 度量档：把 `Theme::metrics_profile` 写回当前主题并 `register_theme` + `set_theme`，
  控件的 `active_profile()` 随 revision 更新（H-23）。
- 动效曲线：把 `BezierCurveEditor::curve_changed` 的两组控制点写为
  `EasingFunction::cubic_bezier(x1,y1,x2,y2)` 并将 `Motion::curve` 置为 `Easing`（H-22）。
- 曲线编辑器在挂接信号前从当前主题 seeding，编辑本身就是可视化结果。

### 3.9 H-24：预览切主题 crossfade

- 主题面板的 Switch 调用 `ThemeManager::set_theme_faded_default`；管理器内部在
  reduced-motion 下把时长折为零。
- `schedule_theme_crossfade` 每 16 ms `tick_theme_crossfade(16)`，在跨渐变期间
  `invalidate_surface(window)`，结束后停止递归；不需要常驻帧循环。

## 9. 本轮做了什么

1. **控件能力核对（用户第 2 点）**：宿主目录不再只暴露属性/事件，补齐
   `category`（manifest protocol 5+）、`commands`（方法）、`children`（容器子项规则）、
   `alias_of`、属性的 `readable`/`writable`/`tokens`/`constraints`。
2. **新增两个核对入口**：`--catalog audit`（全量能力审计）与 `--catalog icons`（图标选择器清单）。
3. **H-34**：`--preview paint:<path>:<w>x<h>` 用上游真实绘制路径把已挂载树写成 SVG 帧。
4. **M-4 补证**：Linux `linux-native`（GTK3）构建与真实 1280x800 GUI 有界会话；
   4.0.0 五个 profile 的 `--lib` 在 Linux x86_64 全部构建通过。
5. **记录质量**：清除 `NOTARIZE_TIMEOUT`/`scratch`/`unused_mut`/`unused_import` 与两处 clippy
   `useless_format`；`cargo clippy --all-targets` 与 `cargo fmt --check` 均干净。
6. **i18n 修复**：把上一轮新增但未编目的 6 个 `ui.*` 键加入 `WINDOW_KEYS`，删除未使用的
   `ui.canvas`；中英语言包各 240 键并与 `entries()` 完全一致。
7. **文档回写**：support-matrix（JSON+MD）、verification.md B1–B3、roadmap §1.6.4、blue22 §7、
   blue21 复核段，新建 `docs/rw-feedback/feedback-20261103.md`。
8. **热路径小优化**：`set_list_rows` 先比较 `ListBox::items()` 的切片，再只在有差异时
   计算公共前缀；移除了每次面板同步都克隆全部行的分配。

## 10. 控件目录补全（widget_catalog.rs）

`WidgetDescriptor` 新增：

| 字段 | 来源 | 用途 |
|---|---|---|
| `commands: Vec<CommandSchema>` | `DesignerManifest.commands` | 方法名、签名、参数名/类型、arity、effect |
| `children: Vec<String>` | `DesignerManifest.children` | `*` = 任意可构造子项；受限容器列出规范名 |
| `alias_of: String` | `DesignerManifest.alias_of` | 别名行指向规范控件 |
| `category` | `DesignerManifest.category`（空则回退 kind 拼写） | 不再按名字猜分类 |

`PropertySchema` 新增 `readable`/`writable`/`tokens`/`constraints`；`render()` 会标出
`(read-only)`/`(write-only)`/`(no access)`、枚举 tokens 与约束。

新增访问器：`Catalog::commands(id)`、`Catalog::children(id)`、`Catalog::audit()`。
配合/伴生控件可先用 `--catalog category:companion` 找分组，再用 `schema:<id>` 看它的
属性、事件、方法；容器父子规则由 `audit` 输出。

`--catalog audit` 在本机 4.0.0 上的输出摘要：

```text

manifests: 242 read, 0 unread
```

其中 `dock_area`/`dock_widget`/`mdi_area` 声明受限子项，其余容器为 `*`；
`events: 221` 表示 21 个控件没有事件（11 个非容器在 audit 中逐条列出，其余是容器），
`color_history`/`group_avatar` 没有方法；均逐条列出而不是静默当作“齐全”。

3. **T05.02 与 §2.2 的优先级**：这是当前最大的两个剩余面，但都需要真实命令/面板内容；
   请确认下一轮是否优先做其中一项。
4. **控件面板的展示深度**：本轮把能力透传到目录模型与 `--catalog schema/audit`；GUI 的
   Widgets 面板仍是一行 `[category] name`，没有在行内展开属性/方法/事件计数。若要求在面板内
   直接看到“缺失能力”，需要定义面板空间与交互（例如选中后显示详情），Plan 未给出该形态。

## 16. 已知并行测试波动（非本轮引入）

并行跑 `cargo test --bin rustage` 时，三个依赖进程/端口/短超时的既有测试偶发失败；串行
（`--test-threads=1`）2720 项全绿。它们与本次目录/属性改动无关，按原则 #65 不静默当作通过：

| 测试 | 并行失败形态 | 方向 |
|---|---|---|
| `app::build::compile::tests::cancelling_kills_the_process_group_and_leaves_no_orphan` | 资源紧张时 `execute_with` 派生失败被 `expect("a run")` 抛出 | 与同文件已加的重试一致，可加派发重试 |
| `host::network::tests::a_port_nothing_listens_on_is_reported_with_the_address_it_tried` | 绑定后释放的端口被别的进程占住，`connect` 成功 | 保留监听器或用保留端口，避免释放后再连 |
| `project::lifecycle::session::tests::the_three_ways_a_toolchain_program_can_fail_are_told_apart` | 负载下 500 ms 超时先于“无输出”判定触发 | 增大该用例的超时或串行运行 |

本轮对 `a_submitted_build_belongs_to_an_owner_and_a_cancel_takes_its_process_down` 加了最多
三次的派发重试，并在失败时打印最终 `outcome`；其余两项未改，仅登记。

## 20. 并行子轮：`panel.inspection` + `panel.vcs` + 堆叠停靠（第五子轮）

### 20.1 并行方式

两个子代理各自只写一个文件（互不重叠），模块声明与 `src/app/run/workbench_gui.rs` 的接线由
主线程完成：

| 子任务 | 文件 | 内容 |
|---|---|---|
| 设计检查行 | `src/app/run/workbench_inspection.rs` | `rows(&CanvasState) -> Vec<String>`，用 `quality::DesignFacts::check` 跑真实检查 |
| 版本控制行 | `src/app/run/workbench_vcs.rs` | `rows(&Path) -> Vec<String>`，用 `vcs::Repository` 跑真实 `git` |

### 20.2 `panel.inspection`（F21）

- 从场景构造 `DesignFacts`：每个节点一条 `LayoutFact`，`frame` 是**父坐标**（子节点减父节点原点）；
  容量用 `capacity_from("desktop")`，读不到就不设上限（避免假溢出）；能力用
  `capability_from(WidgetFactory::shared(), "desktop", …)` 逐个控件名检查。
- 行内容就是 `DesignFacts::check` 返回的 `Problem::render()`；空结果由 GUI 补
  `ui.status.no-problems`，不是空面板。
- 三份测试：干净场景不 panic；超容量被报；子节点越界被报。

### 20.3 `panel.vcs`（F20）

覆盖 Plan 的五项：仓库/分支（`discover`/`status`）、修改与暂存（`status.entries` 的 index/worktree
列 + 汇总）、冲突（`conflicts`）、提交预览（`staged_diff` 的文件/块计数）、生成物来源（按文件自身的
region 标记分类 generated / handwritten / mixed）。

修正：初版把 `artifact::regions` 的“未标记字节也算 generated”直接用于任意文件，会把普通文本
误报为 generated。现改为**只有含 region 标记的文件才算生成物**，无标记文件不计数；三类分别统计。

### 20.4 堆叠停靠（同一槽位多面板）

底栏只有 5 个槽位，但新增面板不能无限加宽。引入 `Gui.panel_areas: BTreeMap<String, Area>`：
同一个 `Area` 槽位可以注册多个面板，**同一时刻只显示一个**。`toggle:<id>` 在显示一个面板前先把
同槽位的其他面板隐藏（`panels.hide`），因此不会出现两个面板叠画。

- `problems` 与 `inspection` 共用底栏槽 1；`environments` 与 `vcs` 共用槽 3。
- 两者默认隐藏（`Hidden`），通过 View → Panels 打开；打开时才做真实工作（检查/`git`），
  不拖慢启动。
- View → Panels 菜单补齐 `environments`、`targets`、`inspection`、`vcs`、`help`、`search`。

## 33. 剩余 7 个面板的原则分析（不新建假文档字段）

§30 的 ⚠️ 仍然成立。本轮按 principle #6/#9/#14/#22/#26/#54 逐项复核，结论是：**这 7 个面板缺的是
“被编辑的数据从哪来”，不是控件、不是域服务、也不是上游能力。** 在没有格式决策前，不能用内存
模型、临时 JSON 或空面板冒充完成。

| 面板 | roadmap §2.2 要求 | 已有真实模型 | 缺的输入 | 若强行实现的后果 | 推荐 |
|---|---|---|---|---|---|
| `panel.components` | 组件定义、实例、变体、覆盖、版本、目标兼容 | `component::definition`（Registry/Definition/Instance/Variant）、`variant::target_compatibility` | 组件定义在工程文档中的存放位置与字段 | 要么新建未版本化文件（违反 F1/Q6），要么只显示空注册表（#26） | 先定格式 v2 的组件段（含迁移），再接线 |
| `panel.layout` | 容器、约束、尺寸策略、边距、间距、布局诊断 | `layout::layout_plan`/`constraints`/`frames` | 节点上的约束输入 | `CanvasState` 只有矩形，面板只能显示位置，不能显示约束/策略/诊断 | 先让页面节点能表达约束（T10.03），再接线 |
| `panel.items` | 表列/树项/标签页、角色、数据源、选择与编辑规则 | `collection::content`（Collection/Column/Row/Cell/SourceContract） | 示例内容在页面 JSON 中的成员 | 页面格式 v1 的 `properties` 只接受标量（`PropertyValue` 无列表），新增成员即改格式 | 随格式 v2 的集合段落地 |
| `panel.states` | 状态、守卫、动作、过渡、目标能力与运行状态 | `data::state_machine`（Machine/Session/Transition/Answer） | 状态机在工程中的持久化位置 | 只做内存编辑会在重启后丢失，且与“文档模型唯一事实来源”冲突（#6） | 先定状态机段与版本迁移 |
| `panel.timeline` | 时间参数、播放/暂停、状态比较、不支持原因 | `style::motion`（Timeline/Control/Capability/Effect/Timing/Verdict） | CSS 过渡/动画的解析结果或文档中的 motion 列表 | 宿主没有 CSS transition 提取器；自造 motion 列表即第二事实来源（#59） | 先接 T11.06 的样式来源，再接面板 |
| `panel.outline` | 文件符号、生成区、节点关联、过滤和跳转 | `language::navigation`（Navigation/OutlineNode/Symbol）；本机有 `rust-analyzer` | GUI 里的真实工程文档会话（T07.01/T07.02） | 当前编辑器文档是演示文本；跳转无真实坐标，等于假定位（#22） | 等编辑器打开工程文件并持有 LSP 会话后接线 |
| `panel.ai` | coder/reviewer 工作区、share 候选/评审版本、授权上下文、工具/预算、接受/拒绝 | `ai::workflow`（Session/Context/Candidate/Handoff/ToolPolicy）+ `ai::journal` | 会话 journal 的路径或外部 agent 的启动入口 | 空 session 面板没有可观察行为；伪造候选违反 #26 | 先定 journal 路径（工程内 `.ai/`）或启用外部 agent |

**推荐顺序（不改变现有方向）：**
1. 先定 **工程格式 v2**：组件、状态机、集合、motion/断点字段 + 版本迁移（F1/Q6 已有规则）。
2. 再按 T12.01/T13.06/T27.01/T11.06 把模型接到页面文档，面板只读同一模型。
3. `panel.outline` 与编辑器/LSP 会话一起做（T07.01–T07.04），不单独造符号列表。
4. `panel.ai` 以 journal 路径为入口；未配置时面板显示“未配置”，不显示假 session。

在这些决策落地前，7 个面板保持 `Missing` 账目，`show_panel_if_available` 继续保证它们不会被
空壳占位。已接线的 33 个面板（14 shown + 19 hidden）不受影响；`panel.profiler`/`panel.memory`
继续按 roadmap 标为 `deferred`。

## 44. `panel.outline` 节点关联接线（T15.03 的 GUI 侧，第二十六子轮）

§43 确认 4.0.0 的 `GenerationReport.node_anchors` 已可读。本轮把面板的“节点关联”接上，并顺带修掉
一个由此暴露的主循环死锁。

### 44.1 面板的主体改为“生成物 + 锚点”

- `refresh_source`：先尝试 `generated_source(gui)` —— 读工程启动页 → `read_document` 翻译 →
  `pipeline::Input`（尺寸取窗口 1280×800，target `Default`）→ `pipeline::run`。生成在内存里完成，
  **不启动构建、不写文件**。
- 有生成时，面板大纲的主体是 `artifact::dual_outputs()[0]`（`src/generated/ui_default.rs`，路径来自
  上游 `ArtifactPaths`，不是宿主拼的字符串），文本就是刚才生成的源码；符号仍来自 `--lsp` 的
  `documentSymbol`。
- 没有生成（无工程、页面被 §41 拒绝、precheck 阻断）时退回“焦点编辑组缓冲”，并明确说明关联不可用。
- 跳转：目标文档不在编辑组时先 `Groups::open` + 写入该文本（生成物在本会话没有磁盘文件），再
  `CodeEditor::goto_line`。

### 44.2 关联规则

- 仅当 `Generated.source == 当前文本` 才使用锚点：锚点偏移属于另一次生成的文本时，映射到别的行
  比“没有映射”更糟。
- 符号：名字偏移落在某个节点表达式 `[offset, offset+length)` 内时，行尾加 ` node <id|key>`
  （`id` 优先，缺省用生成 key），取**最内层**（length 最小）的锚点。
- 节点行：每个锚点一行 `node <id|key> [<widget>] line:col`，可激活跳转到该节点的生成表达式。
  这就是“画布节点 ↔ 生成源码”的宿主侧导航，不需要再自造 key 扫描。
- 行示例（真实会话）：
  `node mapping: 1 anchor(s) from generating pages/main.json`、`nodes: 1`、
  `node 1 [window] 15:5`。

### 44.3 顺带修复：`sync_editors` 的同步信号死锁

打开第 4 个文档时 `TabWidget::set_current_index` 会**同步**发出 `current_changed`，其订阅者要锁
`Gui`；而 `sync_editors` 的调用方（快捷动作、列表回调、smoke）已经持有该锁 → 主循环永久阻塞。
本轮新增 `Gui::syncing_editors`（`Arc<AtomicBool>`）：

- `sync_editors` 进入时置位、返回前清零（函数内没有提前 return）；
- 订阅者**先读这个 Arc 再锁 `Gui`**（顺序关键：放在 `lock()` 之后仍然会死锁）。

这是既有代码的隐患，只是在“面板打开一个新文档”之前没有路径能触发它。

## 50. O-6：预览文档改为写时复制的分享向量（第三十二子轮）

### 50.1 改了什么

`app::preview::preview_service::Document` 的 `nodes` 从 `Vec<DocumentNode>` 改为

## 52. T05.02 第二切片：视图菜单与面板开关并入命令注册表（第三十四子轮）

### 52.1 四个窗口动作成为命令

|---|---|---|
| `view.split` | `group:split`（拆分当前编辑器组并显示同一文档） | Layout → Split Right；工具栏 |
| `view.next-group` | `group:next`（焦点移到下一组） | Editor → Next Group；工具栏 |
| `view.save-layout` | `layout:save`（写布局文件） | Layout → Save Layout；工具栏 |
| `view.reset-layout` | `layout:reset`（恢复启动布局） | Layout → Reset Layout；工具栏 |

### 52.2 `view.panel-show`：一条命令覆盖 §2.2 全部面板 ID

roadmap §3「视图 / 面板」要求“显示各面板……覆盖 §2.2 全部面板 ID”。
命令 ID 只能有一个点（`P-CMD-ID` 的 `域.动作`），所以写作 **`view.panel-show`**：

- 参数 `panel` 是 **必需的 `Choice`**，候选值直接取自
  `shell::panels::REQUIRED_PANELS`（42 个 `panel.*`，含 2 个 deferred），没有第二张面板表；
- 处理器 `show_panel` 只在 §2.2 账目里查 id：deferred 面板如实回答
  `ui.status.command-not-implemented` 并带上它的计划任务号（T21.09/T19.09），
  账目外的 id 回答 `ui.status.no-panel`；命中的面板映射到窗口 host id 后走同一个 `toggle_panel`；
- `toggle_panel` 由原来的 `apply_action("toggle:…")` 分支提取而来，行为不变
  （同一 dock 槽一次只显示一个面板，显示前先隐藏同槽兄弟）。

**菜单如何带参数**：`Item::Command` 只有命令 ID，不带参数；窗口的动作字符串因此允许
`command:<id>?name=value&…`。`apply_action` 解析成 `Call::with`，`run_call` 与键盘/面板走同一分派。
View → Panels 的每一项由 `panel_action(host)` 生成：账目内的面板得到
`command:view.panel-show?panel=panel.*`，账目外的内置 `messages` 保留窗口自己的 `toggle:`。
菜单同时补上此前缺失的 Outline / Inspector 两项（它们的 §2.2 id 是 `panel.objects` /
`panel.properties`），于是 41 个可显示面板全部有入口。

### 64.1 先解除先决条件：命令层拿得到窗口句柄

终端与测试的启动必须让后台轮询继续（`schedule_terminal_poll` / `schedule_tests_poll`
都要求 `&Arc<Mutex<Gui>>`），而命令分派只拿到 `&mut Gui`。本轮补上最小机制：

- `Gui` 新增 `self_weak: Weak<Mutex<Gui>>`，在 `Arc::new(Mutex::new(Gui { … }))` 之后立即
  `Arc::downgrade` 写入；用弱引用，避免 `Gui → Arc<Gui>` 的自引用环；
- 启动类命令在需要时 `self_weak.upgrade()` 得到同一个窗口句柄，再交给既有的轮询函数；
- 面板菜单原先在闭包里手动 `schedule_*_poll(&state)`，改由共用函数调度，避免“命令一次 +
  菜单一次”的双轮询。

## 82. O-10 关闭：`DocumentStore::apply` 改为借用变更集（第六十四子轮）

## 87. T05.02 第三十子轮：文件/工作区符号与定位当前文件（第六十九子轮）

### 87.1 一条符号链，三个入口

Plan §3.2「导航 / 打开」要求五项：快速打开文件、工程符号、当前文件符号、跳转行列、定位当前文件。
前两项已在 §84/§86 落地；本轮补齐后三项，并把符号查询接到已有的 LSP 会话上，而不是另起一套：

| 命令 ID | 实现 | 菜单 |
|---|---|---|
| `nav.file-symbol` | 提示框输入符号名 → `SourceOutline::file_symbol`（精确名优先，其次 `quick_open::fuzzy_score` 最佳）→ 光标落到符号名的 `(line, column)` | Navigate → Go to Symbol in File |
| `nav.workspace-symbol` | `workspace/symbol` 请求 → `path_from_uri` 限定在工程根内 → 读文件 → UTF-16 位置换算 → 打开并定位 | Navigate → Go to Symbol in Workspace |
| `nav.reveal-current-file` | 取聚焦编辑器文档 → 交给系统文件管理器显示其所在目录；磁盘上不存在的生成缓冲被拒绝 | Navigate → Reveal Current File |

### 87.2 关键实现决定

- **服务器只启动一次。** `SourceOutline` 新增 `ensure_started`，`refresh` 与 `workspace_symbols` 共用：
  根目录变化时丢弃旧会话，未变化时复用同一客户端；不重复 `initialize`。
- **文件符号读当前缓冲。** 大纲面板平时优先读生成产物；`nav.file-symbol` 明确刷新**聚焦编辑器**
  的文档（`refresh_active_source`），因为“当前文件符号”问的是正在编辑的文本。
- **工作区结果必须落在工程内。** `host::lsp::path_from_uri`（`file_uri` 的逆操作）解码
  `file://` 与百分号转义；`strip_prefix(root)` 失败的符号被拒绝并给出原因，不打开工程外文件。
- **位置是协议的 UTF-16 单位。** `SourceOutline::position` 走 `protocol::to_offset`，再换算为
  字符列；无法换算时退化为服务器给出的行列，而不是假定 ASCII。
- **不覆盖未保存缓冲。** 新的 `show_document_at` 只在文档尚未打开时写入磁盘文本；已打开的文档
  仅激活并移动光标，避免跳转覆盖别人的未保存修改。
- **旧跳转复用同一落点。** `jump_to_source` 拆出 `jump_to_source_position`，现在同时设置列
  （此前只 `goto_line`），大纲激活与文件符号共用一套定位语义。

**命令 ID 约束。** 注册表的 id 是严格的 `namespace.action` 两段式（`CommandId::parse` 拒绝第二个点），
因此 Plan 的分组记法 `nav.code.*` 在实现中落为 `nav.code-*`。这与既有的 `nav.goto-line`、
`nav.design-parent`、`view.mode-project` 等一致；没有引入第三种命名。

### 88.2 实现要点

- **一个 LSP 会话。** `SourceOutline` 抽出 `ensure_open`（打开或全量变更）与 `document_uri`；
  `refresh` 与 `code_locations` 共用，不会为每次查询重开文档或重启服务器。
- **能力先协商再请求。** 定义/声明/类型定义/实现共用 `Capability::Definition`，引用用
  `Capability::References`；未协商时返回带能力名的原因，命令显示原因而不是“没有结果”。
- **位置单位显式换算。** 光标列（字符）经 `units` 转为协议 UTF-16 单位；返回位置再用
  `SourceOutline::position` 换算回字符列。跨文件结果不借用当前文档的文本。
- **多目标不丢。** 服务器的每个位置都写入 Messages 面板；编辑器跳到**工程根内的第一个**位置，
  并在状态行报告总数。工程外的位置被拒绝并说明原因。
- **返回/前进是一份历史。** `Gui::jump_back` / `jump_forward` 记录 `(document, line, column)`；
  每次真实跳转（大纲、文件/工作区符号、代码导航）先记录当前光标，新的跳转清空 forward；
  历史回放不记录自身，失败时把条目放回栈中。
- **不覆盖未保存缓冲。** 与 §87 的 `show_document_at` 相同：已打开的文档只激活并移动光标。
