# blue12｜MS11 调试客户端

> 依据：[roadmap.md](./roadmap.md) §5 里程碑表及对应 F 域任务表。本文编号 12 对应 MS11；路线图是范围与契约基准，如有差异以路线图及批准的变更记录为准。

## 阶段目标与范围

- **阶段目标：** 调试客户端。
- **进入条件：** MS09、MS10 均已完成并验收。
- **交付集合：** F19（调试客户端、断点、变量与源码映射）
- **退出门禁：** 基础断点/变量/线程/源映射真实，热更新边界清楚；高级能力留待未来。
- **演示脚本：** 在认证组合运行最小调试程序，演示断点/继续步进/线程变量/双向源码映射及与热更新互斥；异常退出后工程可编辑且资源释放。
- **范围说明：** T19.09–T19.10 属 FUTURE，不在此里程碑验收。

## 执行约定

1. 按任务表中明确列出的前置关系推进；无依赖任务可并行，不把本文件排列顺序当作额外依赖。前置未满足时标记阻塞，不以占位实现代替。
2. 先核对公共契约、支持能力、权限与版本，再实现任务交付物；复用路线图已定义的事实来源和服务，缺少上游能力时记录缺口，不自行复制库实现或创造不兼容语义。
3. 各任务按适用范围验证正常、非法输入、取消、拒绝/冲突、服务故障和恢复；结果应可观察、可重现，失败不能显示为成功。
4. 逐任务记录责任人、状态、实现修订、测试命令/环境、自动/人工结果、目标/设备、产物、未覆盖范围与验收日期。未执行、缺设备或仅模拟的项目不得记为通过。
5. 状态使用“待开始 / 进行中 / 阻塞 / 待验收 / 完成”；实现完成不等于验收完成。

## F19｜调试客户端、断点、变量与源码映射

接入可替换调试适配器协议，不自研 Rust 调试后端。先证明目标平台适配器可用。
原生调试时默认冻结自动逻辑替换；替换会导致旧逻辑进程调试会话结束，必须确认重启/重新附加，
不承诺热切换后保留调用栈或断点绑定。
