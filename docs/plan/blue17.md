# blue17｜MS16 可选 AI 工作流

> 依据：[roadmap.md](./roadmap.md) §5 里程碑表及对应 F 域任务表。本文编号 17 对应 MS16；路线图是范围与契约基准，如有差异以路线图及批准的变更记录为准。

## 阶段目标与范围

- **阶段目标：** 可选 AI 工作流。
- **进入条件：** MS15 已完成并验收。
- **交付集合：** F23（可选 AI、变更提议、候选验证与人工确认）
- **退出门禁：** 两角色工作区/share/候选评审一致，无 AI 完整可用，人和宿主裁决。
- **演示脚本：** 执行无 AI 人工核心旅程；再执行授权上下文→不可变候选→验证→独立评审→人工部分接受/拒绝，并证明旧 PASS 不可授权新候选。

## 执行约定

1. 按任务表中明确列出的前置关系推进；无依赖任务可并行，不把本文件排列顺序当作额外依赖。前置未满足时标记阻塞，不以占位实现代替。
2. 先核对公共契约、支持能力、权限与版本，再实现任务交付物；复用路线图已定义的事实来源和服务，缺少上游能力时记录缺口，不自行复制库实现或创造不兼容语义。
3. 各任务按适用范围验证正常、非法输入、取消、拒绝/冲突、服务故障和恢复；结果应可观察、可重现，失败不能显示为成功。
4. 逐任务记录责任人、状态、实现修订、测试命令/环境、自动/人工结果、目标/设备、产物、未覆盖范围与验收日期。未执行、缺设备或仅模拟的项目不得记为通过。
5. 状态使用“待开始 / 进行中 / 阻塞 / 待验收 / 完成”；实现完成不等于验收完成。

## F23｜可选 AI、变更提议、候选验证与人工确认

AI 接入是可选受控能力；默认不发送工程内容。模型评审不是权限仲裁，也不是构建证据。

### T23.01｜人工/单/双 agent 会话、服务配置、授权与离线状态；双 agent 默认工作区 `.ai/coder`、`.ai/reviewer`，公共共享目录 `.ai/share`

- **前置：** T22.08、T01.05
- **优先级/投入：** P2/M

**执行步骤**

1. 对照前置任务和当前版本/能力/权限状态，确认本项输入、输出、涉及的服务/文档身份，以及相应的失败与回滚边界。
2. 按交付项落实以下工作（按其真实依赖排序；若无依赖可并行）：
   - 人工/单/双 agent 会话。
   - 服务配置。
   - 授权与离线状态。
   - 双 agent 默认工作区 `.ai/coder`。
   - `.ai/reviewer`。
   - 公共共享目录 `.ai/share`。
3. 将实现接入真实调用链与相关共享契约，确保状态/权限/版本来源唯一；对失败、取消或不支持情形给出准确结果，不以空占位、假数据或静默成功代替。
4. 根据最低验收补齐可重复的测试与演示：无配置/无网络仍完成全部人工旅程；并按适用性覆盖非法输入、取消、外部修改/冲突、权限拒绝、服务失效和恢复。
5. 记录测试命令和环境、原始输出/日志、工程或产物修订、目标/平台、未覆盖项及责任人；把状态更新为“待验收”，通过证据审查后再标“完成”。

**验收规范**

- **路线图最低验收：** 无配置/无网络仍完成全部人工旅程
- 自动化测试记录具体测试集和结果；人工/平台测试记录设备、系统、操作步骤及观察结果。缺工具/目标/设备时明确标阻塞或不支持，不能算通过。
- 核对结果与当前工程/模型/生成版本一致；任何数据丢失、权限越界、未授权副作用、过期结果冒充当前结果或失败被显示为成功，均判定不通过。
