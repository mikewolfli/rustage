# blue8｜MS07 首个源码交付

> 依据：[roadmap.md](./roadmap.md) §5 里程碑表及对应 F 域任务表。本文编号 8 对应 MS07；路线图是范围与契约基准，如有差异以路线图及批准的变更记录为准。

## 阶段目标与范围

- **阶段目标：** 首个源码交付。
- **进入条件：** MS06 已完成并验收。
- **交付集合：** F15（确定性生成、源码映射与双向合并）；F16（构建、运行、终端与外部任务）
- **退出门禁：** 独立生成工程真实构建运行，GUI/CLI 语义一致，诊断回指画布。
- **演示脚本：** 由设计生成工程并脱离宿主真实 build/run；从错误定位回节点；对比 GUI 与 headless/CI 的结果、退出码、离线缺缓存失败和任务取消清理。

## 执行约定

1. 按任务表中明确列出的前置关系推进；无依赖任务可并行，不把本文件排列顺序当作额外依赖。前置未满足时标记阻塞，不以占位实现代替。
2. 先核对公共契约、支持能力、权限与版本，再实现任务交付物；复用路线图已定义的事实来源和服务，缺少上游能力时记录缺口，不自行复制库实现或创造不兼容语义。
3. 各任务按适用范围验证正常、非法输入、取消、拒绝/冲突、服务故障和恢复；结果应可观察、可重现，失败不能显示为成功。
4. 逐任务记录责任人、状态、实现修订、测试命令/环境、自动/人工结果、目标/设备、产物、未覆盖范围与验收日期。未执行、缺设备或仅模拟的项目不得记为通过。
5. 状态使用“待开始 / 进行中 / 阻塞 / 待验收 / 完成”；实现完成不等于验收完成。

## F15｜确定性生成、源码映射与双向合并

模型到源码增量更新；文本到模型只支持明确定义的描述变化，任意 Rust 改动保持手写或冲突。
组件后续加入时扩展映射与测试，不另写一套生成器。
