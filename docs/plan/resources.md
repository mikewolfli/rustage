# rustage 图标与资源规划

> 编制日期：2026-10-12；状态：推荐方案，待实施与平台验收。
> 适用范围：rustage 桌面宿主图标、用户工程图标、生成产物资源、操作系统应用图标。
> 依据：[项目原则](principle.md)、[白皮书](whitepaper.md)、[完整路线图](roadmap.md)。
> 本文不是已实现能力清单，不新增路线图任务编号，也不表示已经导入图标或修改 GUI 库。

## 1. 推荐结论

**最适合当前项目的方案不是下载一整套图标放进源码目录，而是：**

1. **宿主常用图标优先复用 rust-widgets 内置 Material Symbols 轮廓。**
2. **rustage 用自己的稳定语义 ID 引用图标，不让界面代码依赖文件路径或上游枚举序号。**
3. **少量产品专用图标由 rustage 管理，SVG 为编辑源，构建工具生成可验证的渲染数据。**
4. **宿主资源、用户工程资源、品牌母版、平台派生产物四者隔离。**
5. **发布宿主的核心 UI 资源内嵌；操作系统图标通过平台打包流程安装。**
6. **用户工程通过资源清单实现相同逻辑身份的外部加载或静态嵌入，按目标能力生成。**
7. **主题、DPI、状态、RTL、无障碍、许可证、缓存及测试是同一个闭环，不是后补事项。**

“最优”以当前库契约、可维护性、跨平台一致性和真实验收为条件；不存在不用测试即可保证
所有平台、所有图标、所有缩放下都完美的方案。本文选择低重复、低运行成本、失败可诊断的
默认路线，并明确上游缺口，不为未来扩展提前堆砌框架。

## 2. 现状核验与设计约束

### 2.1 核验基线

rustage 当前 `Cargo.toml` 没有第三方依赖，`src/app/mod.rs` 只报告骨架状态，
还没有 GUI、图标服务或资源流水线。不能把“项目方向依赖 rust-widgets”写成
“当前 Cargo 已接入 rust-widgets”。

本次读取的 rust-widgets 工作树干净，提交为：

```text
027d72655fff634b75289b7ab3fc5843cafe311b
```

以下源码路径均相对于本地 `/home/mikeli/workspace/rust-widgets`。
固定版本的在线证据入口：
[rust-widgets 核验提交](https://github.com/mikewolfli/rust-widgets/tree/027d72655fff634b75289b7ab3fc5843cafe311b)。
升级 GUI 库后必须重新核验，不以注释、历史白皮书或默认分支代替实际实现。

| 已核验事实 | 源码位置 | 对方案的影响 |
|---|---|---|
| `desktop` profile 包含 `icons`、`image`、`desktop-runtime` | `Cargo.toml` 的 feature 定义 | 宿主优先使用已有矢量与图片管线；不是另选一套 GUI |
| 内置轮廓表有 69 项，图标词汇由单一 token 文件生成 | `src/widget/icon_data.rs`、`tools/icon_tokens.txt` | 查询实际词汇并映射，不能凭印象写不存在的 token |
| 内置图标来源为 Material Symbols outlined，轮廓许可为 Apache-2.0 | `src/widget/icon_data.rs`、上游 `NOTICE` 与许可文件 | 发行物必须包含相应许可/声明，不能只附 rustage 的 MIT |
| `IconName` 是闭合枚举，宿主注册图标是另一条扩展通道 | `src/widget/icon_registry.rs` | 不向 rustage 复制或重新定义一套上游枚举 |
| 自定义注册容量 `MAX_REGISTERED_ICONS = 16` | 同上 | 不把完整工作台图标集塞进注册表 |
| 注册名和路径必须具有静态生命周期，注册返回 `bool` | 同上 | 固定自有表可用；用户导入/热更新不适合靠泄漏内存注册 |
| 已注册同名图标会替换；内置轮廓先于宿主注册查询 | 同上、`src/widget/display_widgets/icon.rs` | 使用独立命名空间，不能靠同名注册覆盖内置图标 |
| 图标轮廓按填充路径绘制，不承载普通 SVG 的完整语义 | `src/widget/display_widgets/icon.rs` | 描边、变换、洞、渐变等须转换并验证或改走图片管线 |
| 几何数据使用 `x: 0..grid`、`y: -grid..0` | 同上、`src/render/path/flatten.rs` | 24 单位正坐标 SVG 不能只改 grid 就注册 |
| 展平有 1024 点、64 轮廓容量上限 | `src/render/path/flatten.rs` | 验收要实际展平，不能只数 SVG 文件字节或 path 数 |
| 某些展平失败路径会直接不绘制 | `draw_outline_in` 所在实现 | 宿主预检并报告错误，不能以“注册返回 true”作绘制成功证据 |
| `Icon::set_icon` 接受字符串，未知名画问号 | `src/widget/display_widgets/icon.rs` | 挂载前校验，问号是可见故障标记而非正常成功 |
| `ToolButton::set_icon` 接受文件 `PathBuf` | `src/widget/menu_toolbar/tool_button.rs` | 不能将 `save` token 传给它当作矢量图标 |
| `Button` 图标字段是 `Image`；`Action::icon_text` 仍走文本绘制 | `src/widget/base_widgets/button.rs`、`src/widget/menu_toolbar/action.rs` | 各入口必须分别适配；菜单图标不能用字符串冒充统一接线 |
| SVG 输入由图片解码器的 resvg 通道光栅化，按 intrinsic size 解码 | `src/image/decoder.rs` | 不自动等价于任意 DPI 的矢量控件绘制 |
| `render::svg::SvgPaintBackend` 是 SVG **输出**后端 | `src/render/svg/mod.rs` | 不能把截图/导出能力误当 SVG 资源输入加载器 |
| 存在 `ResourceId`、`ResourceSource`、`ResourceResolver`、`EmbeddedSource` | `src/asset/resource.rs` | 优先复用逻辑资源身份和解析契约 |
| `asset` 公共模块受 `desktop-runtime` 且非 `alloc_frugal` 条件限制 | `src/lib.rs` | 内部类型看似纯数据，也不能据此声称所有 profile 可导入 |
| 解析器默认对多个来源同名资源报歧义，不是“第一个获胜” | `src/asset/resource.rs` | 自定义覆盖必须有显式策略，不能依赖注册顺序 |
| 窗口图标有公开入口，Windows 有平台实现；通用状态也会记录路径 | `src/lib.rs`、`src/platform/windows/platform_impl.rs`、`src/platform/state.rs` | 返回成功或保存路径不等于三平台任务栏/Dock 已显示正确 |

### 2.2 最容易选错的三条路线

**错误一：拿任意 SVG 提取 `d`，调用 `register_icon_on_grid(..., 24)`。**

这个 API 的 grid 只解决缩放，绘制坐标仍使用：

```text
device_x = origin_x + x * size / grid
device_y = origin_y + (y + grid) * size / grid
```

普通 `viewBox="0 0 24 24"` 的源，转换后应满足 `y' = y - 24`。
不是 `y' = -y`，也不是仅修改 viewBox；曲线控制点、相对命令、变换和弧命令必须由
真正的 SVG 几何转换器处理，不能用正则替换数字。

**错误二：选择描边图标库后直接注册路径。**

很多线性图标依赖 `fill="none"`、stroke width、linecap、linejoin；
当前图标轮廓绘制是填充路径。直接提交中心线会变成错误填充或完全不可见。
要么构建时将 stroke 展开为封闭填充轮廓并验证，要么走 SVG/图片通道。
本项目因此默认复用当前 Material Symbols outlined，不混入另一套描边风格。

**错误三：把所有用户资源注册成全局静态图标。**

注册表只有 16 槽、没有工程身份隔离、不能用于大量动态资源；
持续 `Box::leak` 名称/路径会让热更新不断泄漏。用户资源应由资源解析和缓存服务管理，
不进入宿主全局注册表，也不能在关闭工程时清空整个注册表影响其他窗口。

## 3. 四层资源边界

### 3.1 宿主 UI 图标

表示 rustage 自身的保存、撤销、预览、对齐、诊断、构建等命令。
跟随宿主版本发布，通常单色、可着色，用户工程不允许覆盖。
已有上游图标只引用；自有图标只补语义缺口。

### 3.2 产品品牌与操作系统图标

包括产品 logo、启动器图标、安装包图标及将来的工程文件类型图标。
多色品牌资源保持原色，不能当成菜单单色 glyph 随文字颜色重染。
系统图标的规范、尺寸和安装位置与 GUI 控件内图标分开管理。

### 3.3 用户工程资源

是用户设计应用的内容，包括图标、照片、字体和插画。
由工程资源清单、导入事务、逻辑 ID 和目标配置管理。
不因 rustage 更新而改变用户图标，也不自动把宿主图标整套打进用户应用。

### 3.4 派生物和缓存

是对母版或原文件的确定性转换：轮廓表、缩略图、PNG、ICO、ICNS、目标像素数据等。
可重建、可失效，不是事实来源；不能让用户编辑缓存替代源文件。
发布派生物附工具版本、输入摘要和目标参数。

## 4. 推荐目录结构

```text
rustage/
├── resources/
│   ├── host/
│   │   └── icons/
│   │       ├── manifest.json
│   │       ├── custom/
│   │       │   ├── design-canvas.svg
│   │       │   └── event-binding.svg
│   │       └── vendor/                 # 仅在确实缺图标时创建
│   │           └── material-symbols/   # 固定版本、按需子集
│   ├── branding/
│   │   ├── app-icon.svg                # 正式应用图标母版
│   │   ├── app-icon-small.svg          # 必要时单独优化的小尺寸母版
│   │   ├── logo.svg
│   │   ├── logo-monochrome.svg
│   │   └── manifest.json              # 色彩、留白、派生规格和来源
│   └── licenses/
│       ├── manifest.json
│       └── <provider>/                # 原始许可与适用 NOTICE
├── src/
│   └── resources/                     # 仅资源接缝和适配代码，不放二进制
│       ├── mod.rs
│       └── icons.rs
├── tools/
│   └── resources/                     # 随首个转换需求实现，不预建空工具
├── packaging/
│   ├── windows/
│   ├── macos/
│   └── linux/                         # 打包定义和安装规则，不是手工 PNG 仓库
├── tests/
│   └── baselines/
│       └── icons/
└── target/
    └── resources/
        ├── normalized/                # 规范化与展开后的中间 SVG
        └── package/
            ├── windows/rustage.ico
            ├── macos/rustage.icns
            └── linux/hicolor/...
```

原则：

* 不同时创建 `assets/`、`res/`、`images/`、`icons/` 四套宿主根目录。
* 不把 SVG 散放到每个视图源码旁；按语义清单管理，不按工具栏所在位置分散。
* 不在本仓库镜像上游已经内嵌的 69 项轮廓。
* 初期 `icons.rs` 可同时负责语义解析和小规模控件适配；确实变复杂再拆文件。
* Cargo 生成 Rust 放 `OUT_DIR`，发行图标放 `target/resources/package/`，职责不混淆。
* 多架构并发构建时，生成目录再增加 target triple、profile 或独立 staging 标识，避免覆盖。
* SVG、小型许可文本、清单直接进 Git；不要为小图标引入 Git LFS。
* 大型用户素材是否使用 LFS 是用户工程决定，不成为打开工程的隐藏网络依赖。

## 5. 图标选型、视觉规范与来源

### 5.1 默认风格

| 类别 | 默认处理 |
|---|---|
| 常用命令、状态、导航 | 上游已有 Material Symbols outlined |
| 设计器专用概念 | 自制与既有图标视觉重量一致的单色封闭轮廓 |
| 品牌与系统应用图标 | 自有多色 SVG 母版及小尺寸光学优化 |
| 文件类型 | 首版通用文件/目录图标加文字，按需要加入少量类型 glyph |
| 控件面板 | 类型 glyph 表示类别；真实控件缩略图单独生成 |
| Git/调试状态 | 基础 glyph 配状态标记，不为每种组合画一张文件 |
| 用户应用资源 | 保留用户风格，不强制转换为宿主图标库 |

不以“下载数量最多”作为质量标准，不为每个菜单项强行安排图标。
明确的文本菜单可以没有图标；高频工具栏、状态和导航优先覆盖。
不得直接搬用其他产品的商标、产品图标或未核验授权的资源。

### 5.2 自有单色图标规范

* 编辑源默认正坐标 `viewBox="0 0 24 24"`，导出宽高明确，背景透明。
* 主体保留约 2 单位安全留白；必要的光学偏移需记录，不盲目数学居中。
* 单色 SVG 可用 `currentColor` 表达语义，转换器输出不携带主题色的几何数据。
* 轮廓优先闭合填充；含 stroke 的文件构建时展开，不依赖运行时补猜。
* 源中不含字体/文本、脚本、动画、外部 URL、嵌入位图或隐式外部样式。
* 单色 glyph 禁止渐变/滤镜；确需这些效果的内容归入品牌或插画资源。
* 允许编辑源中的 group/transform，但转换必须展开并校验，不直接丢弃。
* 不能保真转换的内容报错，不能为了通过构建静默删掉路径或效果。
* 洞、复合路径、fill-rule 必须实测。当前逐轮廓填充不是完整 SVG 填充规则承诺。
* 若轮廓有洞在当前后端不保真，应分解为可绘制几何或走图片管线；保留转换说明。
* 不简化原始第三方母版；规范化结果是单独派生物，保留来源摘要。

### 5.3 字体与 emoji 不作为命令图标

不用 icon font、Unicode 字符或 emoji 表示保存、运行、错误等功能。
它们依赖字体覆盖、平台替换、基线和颜色字形行为，无法保证视觉一致。
无障碍名称来自命令文本/翻译键，不来自 glyph 或 Unicode 名称。

## 6. 语义 ID、清单与命令映射

### 6.1 三种身份不要混为一谈

1. **命令 ID**：例如 `file.save`，控制执行、权限、快捷键、撤销和状态。
2. **宿主图标 ID**：例如 `host/file/save`，控制视觉语义和渲染选择。
3. **工程资源 ID**：例如 `project/icons/save`，控制用户资源解析和产物追踪。

相同 glyph 可以服务多个命令，命令不因图标更换而改名。
宿主图标采用类型化 `HostIconId`，其稳定字符串由清单生成或集中映射。
不持久化 Rust enum discriminant，不将上游路径或 `IconName` 序号写进工程。

命名规则：

* 语义 ID 使用小写 ASCII、`/` 分段、段内 `-`，不含扩展名、语言或主题名。
* 原文件名用小写 kebab-case，如 `event-binding.svg`。
* 上游 token 保持其实际 snake_case，如 `folder_open`，不做模糊匹配。
* 清单中的源路径相对于清单所在目录，包内路径只用 `/`。
* 小写约束之外，还要检测大小写不敏感文件系统上的碰撞。
* 语义更名保留迁移/废弃信息，不静默复用旧 ID 表示新含义。

### 6.2 宿主清单示意

以下是**建议 schema 示例，不是当前 rust-widgets API、JSON 控件 schema 或已可执行配置**。
第一项复用库数据，第二项引用本项目将来的自有 SVG：

```json
{
  "schema_version": 1,
  "upstream": {
    "name": "rust-widgets",
    "revision": "027d72655fff634b75289b7ab3fc5843cafe311b"
  },
  "icons": [
    {
      "id": "host/file/save",
      "source": {
        "kind": "rust-widgets-builtin",
        "token": "save"
      },
      "color_role": "icon-default",
      "rtl_mirror": false
    },
    {
      "id": "host/design/event-binding",
      "source": {
        "kind": "local-svg",
        "path": "custom/event-binding.svg"
      },
      "color_role": "icon-default",
      "rtl_mirror": false,
      "provenance": {
        "provider": "rustage",
        "license": "MIT"
      }
    }
  ]
}
```

完整 schema 还应约束：源类别互斥、ID 唯一、可选光学尺寸变体、注册 token、
许可记录键、原始摘要、转换参数，以及废弃别名。不要在每条内置项复制上游全部许可信息；
内置来源通过固定依赖修订与许可记录统一追踪。

缺少图标是合法设计时，命令元数据显式为“无图标”；请求了图标却未解析成功是错误，
二者不能都用 `None` 吞掉。宿主模块对外返回可区分的错误。

### 6.3 首批映射与补图策略

| 宿主语义 | 已核验内置 token | 策略 |
|---|---|---|
| 保存 | `save` | 直接复用 |
| 打开工程/目录 | `folder_open` | 直接复用 |
| 文件与关闭目录 | `file`、`folder` | 直接复用 |
| 撤销/重做 | `undo`、`redo` | 复用；RTL 行为单独确认 |
| 剪切/复制/粘贴 | `cut`、`copy`、`paste` | 直接复用 |
| 查找/过滤/设置 | `search`、`filter`、`settings` | 直接复用 |
| 添加/删除/关闭 | `plus`、`trash`、`close` | 不把删除与关闭混用 |
| 信息/警告/错误 | `info`、`warning`、`error` | 颜色、轮廓、文本共同传意 |
| 刷新、上下行传输 | `refresh`、`upload`、`download` | 直接复用 |
| 折叠/展开 | `chevron_left/right/up/down` | 查方向规则，不能全局自动镜像 |
| 画布、事件连线、布局对齐 | 不在此宣称已有专用 token | 查询完整 `IconName` 后再决定是否自制 |
| 运行、停止、调试、测试、Git | 不靠推测补 token | 实施时验证实际词汇和命令语义 |

这张表是首批选择依据，不是独立维护的完整能力注册表。
工具在固定依赖下校验所有内置 token；新增需求先查上游，再复用，再补自有轮廓。
用户工程若显式选择库内置图标，持久化“来源 + token + 契约版本”并在目标能力检查中验证，
不能将宿主专用 ID 偷换成用户应用内的图标。

## 7. rust-widgets 集成与真实缺口

### 7.1 单一宿主入口，多个控件适配

宿主调用者仅传递语义 ID、尺寸角色、状态和上下文，由集中入口：

```text
Command metadata
    -> HostIconId
    -> source selection / validation
    -> theme + state + scale
    -> actual control adapter
    -> rust-widgets render or image pipeline
```

“统一”指统一语义与解析，不是掩盖各控件底层接口不同。
不要把图标服务扩展成另一个渲染引擎、事件框架或资源操作系统。

| 消费入口 | 当前可用通道 | 本项目必须做的事情 |
|---|---|---|
| 独立 `Icon` 控件 | `IconName` 或已注册名称 | 挂载前解析，设置主题/尺寸，检测注册拒绝 |
| 自定义绘制内联 glyph | `draw_icon_at` / `draw_icon_named` | 检查返回及几何预检；不额外建子控件 |
| `Button` | 图片对象 | 从同一资源源生成适配尺寸图片；验证高 DPI 与禁用状态 |
| `ToolButton` | 文件路径图片 | 首版可使用明确的派生图片路径；预加载检查，不能默默丢图 |
| `Action` / 菜单入口 | `icon_text` 是文本 | 优先文字菜单；需要 glyph 时先补真实图标绘制接缝 |
| 原生 OS 菜单 | 平台菜单接口 | 验证各平台是否支持图标，允许平台约定为文字，不强行模拟 |
| 窗口/任务栏/Dock | 窗口后端 + OS 包元数据 | 分开验收，不能只看通用 setter 返回值 |

### 7.2 首版如何控制注册表风险

* 内置图标不占宿主注册槽。
* 自有注册 token 使用如 `rustage.event-binding` 的独立前缀。
* 清单检查禁止与内置 token 或其他宿主项冲突。
* 固定自有静态路径表在 GUI 初始化前一次注册，逐项检查返回结果。
* 本项目自定义注册初期软预算为 **不超过 12 项**，实际硬上限为 **16 项总计**。
* 剩余槽位只作为余量，不承诺扩展可自由占用；任何第三方消费者也计入总数。
* 同名替换只用于明确的初始化所有权，不允许用户工程改写宿主注册项。
* 不按窗口重新注册，不在视图卸载时调用进程级 `clear_registered_icons`。
* 测试全局注册状态时串行隔离，避免并行测试互相清空。
* 超预算时触发设计检查，不靠提高本地常量或动态轮换 token“修复”。

### 7.3 超过 16 项或需要统一矢量按钮时

优先向上游提出有测试的最小能力补齐：

1. 可直接传入经校验几何数据的绘制接缝，避免所有自定义 glyph 必须全局注册。
2. Button、ToolButton、菜单共享可表达内置/自定义几何/图片的类型化图标引用。
3. 保持命令状态、布局、点击、焦点和无障碍行为不变，仅补图标内容通道。
4. 保留现有图片接口，明确新旧接口选择及优先级。
5. 绘制失败返回可诊断结果，不能继续出现“注册成功但展平失败不画”。
6. 对不同 profile 控制数据和代码成本，不无条件给受限产物带入完整表。

这是建议的上游改进，不是当前存在的 `IconSource` 等 API。
如果必须在上游改进前发首版，采用文字菜单、内置 glyph 和构建期图片适配，
明确其 DPI/主题验证限制。不要复制 ToolButton 或 Action 的整个实现自维护分叉；
确需宿主组合控件时复用库的命令、交互和布局机制，不重写行为。

路径型控件不得以当前工作目录作为资源根。发布可采用包内只读派生文件；
若发行形态要求单可执行文件，则需先补内存图片接缝，或实现受控的内容寻址缓存落盘，
检查写入/权限/完整性并明确清理策略。不能声称 `include_bytes!` 自动满足 `PathBuf` 接口。

### 7.4 上游是否值得统一图标接口

本节说明决策理由；完整的上游接口、迁移与验收设计见本文[第 19 节](#19-rust-widgets-统一图标完整设计方案)。

**值得，而且对于 rustage 这样的多入口工作台，应优先于不断增加宿主转换补丁。**
目前的差异不仅是 setter 名字不同，而是存在实际契约断层：

* 同一个保存命令，在独立 Icon 中可用内置几何，在 Button 中需图片，
  在 ToolButton 中需文件路径，在 Action 中只有文本图标槽。
* 内嵌数据为了满足文件接口需要额外落盘，增加权限、缓存和发布故障面。
* 同一单色图标的主题、DPI 和禁用外观容易在不同入口产生不同结果。
* 运行期文件加载失败和轮廓绘制失败缺少一致的诊断接缝。

这会使复杂宿主为每个入口重复维护转换、状态和测试，统一的收益已经具有真实消费者，
不是为了抽象而抽象。但应统一**内容契约与渲染接缝**，而不是抹平全部控件差异。

#### 建议统一的层

1. **图标来源类型**：区分内置 glyph、直接几何、内存图片；逻辑资源引用在适用层解析。
   文件路径作为既有入口或便利加载入口保留，不作为所有来源的共同最低标准。
2. **外观策略**：区分可着色单色 glyph 与保留原色的多色图片，明确尺寸、比例、
   主题前景、禁用状态和失败占位策略。
3. **共享绘制/测量接缝**：独立 Icon 和内联槽复用同一测量与绘制路径。
   控件提供自己的图标矩形/状态；图标渲染不接管点击、命令执行或焦点路由。
4. **解析和错误接缝**：加载/转换在绘制外完成，返回可区分错误；
   绘制也能报告几何或后端失败，避免“返回成功但空白”。
5. **生命周期规则**：内置静态几何无需分配；动态工程数据有所有者和可释放句柄，
   不强迫动态内容满足 `'static`，不靠全局注册表承载所有来源。

可以用 `IconSource` 作为将来类型的讨论名，但本文不预定一个带所有变体、
全 profile 通用的枚举。具体设计必须尊重 `image`、无堆/受限 profile 的编译边界：
不能因为某个 variant 不使用，就允许它无条件拉入图片解码、文件系统或引用计数依赖。

#### 不应该强行统一的层

* 原生系统菜单不保证支持图标；能力不足时明确采用文字，不伪装为跨平台一致。
* 菜单、工具栏、树节点各自的间距、对齐、选中标记与点击热区仍由控件决定。
* SVG 导入、文件监视、许可证、打包和资源权限继续由宿主负责，不塞进 glyph renderer。
* 多色 logo 不统一成文字前景色；用户图片不为了“同一个 API”被重新编码为单色轮廓。
* mini/embedded 不为桌面资源便利性承担不需要的运行时依赖。

#### 推荐迁移顺序

| 步骤 | 范围 | 验收重点 |
|---|---|---|
| 1 | 固定现有行为测试，确认图标内容模型与 feature 边界 | 不破坏旧调用和受限构建 |
| 2 | 提取/公开可诊断的几何绘制接缝，Icon 与内联 glyph 先共用 | 静态数据无额外分配，绕开 16 槽限制但不绕过容量验证 |
| 3 | Button、ToolButton 增加共享内容入口，保留旧图片/路径接口 | 内存图标不落盘；布局、点击、主题与 DPI 正确 |
| 4 | Action 与自绘菜单消费同一来源，补足实际图标槽 | 命令状态不重复，名称/快捷键/勾选标记不受损 |
| 5 | 原生菜单后端按能力映射，覆盖树/导航等其余真实消费点 | 平台限制可见，无文本 glyph 假适配 |
| 6 | 更新 capability/schema、JSON、生成器、文档和示例 | 持久化来源可校验，两种产物同语义、可真实构建 |

运行期类型化来源与持久化资源描述不必是同一个 Rust 类型。
含内存句柄的 `Image` 或几何对象不能直接写入 JSON；生成器需从可序列化来源描述构造
目标可用对象。旧 `icon_text` 继续作为文本语义兼容，不偷偷将任意文本解释为 token。
旧接口是否废弃在版本策略中决定，不以一次重构删除用户已有代码。

**完成统一的标准**不是所有控件都有名为 `set_icon` 的方法，而是：
同一语义来源在所有声称支持的消费点显示正确、状态一致、内嵌不必落盘、
失败可诊断、旧行为保持，并且所有声明支持的 feature/profile 组合实际通过验证。

## 8. 源文件校验与确定性构建

### 8.1 三条处理管线

```text
A. 上游内置 token -> 固定库契约校验 -> HostIconId 映射 -> 库内置轮廓

B. 自有/额外 vendor SVG -> 来源核验 -> SVG 规范化/描边展开/坐标转换
   -> 填充保真与容量预检 -> OUT_DIR 静态路径表或图片适配

C. 品牌母版 -> 小尺寸母版选择 -> 固定参数栅格化
   -> ICO / ICNS / Linux PNG + SVG -> 平台打包
```

输入白名单、转换能力与许可检查先于派生生成。转换任务无网络，不在 `build.rs`
临时下载 SVG、字体或工具。维护者更新 vendor 是显式操作，不是普通构建副作用。

### 8.2 工具选择

* 首选复用上游已有转换、展平与图像接口，先检查可见性、feature 与实际语义。
* SVG 规范化、stroke-to-path、复杂填充转换应选成熟工具，不手写半套 SVG 解析器。
* 若无单个工具涵盖需求，组合有明确职责和固定版本的工具，记录中间结果与失败位置。
* 栅格化输出与交付管线使用固定版本和色彩参数，不能混用不同机器上默认的设计软件导出。
* 一般 `cargo build` 尽量不要求 Inkscape 等桌面软件；图标导入/更新可用离线开发工具。
* 平台编码依赖限制在打包任务；常规 Linux 开发不要求 macOS 的系统打包工具。
* 具体依赖在首个实现任务中经过小样探针选定，本文不增加未经使用的依赖。

### 8.3 生成约束

* 固定输入字节、工具版本、参数、依赖修订产生确定输出。
* 输出按稳定 ID 排序，不依赖目录遍历顺序、时间戳、绝对路径或随机数。
* 字节摘要覆盖内容；缓存 key 另覆盖转换器版本、目标尺寸、状态和色彩参数。
* `build.rs` 使用精确的输入变化声明，不能每次构建无条件重跑全部转换。
* build script 只写 `OUT_DIR`，不改源 SVG、清单、已审核基线或工作树。
* 生成失败保留最后有效源，移除未完成候选，不将空表作为成功输出。
* 更新源和清单使用临时候选 + 完整校验 + 原子提交；多文件失败需可恢复。
* 发布任务清理其专属 staging 而不是全局缓存或用户工程。
* 发布验证可以在独立目录重新生成比较摘要，禁止为“通过”自动更新基线。

规范化数据的检查至少包括：

1. 矩形与坐标范围、有限数、非零尺寸、透明背景。
2. 完整源特性清单；不能仅提取 `<path>` 而丢失其他可见元素。
3. 源图与派生图的实际渲染比较，特别是洞、交叉、弧线和光学居中。
4. 所有计划显示尺寸下的展平结果，包括 1024 点/64 轮廓的容量限制。
5. 注册容量、字符串合法性、无重名与上游 token 兼容性。
6. 路径表、清单、许可、派生物的一一追踪。

## 9. 主题、状态、缩放与 RTL

### 9.1 不为每种状态复制一份 SVG

同一单色 glyph 使用主题语义色，建议角色为：

```text
icon-default
icon-muted
icon-accent
icon-on-accent
icon-disabled
icon-success
icon-warning
icon-danger
```

角色名是宿主设计建议，实施时映射到现有主题能力，不冒充上游已定义字段。
轻/暗主题切换更换颜色与相关图片缓存，不读取另一份 `save-dark.svg`。
只有真实的轮廓变体或多色资源才允许单独源文件，并在清单显式关联。

| 状态 | 呈现规则 |
|---|---|
| 普通 | 默认前景，符合所在背景 |
| hover | 优先改变按钮背景/边框，不必换 glyph |
| pressed | 跟随真实交互状态，不仅改变图标颜色 |
| disabled | 使用可辨但非主导的样式，禁用原因可查询 |
| checked/selected | 选中底色、边框或标记共同表达 |
| warning/error/success | 颜色 + 形状 + 文本/读屏语义 |
| running/busy | 有真实任务状态；动画可关，非无限“假忙” |

`Icon` 已有去饱和/半 alpha 的禁用绘制。宿主不要再叠一次透明度；
其它控件行为分别测试。高对比主题不能只复用半透明灰，需按真实后端能力验证。
必要时补上游样式接缝，不能用“高对比支持”文案掩盖控件固定算法的限制。

### 9.2 逻辑尺寸与设备像素

推荐尺寸角色：

| 使用场景 | 逻辑尺寸 |
|---|---|
| 状态标记、小树节点 | 12–14 |
| 菜单、工程树、常规行内 | 16 |
| 密集工具栏 | 20 |
| 主工具栏、常规图标按钮 | 24 |
| 大入口/欢迎页 | 32 |

这是视觉角色，不是要求所有同类场景强制一个尺寸。图标画幅与点击热区分开：
16 的 glyph 可以放在更大的键盘/指针可访问控件里，不能把点击区也缩到 16。

* 实际栅格尺寸按逻辑尺寸乘宿主有效 scale，经统一规则舍入。
* 验证 100%、125%、150%、200%、300%，以及跨不同 DPI 显示器移动窗口。
* 矢量数据免去多份分辨率源文件，但不免除像素对齐与小尺寸视觉测试。
* 16 等小尺寸失去细节时可以有显式光学变体；不可对所有图标机械缩小复杂 24 母版。
* 当前 resvg 通道的 intrinsic-size 图片不能直接被放大后宣传为高 DPI 矢量清晰。
* 图片适配在所需实际像素尺寸生成/缓存；品牌资源保持比例和透明边缘。
* 不在绘制循环解析 SVG、执行转换器、访问磁盘或做文件摘要。

### 9.3 RTL 是逐语义决策

导航前进/后退、展开方向等可以镜像，但必须结合控件行为和 locale direction。
保存、搜索、logo、数字、Git 分支以及数据/时间轴方向不默认镜像。
清单 `rtl_mirror` 是输入规则，不意味着当前绘制 API 已有镜像参数。
当前无镜像接缝时使用成对内置 token 或构建期变体，避免宿主和控件各镜像一次。
测试至少覆盖一个 RTL 布局与中文/英文，检查布局方向、箭头和命令语义一致。

## 10. 无障碍与信息表达

* 纯图标按钮必须有真实可访问名称、键盘焦点和可发现的命令说明。
* tooltip 是补充，不替代读屏名称或键盘访问；触屏/键盘不能依赖 hover。
* 图标旁已有完整标签时，图标作为装饰，避免读屏重复播报。
* 状态不能仅靠红/绿区别：错误/警告使用不同轮廓，并保留文字和状态语义。
* 焦点环属于控件边界，不画在图标文件中；缩放和裁剪不能吃掉焦点环。
* 动画尊重减少动态效果偏好；静态状态仍能表达任务正在运行。
* 建议采用非文本关键图形对相邻背景至少 3:1 的对比目标；普通文字按相应文字标准检查。
  禁用项按适用规范处理，不伪造所有状态统一达标；品牌/装饰与功能图形分开分类。
* 可访问树中名称/role/state 存在，还不等于辅助技术端能用；三平台分别实测。

## 11. 用户工程图标与资源清单

### 11.1 工程内布局

```text
user-project/
├── assets/
│   ├── manifest.json
│   ├── icons/
│   │   └── save.svg
│   ├── images/
│   └── licenses/
├── ui/
├── src/
└── .rustage/
    └── cache/
        └── resources/                 # 可删除、可重建，不提交
```

这是建议的资源子结构，`ui/` 与 `src/` 不替代白皮书尚待决定的完整工程格式。
导入外部文件时复制到工程受管目录，记录来源；不默认保留指向用户下载目录的绝对引用。
必须保留外部链接的高级场景另有权限与可移植性诊断，不进入默认发布路径。

工程清单建议示例：

```json
{
  "schema_version": 1,
  "resources": [
    {
      "id": "project/icons/save",
      "path": "icons/save.svg",
      "media_type": "image/svg+xml",
      "role": "monochrome-icon",
      "packaging": "auto",
      "provenance": {
        "provider": "project-author",
        "license": "MIT"
      }
    }
  ]
}
```

许可值仅作格式示例，不能为用户自动声明其图片是 MIT。
实施时还需实际内容摘要、尺寸、使用节点、引用位置和目标转换结果；未知许可允许编辑预览，
但进入发布流程前须明确补齐或经审阅确认其发行权限。

### 11.2 逻辑 ID 不等于物理路径

`project/icons/save` 不随 `icons/save.svg` 移到新目录而变化。
改物理路径只更新清单，改逻辑 ID 则形成引用迁移事务，预览受影响节点并可撤销。
内容去重也不能合并两个不同的用户语义 ID；只在字节/派生缓存层共享。

使用上游 `ResourceId` 归一化时还需宿主规则：

* 只接受 schema 允许的相对路径，拒绝 OS 绝对路径、盘符、URI、NUL、`..` 和非法段。
* 库会剥离前导 `/` 和 `./`，因此 `ResourceId::parse` 成功**不是**安全路径验证成功。
* 实际文件访问需检查符号链接和规范化后边界，防止相对路径指向工程外。
* 清单路径校验和实际文件读取一起做边界保证，不能只比较字符串前缀。
* `contains` / `get` 失败要保留来源与读取原因，宿主不能只留下“没图”。
* 多来源同名默认报歧义；工程/扩展覆盖若开放，应先解析显式优先级，再交付唯一来源。

### 11.3 导入、修改与热更新事务

```text
选择文件
 -> 权限与边界检查
 -> 有界格式检测/解析
 -> 候选原文件和来源记录
 -> 候选转换与预览
 -> 用户确认（如需转换/覆盖）
 -> 源文件 + 清单 + 引用原子提交
 -> 精确失效并更新预览
```

失败保留旧有效资源和用户编辑内容，问题面板指出文件、资源 ID、阶段和原因。
外部修改先在候选数据上校验，通过才替换；错误候选不得破坏最近一次有效预览。
删除资源先查询反向引用，允许取消、替换或显式保留缺失状态，不自动删除引用节点。
关闭工程取消归属任务并释放缓存，不影响别的工程与宿主 UI。

## 12. 生成模式与受限目标

| 目标/模式 | 推荐资源策略 | 必须验证的限制 |
|---|---|---|
| desktop/tablet/mobile 模式 1 | 工程逻辑 ID + 外部/嵌入解析策略 | 实际目标解码、主题、加载失败和包内定位 |
| desktop/tablet/mobile 模式 2 | 只嵌入引用资源，或显式外部打包 | 无设计器依赖；资源身份与模式 1 相同 |
| mini/embedded 模式 2 | 生成目标可用静态几何/像素数据 | feature、内存、格式、容量、链接与设备验证 |
| mini/embedded 模式 1 | 不提供 | 不绕过既有两种产物边界 |

重要边界：

* 不在受限产物中无条件引用 `rust_widgets::asset`、resvg 或 `Image`。
* 生成器先查选定 profile 的实际公共 API 与渲染能力，不凭宿主构建成功判断可用。
* 上游 `EmbeddedSource` 内部持有/返回 `Vec<u8>`，不能将它描述成零拷贝静态资源表。
* 需要无堆或受限内存的目标，生成与目标兼容的静态切片和访问代码，
  而不是把 desktop 的 resolver 带进去。可复用语义和格式，不强求相同 Rust 类型。
* 不支持的 SVG 特性可在宿主生成阶段按批准规则转换；目标端不运行转换器。
* 目标转换改变视觉或色彩时，说明差异并要求确认；无法满足容量则阻断，不静默缩小。
* 收集从入口可达的资源引用及显式动态白名单，避免全量打包宿主与用户素材。
* 业务代码动态引用无法静态分析时，要求显式声明或完整包策略；不错误裁剪。
* 生成报告列出逻辑 ID、源摘要、派生摘要、体积、目标格式、许可及未支持项。
* 模式 1/2 的同一资源身份要有实际端到端比较测试，而非仅清单字符串相同。

## 13. 平台应用图标与打包

### 13.1 Windows

* 从品牌母版生成多尺寸 ICO：建议包含 16、20、24、32、40、48、64、128、256 像素。
* 至少验证小尺寸帧与 256 的大尺寸编码被目标系统正确读取。
* 应用图标进 PE 资源，安装器、快捷方式、文件关联引用打包产物。
* 窗口大/小图标入口另行设置并验证，不能只依赖 EXE 图标。
* 应用身份、快捷方式及任务栏组合策略按最终打包形态确认。
* 验收 Explorer、快捷方式、任务栏、窗口标题栏及 Alt-Tab，而非只检查 ICO 文件存在。

### 13.2 macOS

* 从 1024 级品牌母版生成 `.iconset` 再得到 ICNS。
* 传统 iconset 覆盖 16、32、128、256、512 的 1x/2x，最大实际像素 1024。
* 安装到 `.app/Contents/Resources/` 并由对应 Info.plist 图标配置引用。
* 最终 macOS 版本若采用新的图标/外观机制，按最低支持版本核验适用规则，
  不把单一年代的模板宣称为所有系统的最终规范。
* 验证 Finder、Dock、应用切换器及打包后启动；公证/签名流程包含资源。
* logo 不重复加入系统已经提供的圆角、背景或材质，留白由品牌规范定义。

### 13.3 Linux

* 按 hicolor 布局准备 16、24、32、48、64、128、256、512 PNG；
  需要时提供更大尺寸，并安装可缩放 SVG 到 `scalable/apps/`。
* `.desktop` 的 `Icon` 使用与安装文件 basename 一致的稳定名称，不带绝对开发路径。
* reverse-DNS 应用 ID 必须基于项目实际控制的命名空间确定；本文不虚构域名。
* 桌面项、图标文件与 Wayland app_id / X11 身份匹配，避免任务栏重复或显示通用图标。
* 发行形态分别定义 deb/rpm/AppImage/Flatpak 等适用布局，不保证一套路径覆盖所有包。
* 使用用户级安装时更新相关缓存的行为按系统工具与权限执行，失败可诊断。
* 验证至少 GNOME 与 KDE 的实际启动器/任务栏；窗口图标是否由桌面项解析也需确认。

### 13.4 平台共同要求

* 应用图标只由品牌母版和显式小尺寸母版派生，不手工修每个平台的每个 PNG。
* 首次设计通过尺寸矩阵审阅，允许 16/32 的光学差异，不以纯缩放保证小尺寸质量。
* 工程文件类型图标只在启用真实文件关联功能时加入，不能提前宣称关联已支持。
* 整个包复制到无源码、无 sibling rust-widgets、无网络的干净环境验收。
* 系统缓存可能延迟刷新，测试记录安装/升级步骤；不靠手动清缓存掩盖身份错误。
* 打包成功不等于 UI 图标加载成功，二者分别验收。

## 14. 缓存、性能与资源预算

### 14.1 优先复用已有缓存

先复用库的解码与内容缓存，不另造相同的图片缓存。
宿主只补语义解析、转换结果和未覆盖的主题/DPI派生缓存。
当前内置几何绘制仍有展平成本，不未经测量宣称“一次解析、之后零成本”。

图片/派生缓存 key 建议包含：

```text
source digest
+ pipeline version
+ render backend / pixel format
+ actual pixel size
+ resolved color(s) and color space
+ visual state when it changes pixels
+ optical variant
```

纯几何缓存不包含无关的命令权限或翻译；路径变了但内容相同可共享解码。
主题切换失效着色像素而非原始几何，DPI 切换失效相关像素尺寸而非全部工程。
缓存缺失可重新生成，源缺失不能伪装为缓存 miss 成功。

### 14.2 建议初始预算

以下是待测量调整的门禁目标，不是现有性能数据：

| 项目 | 初始目标 |
|---|---|
| 宿主自定义全局注册数 | <= 12，且所有消费者总计 <= 16 |
| 单个自有 glyph 源 SVG | <= 32 KiB，例外须审阅 |
| 单个自有 glyph 几何复杂度 | 在实际尺寸下成功展平，且不超过库当前容量 |
| 新增自有静态 glyph 数据总量 | <= 256 KiB，不计既有依赖和品牌系统图标 |
| 宿主新增图标/图片适配缓存 | 默认上限 16 MiB，需与已有库缓存核对实际总量 |
| 普通绘制循环 | 0 文件读取、0 SVG 解析、0 外部转换进程 |
| 常用可见图标 | 初始化/首次显示预热，避免一排按钮首次同时阻塞 |
| 故障诊断 | 同资源同版本合并呈现，不每帧重复刷屏 |

这些初值覆盖小型 glyph，不用来限制用户所有图片。
用户资源转换单独设置任务内存/并发/超时预算，超限提示分辨率、格式及可操作建议。

性能报告固定机器、后端、OS、DPI、资源版本、冷/热缓存状态和工作负载。
记录冷启动、首次图标显示、主题切换、DPI切换和长时间打开/关闭工程的缓存曲线。
微基准与真实工作台测量分开，不拿小表查找耗时证明整帧达标。

## 15. 安全、许可与供应链

### 15.1 非可信资源输入

* 格式按内容检测，扩展名只是提示。
* SVG 禁止脚本、foreignObject、外部引用、外部样式、DTD/实体展开及隐式网络访问。
* 拒绝内嵌可执行内容；栅格器配置明确禁止加载工程目录外文件与系统字体。
* 位图限制编码大小、宽高、解码像素总量；校验乘法溢出，不仅检查压缩文件大小。
* SVG/SVGZ 限制输入、解压后大小、节点/路径复杂度、任务时间和输出大小。
* 不因上游存在 64 MiB SVGZ 解压上限就认为导入安全或内存峰值受同一数值限制。
* 建议 UI 图标导入默认上限：源文件 1 MiB、输出边长 4096、输出像素 16 Mi；
  自有宿主 glyph 仍受更严格的 32 KiB 规范。一般工程图片采用单独预算。
* 超限拒绝并解释，不静默降采样；用户批准转换也不得绕过安全硬上限。
* 复杂/非可信解码与转换放受预算的工作进程，取消可终止；进程隔离本身不等于沙箱。
* 解码器升级与供应链审查按项目发布门禁执行，不能仅因“纯 Rust”免检。

### 15.2 来源和许可

来源记录至少保存：

```text
provider / original URL / exact revision or version
original relative path / original SHA-256
SPDX license expression / license file / applicable NOTICE
modification description / conversion tool + version + parameters
derived digest / rustage semantic ID(s)
```

* 上游内置 Material Symbols 的 Apache-2.0 声明随发行物分发；
  rust-widgets 和 rustage 的 MIT 不能替代图标数据许可。
* 额外 vendor 子集保存原始许可与适用 NOTICE，转换/修改记录留痕。
* 自有 SVG 核实作者和贡献权限后才标 MIT，商标使用权单独看待。
* 用户工程保留自己的来源声明，生成应用只携带实际使用的第三方资源声明。
* 没有许可证的网络图片不视为“可自由使用”；缺失来源不自动填写开源许可。
* 发布包生成第三方清单/SBOM，图标和字体都纳入，不只统计 Cargo crate。
* 若生成应用引用宿主自有图标，必须是明确导出的资源能力与授权，不是复制运行缓存。

## 16. 验证矩阵与发布验收

### 16.1 自动检查

| 检查域 | 必须覆盖的正/负用例 |
|---|---|
| 清单 | 合法项、重复 ID、未知字段/源类型、未知上游 token、缺失文件、大小写碰撞 |
| 路径 | `..`、绝对路径、盘符、URI、符号链接越界、移动与权限拒绝 |
| 图标注册 | 空名/空路径、grid=0、16 槽边界、重复名、内置名冲突、初始化重复 |
| SVG 转换 | 正坐标变负坐标、stroke、transform、洞、fill-rule、弧、超复杂、外部依赖 |
| 失败反馈 | 注册 true 但不可展平、图片无法解码、缓存写入拒绝、目标 API 不可用 |
| 状态 | hover/pressed/checked/disabled 与命令状态一致，不改变点击行为 |
| 生命周期 | 多窗口、多工程、热更新、取消、关闭后释放、不泄漏静态字符串 |
| 身份 | 路径移动不改 ID、ID 更名迁移、来源歧义、内容去重不改语义 |
| 生成 | 模式 1/2 同身份、引用裁剪、动态白名单、受限目标不拉入 desktop 资源模块 |
| 打包 | 单可执行/应用包、无开发树、无网络、许可齐全、系统图标真正可见 |

### 16.2 视觉验收

为每个宿主图标生成联系表，展示：

* 12/16/20/24/32 逻辑尺寸及实际像素尺寸。
* 亮/暗/高对比背景。
* 普通、禁用、选中、错误等适用状态。
* 100%/125%/150%/200%/300% 缩放。
* 静态轮廓、Button 图片适配、ToolButton、菜单和工程树的真实消费入口。
* RTL 适用项，以及 logo/非镜像项。

母版参考图、派生资源图、实际 rust-widgets 后端图分别保留，SVG 输出快照不能代替
真实软件/GPU/原生后端截图。PNG、ICO、ICNS 编码也不能仅用 GUI 内显示成功验收。

比较规则：

* 固定后端与环境才能作严格基线比较，跨后端抗锯齿差异分开记录。
* 几何位置、空白/缺图、方向、颜色角色可作结构断言。
* 像素差异采用经校准的阈值与差异图；不随意用一个全局容差掩盖局部缺图。
* 非整数 scale 下要看实际清晰度，不只验证输出尺寸正确。
* 人工审核是小尺寸可辨识和光学平衡的必要补充，不能由文件大小检查替代。

### 16.3 发布最低门禁

1. 清单中所有被宿主请求的图标可解析，无未知 token、无超容量、无缺图。
2. 主题切换、DPI变化、多窗口状态更新正确且没有重复禁用着色。
3. 无障碍名称、焦点与状态在三平台实际消费链可验证。
4. 非法资源不进入有效模型，诊断能定位且用户可恢复。
5. 用户工程资源与宿主资源互不覆盖，两种产物身份一致。
6. 所宣称支持的目标实际构建并运行，受限目标容量报告通过。
7. 三桌面发行包在干净环境显示正确系统图标，许可和来源随包分发。
8. 可复现输出检查通过；未验证平台/后端明确标为未验证，不能扩大支持声明。

阶段可以按任务真实依赖并行，但不能跳过使用点适配验证：

### 17.1 第一个实施变更应尽量小而完整

推荐首个资源实现范围：

1. 在正式接入 rust-widgets 的 GUI 基线后，创建一个宿主图标清单和集中语义映射。
2. 先用已存在的保存、打开、撤销、重做、查找、设置、错误等 glyph。
3. 在一个真实工具栏/菜单/工程树组合中验证，不建无消费者的资源服务。
4. 明确 Action 文本图标和 ToolButton 文件路径的缺口，用文字菜单或经验证的图片适配。
5. 只在出现真实产品专用需求时加入第一个自有 SVG 和转换工具。
6. 同步来源许可、主题状态、失败诊断和最小回归测试。

此阶段不引入完整 icon pack、插件图标覆盖、云资源同步、通用主题市场、
动态全局注册扩容或新的资源数据库。

### 17.2 实施前需要确认但不影响目录方案的决策

* 产品最终品牌稿、实际应用 ID、商标权属与最低 OS 支持版本。
* 首版正式打包形态，是否硬性要求单可执行文件。
* GUI 库固定依赖方式与版本；本地 path 仅作开发选择，发布不依赖个人目录。
* 上游是否补统一图标源/图片内存接缝；否则采用哪些明确受限的首版适配。
* 小样验证后锁定 SVG 转换及平台编码工具。

这些事项不在本次文档中冒充用户已经批准的品牌或发行决策。

## 18. 日常维护流程与最终放置原则

### 新增一个宿主图标

```text
确认命令语义
 -> 查询固定版本上游词汇
 -> 能复用则只加映射
 -> 确需补图则添加 SVG + 来源许可
 -> 规范化/转换/展平/容量检查
 -> 在真实入口测试主题、DPI、状态与无障碍
 -> 审核视觉 diff
 -> 更新清单和必要基线
```

### 更新一套第三方图标来源

显式变更来源版本和摘要，生成变更报告，检查新增/删除 token、风格、许可、派生差异、
注册容量和平台回归。正常应用启动不下载资源，正常构建不拉取浮动最新版本。

### 删除或更名

先查命令与文档引用；稳定 ID 必要时保留迁移表；移除死资源和无用派生物；
确认用户应用没有被宿主升级改变内容。不得随意更新视觉基线来掩盖删错图标。

**最终规则可以浓缩成四句话：**

* **库内置图标留在库里；rustage 只引用和验证。**
* **宿主补充资源放 `resources/`，编辑源与许可入库，派生物走确定性构建。**
* **用户资源放用户工程 `assets/`，稳定 ID 经清单解析，绝不混进宿主全局表。**
* **系统图标由 `resources/branding/` 母版生成，按平台安装并在真实系统验证。**
