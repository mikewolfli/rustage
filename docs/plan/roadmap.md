## 1. 产品目标、范围与规划方法

### 1.1 产品目标

交付面向 Rust UI 工程的一体化桌面开发设计工作台，贯通：

**工程建立 → 页面/组件设计 → 样式与数据 → 事件与业务逻辑 → 即时预览 → 源码往返 →
构建/调试/测试 → 多目标部署 → 版本审阅 → 打包发布 → 升级维护。**

完整性不以菜单数量衡量。每个入口必须具有真实模型、服务、错误路径和测试，不能做只有外观的面板。
产品差异化优先于堆叠：多目标能力感知、布局语义一致、UI/代码可审阅往返、分级热更新、
开发与静态产物一致性、工程级可恢复事务必须贯穿所有模块。

### 1.2 不可改变的架构边界

| 维度 | 约束 |
|---|---|
| 宿主 | 仅桌面，分别支持并实测 macOS、Windows、Linux；不开发移动端设计器 |
| 生成配置 | desktop、tablet、mobile、mini、embedded；profile 与 OS、target triple 分开建模 |
| 产物 | 模式 1：适用目标的 JSON/CSS 运行时；模式 2：所有配置的静态 Rust；mini/embedded 只模式 2 |
| 模型 | JSON 结构、CSS 外观、稳定 NodeId、版本化变更集；有效模型是唯一事实来源 |
| 布局 | 复用库 `Layout` trait（`update`/`arrange`/`arrange_with_context`）与 `Hints`/`ChildInfo`/`LayoutParams` 语义；拖拽结果必须可表达为真实布局约束 |
| 能力 | 查询带版本的库契约（`WidgetFactory` 注册表与 `DesignerManifest` JSON，含 `protocol`/`library`/`profile`/`triple`）；不可维护猜测的控件/属性支持表，不静默降级成其他控件 |
| 源码 | 生成区受保护，手写 Rust 可编辑；不承诺把任意 Rust 反推成 UI |
| 热更新 | UI/已有绑定即时更新；受管理业务 Rust 增量构建后替换逻辑进程；不兼容则明确重启 |
| 服务 | 文件、语言服务、构建、调试、版本控制、网络属于宿主；widget 不承载系统服务 |
| 权限 | 工程代码、构建脚本、终端、设备部署、外部服务都具有真实副作用；工作进程不是沙箱 |
| 人工流程 | 无 AI、无账号、无网络仍能完成本地工程闭环 |

### 1.3 完整规划与首个交付的区别

本文纳入工程所需的调试客户端、版本控制、终端、组件变体、设计检查、工作区布局和受控扩展，
并补充多根/多包工程、工具组合 Kit、可复现/离线构建、headless/CI 接缝与双 AI 工作区生命周期。
高级原生调试、复合调试会话、内置性能剖析、远程开发/部署及容器环境仅保留为未来扩展，
不进入正式版交付；正式版仍保留基础调试和现有性能验收/报告能力。
不把它们等同于自研调试器后端、任意语言 IDE、插件市场或多人实时协作平台。
这些是宿主功能的明确扩展计划，不要求全部挤进第一个可用版本。

* **交付 A：人工设计闭环**，MS00–MS07；可建立、设计、生成、构建和运行工程。
* **交付 B：可靠开发工作台**，MS08–MS12；组件、往返、热更新、多目标、工程调试。
* **交付 C：完整产品候选**，MS13–MS17；版本控制、测试与证据、扩展、可选 AI、跨平台体验。
* **交付 D：稳定发布与维护**，MS18–MS19；证据收敛、干净安装、升级、维护回归。

每一交付冻结后不能临时把未完成必需项改成“可选”以宣布达标；范围调整须有决策记录和用户可见限制。
白皮书未决 Q1–Q6 仍在 MS00 确认；本路线图描述功能需求，不替代接口选型决策。

#### 1.6.1 上游版本事实

| 事实 | 内容与出处 |
|---|---|
| 控件口径 | `WidgetKind` 228 个变体；注册表 268 个规范名（含别名）；库内另有 188/187 旧口径（生成器探针与渲染金表，时点更早）。引用计数必须注明口径与时点（`src/widget/kind.rs`、`capability/registration.rs`、根 `control.md`） |
| 渲染路径 | 现役画面路径是 CPU 软件光栅（`SoftwarePaintBackend`）；`wgpu` 后端为保留管线（模块自述 "Reserved: no production caller"）。性能门槛与宣称不得以 GPU 加速为前提 |
| 互斥 profile | desktop/tablet/mobile/embedded/mini 五档互斥，`desktop` 默认启用 `designer`、图表、打印/PDF、彩色 emoji；图表/打印/PDF 仅 desktop；`mini` 为 no_std（约 28 核心控件）。容量预算三档：Device 4096 控件/4096 纹理/2 MiB 字形缓存/256 事件队列，Surface 512/2048/1 MiB/128，Minimal 64/1024/256 KiB/64 |
| 设计器契约 | `designer` feature（= `serde_json` + `declarative-view`）提供 JSON 工程 → 确定性 Rust 生成：一次工程固定产出双产物 `src/generated/ui_default.rs`（desktop/tablet/mobile 共用 Node+ViewEngine 模板）与 `ui_stripped.rs`（mini/embedded 命令式模板）；产物首行 `GENERATED_MARKER`；`GenerationReport`/`GenerationGap` 五类原因（unsupported/capacity-overflow/cross-profile/unresolvable-event/incompatible-wire）不静默丢弃；`--check` 退出码 0/1/2；模式 1/模式 2 行为一致性与 manifest 往返各有库侧门禁 |
| 身份与映射 | `TreeIndex` 提供只读 key/path ↔ ObjectId 查询，并明确 "`ObjectId` is not a `NodeId`"；**上游无 NodeId 持久化与源码 span 映射**（上游 blue26 B26.04 待办，对应本计划 T15.03 与 C-SOURCE-MAP） |
| 能力清单 | `PropertySchema`（value_kind/accepted_tokens/约束，默认值来自新建实例实测）+ `EventSchema`（payload 形状由 signal 派生并有门禁）+ 命令 schema；`DesignerManifest` 手写序列化、按名排序、导出→读回→再导出字节一致 |
| 事件与绑定 | signal-slot（connect/disconnect/block/priority、`ConnectionHandle`/`ConnectionScope`）；`EventSignalRef`/`EventSignalBinder` 按名订阅；数据绑定 `Binding<T>`/`BindingPipeline` 与 `bind_widget_property(_two_way/_validated)`；连线规则 `WIRE_RULES`（命令仅接受无载荷事件） |
| 样式与主题 | `WidgetStyle` 全 Option 字段 + `merge` 只填空缺 + `theme_derived` 整体替换；CSS 解析器（类型/类/伪类选择器）与 `css_trace` 获胜规则追踪缝存在，但**无 CSS 生成**——模式 2 在生成期内联样式属性；主题 `ThemeManager` 支持亮暗切换、交叉淡入、8 种系统强调色、JSON 主题文件（themes/*.json 由预设生成防漂移） |
| 布局 | `Layout` trait（`add_widget`/`update`/`arrange`/`arrange_with_context` 携带 `LayoutContext`：缩放/字体缩放/最小触达）+ `Hints`（min/pref/max 规范化）+ `ControlMetrics`（floor=最小可触达面积）；内置 box/flow/wrap/grid/form/splitter/stack/absolute/aspect_ratio/masonry/dock_area 等约 19 个布局模块，布局原语同时注册为控件 |
| 平台后端 | 桌面：Windows（winapi+DirectWrite）、macOS（cocoa-legacy 与 objc2 两套）、Linux（GTK 默认与 Wayland 运行时探测）；另有 iOS/Android/HarmonyOS/Redox/WASM。`platform_diagnostics` 12 位探针（剪贴板/显示器/DPI/主题/文本缩放/安全区/IME/无障碍/文件对话框/外链等）可经 C ABI 调用 |
| 无障碍 | 角色树契约（`A11yRole`/`A11yTree`）+ 三平台通知式桥：macOS NSAccessibility、Windows NotifyWinEvent+UIA 角色映射、Linux AT-SPI2 over D-Bus；是通知+状态表，不是全量树查询 API |
| 文本/i18n | 复杂脚本 shaping 未实现（bidi 只排序不整形）；内置 CJK 矢量面为 2053 字子集，超出需 `register_system_cjk_font()`；i18n 支持复数/上下文/键审计/en 回退/翻译热重载；RTL 有方向判定与排布反转 |
| 附属 crate | `rust-widgets-font`（OFL 子集纯数据，含 CJK 分片）；`rust-widgets-webview`（模型层 web 控件+JS 求值与历史/隐私/插件，**页面内容从不渲染**，无原生引擎）；`mobile-services`（应用壳服务，一律 Available/Denied/Unsupported 三态回答）；C ABI 稳定线 v8 |
| 会话状态 | `SaveState` opt-in：`SavedState{key,version,bytes}`，键由宿主显式分配、版本不符即拒绝；已实现于 TabWidget/Splitter/DockWidget/MdiArea/CollapsiblePane/Pagination 六容器；无参考宿主实现——正是 F04 的落点 |

#### 1.6.3 外部参照：借鉴单位是工作流，不是菜单

本计划的模式、面板与菜单均为自有设计；本节固定参照单位，防止照搬或否认参照两头漂移：

* **借鉴并落地：** ① 模式化工作台与“模式承载工具上下文”（§2.1 的七模式为本产品划分，

  ② 控件盒/属性编辑器/对象检查器/信号-槽编辑器共享同一选择的协作闭环（F09/F11/F13）；
  ③ 外部格式 + 代码生成的“模型为源、生成为产物、往返可审阅”关系（F15；本产品以版本化
  JSON+CSS 取代其 XML，以确定性生成器取代其代码生成器）；④ Kit/工具链抽象（T02.10）；
  ⑤ 翻译键提取/上下文/复数的翻译流水线（T24.10）；⑥ 增量构建与问题面板回流（F16/T21.01）；

* 借鉴项在任务验收中体现为“工作流等价”，不是“界面等价”；与库契约冲突时以库契约为准并记录差异。

## 2. 完整工作台信息架构

### 2.1 顶层区域与模式

主窗口由菜单栏、模式切换、上下文工具栏、左/右停靠区、中心编辑区、底部工具区、状态栏组成。

单工程可有多窗口视图；多工程在独立上下文打开，禁止共享脏状态、撤销栈、运行版本和目标配置。

### 2.3 布局规则

1. 默认提供设计、代码、调试、测试、发布五种布局预设；用户布局有名称、版本、重置入口。
2. 停靠、分栏、浮动和窗口恢复不能改变文档所有权；关闭视图不等于关闭文档。
3. 显示器移除、DPI 改变、窗口位置越界后保证至少一个主窗口与恢复入口可见。
4. 进入调试/发生错误可提示切换面板，默认不夺走输入焦点；用户可配置自动显现。
5. 窄窗口提供折叠区与溢出菜单，不让关键命令仅存在于被遮挡的工具栏。

## 3. 菜单、命令和上下文操作的完整设计

### 3.1 命令系统契约

每个菜单叶项必须注册：稳定 ID、中文标题、描述、分类、图标、可见/可用条件、禁用原因、
快捷键候选、上下文、参数 schema、权限、是否可撤销、是否异步、所属任务与测试。
菜单、工具栏、快捷键、右键、命令面板都调用同一命令；不在菜单回调中直接改模型。

* 未实现命令不显示成可用入口；开发版可在功能总账展示“未实现”，不能假成功。
* `保存`依赖当前可写脏文档；`重做`依赖对应撤销域；`运行`依赖有效目标与可执行产物。
* 能力相关禁用附原因，例如“此目标不支持此事件”，不能只有灰色图标。
* 异步命令反馈任务 ID；取消中不等于已取消；取消必须处理已产生文件/进程。
* 多选命令要定义对全部选中项的适用性；无法部分安全执行时整体禁用并说明。
* 快捷键在 MS00/MS03 做平台与冲突确认，不把某个平台组合键硬编码为三平台统一规则。
* 命令清单内使用 `/` 分隔的项都是独立叶命令，各自采用同组语义 ID 后缀，必须逐项注册与测试。

### 4.2 服务状态机与一致性

* 文件：读取 → 校验/迁移候选 → 有效载入；保存准备 → 写临时产物 → 提交 → 确认。
* 编辑：缓冲变化 → 解析候选 → 校验 → 模型事务 → 视图派生；无效候选保留文本与诊断。
* 构建：排队 → 运行 → 取消中/结束 → 成功/失败/已取消；保留实际退出码。
* 预览：未启动 → 启动 → 同步/不一致 → 恢复/停止；应用失败不显示新版本成功。
* 热更新：旧版运行 → 候选构建/握手 → 暂停排空 → 最新快照/迁移 → 确认组合 → 恢复。
* 本地设备/交付：预检 → 构建 → 打包/导出 → 受支持本地安装 → 启动/验证；
  产物导出不等于设备运行成功，SSH/网络上传与远端运行属于 F28 未来扩展。
* 调试：连接 → 运行/停止 → 断开；附加与自启动会话的停止权限不同。

外部文件变化、版本切换、格式化、AI 提议、工程替换都须进入相同的版本和合并门禁。
撤销历史按文档/设计事务定义归属；跨文件事务可作为一个逻辑操作，但不能承诺撤销网络提交。

## 35. 质量门禁、性能与容量

### 35.1 每个任务的完成定义

1. 实现进入真实调用链，命令、界面、模型、服务、预览/生成/运行中适用环节全部接通。
2. 正常、非法输入、取消、权限拒绝、外部冲突、服务失效中适用路径有可观察结果。
3. 任务记录代码位置、修订、命令/环境、产物、结果、未覆盖范围；写完只能标“待验收”。
4. 改库跑库侧门禁；改宿主跑最小相关测试；改生成契约跑真实产物构建和语义对比。
5. 界面变更检查键盘、焦点、标签、禁用原因、空/错误状态、主题/DPI 和中文。
6. 所有写入口遵守事务/生成区/信任边界；不能只验证鼠标入口。
7. 不删除有效失败测试，不把未测试记为通过，不用日志或固定结果实现功能。
8. 修改契约、支持范围、权限、格式须同步文档；性能改动附前后分布。
9. `mod.rs` 保持薄职责；按责任/内聚性拆模块，小于 2000 行不机械拆分，
   该规则不是单文件 2000 行硬上限。Rust 注释遵循原则中的英文规范。

### 35.3 平台认证

认证逐组合列出：宿主 OS/架构、目标 profile/triple、SDK、产物模式、库修订、工具链、设备。
级别：能力查询 → 生成 → target check → target build → 运行行为 → 真实设备。
这些级别不是自动推导链：build 成功不意味着运行成功，桌面运行不意味着设备认证。
缺 SDK/设备/辅助技术环境标“阻塞/未验证”；发布前补齐或经明确决策缩减公开支持范围。
库侧既有证据纳入认证输入：五 profile 互斥 feature 矩阵、三档容量预算、`platform_diagnostics` 12 位、
字节级 SVG 快照与普查视觉基线、`designer_generate` 双产物与模式一致性门禁（§1.6.1）。
这些属于上游门禁，宿主认证仍须自证运行行为与设备级证据：级别链不因上游门禁通过而自动通过。

## 37. 排期、并行、进度与证据回写

### 37.1 估算方式

MS00 完成后按真实 API 差距、可用人员、平台测试资源与原型测量估算工期。
各任务估算开发、集成、测试、文档、平台复验和风险缓冲，不能把 L 直接换成固定天数。
按完成的交付而非写代码时间预测：F03/F15/F17 等状态一致性任务必须保留故障测试时间。

可并行工作流：

* 基础编辑引擎与工程/宿主基线：契约确认后可并行，最终共享缓冲集成再合流。
* 画布/布局/属性：共享模型和能力契约就绪后分域推进，不能各建一套模型。
* 数据/事件与 UI 预览：同步/解绑契约先定，再并行界面和服务。
* 组件与热更新：基础生成/预览闭环之后并行；多目标发布合流。
* 调试适配器、平台输入/窗口、设备工具链探针：前置服务就绪即先测，不等末期。
* 版本控制、质量系统、扩展：按具体依赖渐进实现，最终按里程碑整域验收。
* Kit/多根身份与离线任务：工程契约先定，再接语言服务/CLI/CI，防止各层解释不同配置。
* 双 AI：复用宿主权限/任务/版本服务，不能用目录或工作进程替代授权检查。
* 远程/容器/远程部署：仅保留 F28 未来清单与接缝，正式版不安排实施、不引入运行依赖。
* 高级原生/复合调试与内置性能剖析：T19.09/T19.10/T21.09 未来立项，正式版只复用基础调试和性能报告。
