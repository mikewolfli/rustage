## 1. 结论

2.8.10 闭合了 `feedback-20261019.md` 的两项开放请求，并额外修复了 Linux GTK 窗口销毁：

| 旧请求 | 2.8.10 中的实现 | 宿主侧处理 |
|---|---|---|
| §4 Linux target + mini 不能编译 | `platform/locale.rs` 增加 `#[cfg(alloc_frugal)] from_environment() -> None`；`platform/linux/platform_impl.rs` 使用 `crate::compat::Vec` | Linux 上 `--features mini --lib` 实跑通过；矩阵 `linux × mini` 升为 `build-verified` |
| §5 需要逐帧 preedit 观察接缝 | `WidgetHandle::on_ime_preedit` + `widget::runtime::{register,notify,clear}_ime_preedit_callback`；`platform::ime::deliver_composition` 在控件处理后通知观察者 | `--ime` 注册观察者；真实 fcitx5 打印 `n`/`ni`/`ni h`/`ni ha`/`ni hao` 后提交 `你好` |

`--probe-apis` 在 2.8.10 上报告 22 verified / 0 gap，修订漂移测试通过。

## 3. 可选改进（不阻塞当前里程碑）

以下两项不是缺陷，也不会阻止宿主继续；记录是因为它们直接影响“设计器界面随窗口缩放”的
实现方式，且能减少宿主自写布局：

1. **面板级子控件构造器。** 当前 `PanelHandle::set_layout` 可以按 id 给子控件安排位置，
   即使这些控件是用 `WindowHandle::new_label/new_list_box` 创建的；本轮工作台就是这样让面板
   标题与列表跟随面板缩放。建议提供 `PanelHandle::new_label/new_list_box/...`（或明确文档
   说明“面板布局可以定位由父窗口创建的控件”），这样面板的布局、父子关系与裁剪语义一致，
   不必让宿主知道这个隐式契约。
2. **固定轨道/边框式布局。** 工作台的顶部工具栏、左右侧栏、底部面板和状态栏需要“固定像素
   高度 + 中间弹性区域”的二维布局。现有 `BoxLayout` 是单轴，`GridLayout` 的列宽按 stretch
   比例分配（没有固定像素轨道），所以本轮在宿主实现了 `WorkbenchLayout`。若库提供
   `BorderLayout` 或支持固定轨道的 `GridLayout`，设计器可以少一个宿主侧布局实现，并复用
   库对 DPI/文本缩放的 `LayoutContext` 处理。

这两项只是改进建议；本轮没有因为缺少它们而伪造布局或绕过库的文档布局语义。

3. **GTK 窗口在 resize 后不重绘（缺陷，不只是建议）。**

   **现象。** `--workbench-gui` 的真实 GTK 窗口从 1280x800 用 `wmctrl -r ... -e` 调到
   1000x700 后，宿主日志确认布局已按 1000x700 重算：
   `workbench layout for 1000x700: 26 widget(s), 1 editor group(s)`；但 `xwd` 抓到的窗口内容仍是
   1280 宽度的旧帧，直到再点一下工具栏（触发一次可见状态变化）才显示新布局。

   **源码证据。** `platform/linux/types.rs` 的 `native.window_painters` 在
   `platform_impl.rs:1307` 写入、在 `:767` 删除，但**没有任何读取点**；
   `Platform::invalidate_surface` 走 `canvas::repaint_canvas`，只看 `native.canvases`
   （由 `mount_surface` 写入的子表面），所以对窗口 id 返回 `false`。
   `app/handle.rs` 的 `WidgetTriggerKind::Resized` 只调用 `apply_window_layout`，没有对窗口
   paint area 执行 `queue_draw`。

   **期望。** `invalidate_surface(window_id)` 能解析窗体的 paint area 并 `queue_draw`（读
   `window_painters`），或 `Resized` 分支在布局后主动 queue；或者把窗口 paint area 注册到
   `canvases`。

   **判据。** 上述 `wmctrl` 缩放后，无需任何指针/键盘事件，窗口内容即显示新布局；
   `invalidate_surface(window_id)` 返回 `true`。

   **本仓库的处理。** 没有用隐藏/显示面板或改文本之类会造成闪烁的绕行把旧帧盖过去；布局状态、
   测试和“缩放后点一下即正确”的真实截图都在，缺口按上游缺陷记录。

  需要在对应宿主验证。2.8.10 的 Linux 修复和 preedit 接缝已在 Linux 上取得真实窗口证据。

  保持禁用，直到真实会话验证。
- **没有新增必须修改 rust-widgets 才能继续的请求。** 本轮的两条 §3 是可选的宿主体验改进。
